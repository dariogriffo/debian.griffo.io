O que é o Atuin AI?

O Atuin AI é o agente de shell do Atuin. O Atuin o trazia embutido até a 18.24 e o removeu na 18.25; agora ele continua como um binário independente, atuin-ai. Aperte ? em um prompt vazio e um chat abre direto no seu terminal: descreva o que quer fazer e ele sugere o comando, ou faça uma pergunta e ele responde. Com a sua permissão, ele também pode buscar no seu histórico do Atuin, ler e editar arquivos e executar comandos. Ele conversa com um servidor Atuin AI que você mesmo hospeda (o upstream o publica como imagem Docker), e esse servidor pode ficar na frente de qualquer endpoint compatível com OpenAI: Ollama, vLLM ou uma API hospedada. O cliente é escrito em Rust pela equipe do Atuin e tem licença MIT.

🚀 Por que a versão mais recente importa: O Atuin AI é novo e anda rápido, e o upstream não publica nenhuma versão, só commits na main. Este repositório gera um snapshot toda sexta-feira quando a main mudou, com versão <versão do cliente>.<AAAAMMDD> (por exemplo 0.1.0.20261127), então o apt upgrade traz as mudanças da semana sem toolchain de Rust. O Debian não empacota o atuin-ai.

⚡ Principais recursos do Atuin AI

❓ A uma tecla

Aperte ? em um prompt vazio para abrir o agente. Em qualquer outro lugar o ? digita um ponto de interrogação normalmente, então ele nunca atrapalha o comando que você está escrevendo.

💡 Sugestões de comandos

Descreva a tarefa em palavras simples ("encontre arquivos com mais de 1 GB alterados esta semana") e receba um comando que você pode ler, editar e executar, em vez de vasculhar páginas de manual.

📜 Conhece o seu histórico

Com permissão, o agente busca no seu histórico do Atuin, então consegue achar o comando que você rodou no mês passado ou partir do jeito como você costuma fazer as coisas nesta máquina.

🛠️ Arquivos e comandos

Ele pode ler e editar arquivos e executar comandos por você, e pergunta antes de fazer. Você decide o que mexe no seu sistema.

🏠 O seu próprio servidor

O cliente conversa com um servidor Atuin AI que você mesmo roda, então seus prompts e seu histórico vão para onde você decidir. O upstream distribui o servidor como ghcr.io/atuinsh/atuin-ai-server.

🔌 Qualquer modelo compatível com OpenAI

O servidor funciona com qualquer endpoint compatível com OpenAI: um modelo local via Ollama ou vLLM, ou uma API hospedada. Troque de modelo no servidor sem mexer no cliente.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

Como funciona o espelho gratuito →

🧩 Sobre a opção extrepo. extrepo é a ferramenta do próprio Debian para repositórios externos: ela escreve o arquivo de sources e instala a chave de assinatura para você, conferindo a chave contra metadados assinados antes de usá-la. Este repositório está registrado nela como griffo, e o espelho gratuito para sempre como griffo-free, então no Debian (bookworm, trixie, forky e sid) os comandos acima são toda a configuração.

O extrepo configura apenas o arquivo de sources e a chave: as credenciais de uma assinatura continuam indo em /etc/apt/auth.conf.d/deb.griffo.io.conf. O Ubuntu não é coberto, porque o extrepo publica metadados só para as suítes do Debian: lá, use os comandos com sudo ou como root.

Passo 3: Primeira execução

# Apontar o cliente para o seu servidor Atuin AI
# (um exemplo comentado: /usr/share/doc/atuin-ai/examples/ai.example.toml)
mkdir -p ~/.atuin
cat > ~/.atuin/ai.toml <<'EOF'
endpoint = "http://localhost:8080"
# api_token = "..."   # só quando o servidor define AUTH_TOKEN
EOF

# Associar ? no seu shell, depois da linha init do próprio Atuin
echo 'eval "$(atuin-ai init bash)"' >> ~/.bashrc

# Abrir um shell novo e apertar ? em um prompt vazio
exec bash

🎯 Exemplos básicos de uso

Configurar o shell:

# bash, em ~/.bashrc
eval "$(atuin init bash)"
eval "$(atuin-ai init bash)"

# zsh, em ~/.zshrc
eval "$(atuin init zsh)"
eval "$(atuin-ai init zsh)"

# fish, em ~/.config/fish/config.fish
atuin init fish | source
atuin-ai init fish | source

Rodando o servidor:

# Só o cliente é empacotado; o servidor é a imagem Docker do upstream
docker pull ghcr.io/atuinsh/atuin-ai-server

# Configure-o com o seu endpoint compatível com OpenAI (Ollama, vLLM, uma API hospedada)
# como descreve o guia Self-Hosting do upstream, e confira se ele responde

🔧 Integrações

O Atuin AI fica entre o seu shell, o seu histórico do Atuin e um modelo que você escolhe:

  • Atuin: uma dependência obrigatória, instalada junto a partir do deb.griffo.io; o agente busca no mesmo banco de histórico que o atuin search usa, e só quando você permite
  • Atuin 18.25 e posteriores: a 18.25 removeu o agente embutido, então este pacote é como você mantém o chat do ? em um Atuin atual
  • bash, zsh e fish: atuin-ai init bash, zsh ou fish imprime o atalho de teclado; carregue-o depois do init do Atuin para que os dois atalhos convivam
  • Servidor Atuin AI: ghcr.io/atuinsh/atuin-ai-server, rodando com Docker ou Podman na mesma máquina ou em qualquer lugar que o cliente alcance; defina AUTH_TOKEN lá e api_token em ~/.atuin/ai.toml para protegê-lo
  • Ollama e vLLM: todo prompt fica no seu próprio hardware quando o servidor aponta para um endpoint local compatível com OpenAI
  • APIs hospedadas: qualquer provedor que fale a API da OpenAI funciona do mesmo jeito, configurado no servidor, nunca no cliente

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Debian oficial: não empacota o Atuin AI, apt install atuin-ai falha em um sistema padrão
  • Downloads do upstream: não existem: o upstream não publica versões, tags nem binários do cliente
  • cargo build a partir do código: um clone, um toolchain de Rust e alguns minutos de compilação, repetidos à mão sempre que a main muda
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ Construído a partir da main do upstream: compilado do código do upstream com o próprio Cargo.lock dele; as notas de versão e /usr/share/doc/atuin-ai/changelog.Debian trazem o commit exato do upstream de cada snapshot
  • ✅ Traz o Atuin junto: depende do atuin, que o deb.griffo.io também oferece, então um único apt install atuin-ai instala os dois
  • ✅ Só o cliente: o pacote instala /usr/bin/atuin-ai e um ai.toml de exemplo; o servidor fica no Docker, onde o upstream o distribui
  • ✅ Atualizações automáticas: cada snapshot novo chega com um simples apt upgrade
  • ✅ Duas arquiteturas: amd64 e arm64 no Bookworm, Trixie, Forky e Sid, as mesmas duas do pacote Atuin do qual depende; não há build para i386 nem armhf
  • ✅ Multi-distribuição: funciona no Bookworm, Trixie, Forky e Sid
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O Atuin AI está nos repositórios oficiais do Debian?

Não, Atuin AI não está empacotado nos arquivos oficiais do Debian. Este repositório é atualmente a única fonte apt, oferecendo Atuin AI 0.1.0.20261125.

Como instalo o Atuin AI mais recente no Debian?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install atuin-ai. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Debian são suportadas?

Debian 12 Bookworm, Debian 13 Trixie, Forky e Sid.
