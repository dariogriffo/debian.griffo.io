O que é o tldr?

O tldr é o cliente oficial em Rust do tldr-pages, a coleção de páginas man simplificadas mantida pela comunidade: cada página é uma descrição de uma linha do comando seguida de um punhado dos exemplos que as pessoas realmente digitam. O projeto upstream se chama tlrc; o pacote e o comando se chamam tldr. É um único binário estático sem dependências, guarda a coleção inteira num cache local para que cada consulta seja instantânea e funcione offline, e renova esse cache sozinho quando ele envelhece. As páginas vêm por plataforma (Linux, macOS, Windows, Android, os BSDs) e em dezenas de idiomas, as cores e o layout da saída ficam num arquivo TOML, e o pacote traz a página man e o autocompletar para bash, zsh e fish.

🚀 Por que a versão mais recente importa: O tlrc acompanha a especificação de clientes do tldr-pages: os novos diretórios de plataforma, as regras de fallback entre idiomas, a busca de páginas, o diretório de páginas próprias e as chaves de configuração que controlam a idade do cache e as cores chegaram lançamento a lançamento, e um binário antigo ou os ignora ou desenha errado as páginas mais novas. O pacote tldr do próprio Debian é outro programa, o cliente em Haskell tldr-hs, e o tealdeer do Debian também instala um /usr/bin/tldr; nenhum dos dois é o tlrc, então este repositório é o jeito de ter o cliente oficial via apt.

⚡ Principais recursos do tldr

📄 Exemplos primeiro

tldr tar imprime as oito formas como você realmente usa o tar em vez das duzentas opções que ele aceita. Comandos de várias palavras funcionam como você digita: tldr git rebase, tldr docker compose.

⚡ Um cache local, não uma requisição

A primeira execução baixa a coleção inteira; cada consulta depois disso é a leitura de um arquivo, então a página aparece antes de você tirar o dedo do Enter, num trem ou atrás de um proxy. O cache se atualiza sozinho quando passa da idade que você definir, ou com --update.

🖥️ Todas as plataformas, um comando

As páginas são organizadas por plataforma. Você recebe a do Linux por padrão e -p macos ou -p windows quando está escrevendo instruções para uma máquina que não é a que está na sua frente.

🌍 O seu idioma

O tldr-pages é traduzido para dezenas de idiomas. O tlrc segue LANG e LANGUAGE e recorre ao inglês página a página, ou -L escolhe um idioma para uma única consulta.

🔍 Encontrar a página que você não conhece

--list imprime todos os nomes de página da plataforma atual, --search procura em nomes e descrições, e --info diz que idade o cache tem e quais idiomas ele guarda.

🎨 Configurado do seu jeito

Um config.toml: cada cor e estilo da página desenhada, a idade do cache antes de uma atualização automática, os idiomas a baixar, a plataforma preferida e um diretório de páginas suas que é consultado antes do cache.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

Como funciona o espelho gratuito →

🧩 Sobre a opção extrepo. extrepo é a ferramenta do próprio Debian para repositórios externos: ela escreve o arquivo de sources e instala a chave de assinatura para você, conferindo a chave contra metadados assinados antes de usá-la. Este repositório está registrado nela como griffo, e o espelho gratuito para sempre como griffo-free, então no Debian (bookworm, trixie, forky e sid) os comandos acima são toda a configuração.

O extrepo configura apenas o arquivo de sources e a chave: as credenciais de uma assinatura continuam indo em /etc/apt/auth.conf.d/deb.griffo.io.conf. O Ubuntu não é coberto, porque o extrepo publica metadados só para as suítes do Debian: lá, use os comandos com sudo ou como root.

🎯 Exemplos básicos de uso

Consultando:

# A página de um comando
tldr tar

# Subcomandos, escritos como você digitaria
tldr git rebase

# Uma página de outra plataforma
tldr -p macos brew
tldr -p windows choco

# Uma página em outro idioma, para uma única consulta
tldr -L pt_BR tar

# Todos os nomes de página desta plataforma, e uma busca por
# nomes e descrições quando você não sabe o comando
tldr --list
tldr --search "compress"

Moldando a saída:

# Markdown puro, para encadear em outra coisa
tldr -R tar

# Sem as linhas em branco, num terminal pequeno
tldr --compact tar

# Sem cores, para logs e scripts
tldr --color never tar

# Nunca tocar na rede, mesmo com o cache vencido
tldr --offline tar

# Desenhar uma página que você está escrevendo antes de mandá-la upstream
tldr -r my-command.md

Deixando do seu jeito:

# De onde a configuração é lida, e um padrão para começar
tldr --config-path
mkdir -p "$(dirname "$(tldr --config-path)")"
tldr --gen-config > "$(tldr --config-path)"

# Depois, no config.toml: idade do cache antes de uma atualização
# automática, os idiomas a manter, a plataforma preferida
# e as cores de cada parte de uma página

# Limpar o cache se um download deu errado
tldr --clean-cache

🔧 Integrações

O tldr é uma consulta, então ele se encaixa ao lado das ferramentas que você já usa:

  • Sua shell: o pacote instala o autocompletar para bash, zsh e fish, então tldr gi<tab> completa nomes de página a partir do cache, e man tldr está lá para o próprio cliente
  • fzf: tldr --list | fzf | xargs tldr é um seletor difuso de páginas em uma linha, e a saída de --raw alimenta o painel de pré-visualização
  • Corrigir uma página: tldr --edit tar imprime um link que abre essa página no editor web do GitHub, então corrigir uma página tldr está a um pull request de distância
  • man: o tldr não substitui o manual, é a primeira coisa a ler; a página completa está a um man de distância assim que você sabe qual opção quer
  • Scripts e docs: --color never e --raw deixam a saída segura para colar num README, num ticket ou num log

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Debian oficial: apt install tldr entrega o tldr-hs, o cliente em Haskell, e o tealdeer é outro cliente em Rust com o mesmo nome de comando; nenhum dos dois é o tlrc oficial
  • Compilar do código-fonte: atual, mas exige uma toolchain Rust em cada máquina e deixa um binário que o apt desconhece
  • O tarball do lançamento upstream: o mesmo binário estático, mas descompactado à mão no seu PATH, sem autocompletar, sem página man e sem atualizações
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ O cliente oficial: o tlrc, o cliente que o próprio projeto tldr-pages mantém, não uma das muitas reimplementações
  • ✅ O comando é tldr: o pacote se chama tldr porque esse é o comando, e ele conflita com o tealdeer e o substitui, então nunca há disputa pelo /usr/bin/tldr
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream, e o cache de páginas se atualiza sozinho por cima
  • ✅ Pacote completo: o binário, a página man e o autocompletar para bash, zsh e fish
  • ✅ Zero dependências: um binário musl com ligação estática, nada mais é puxado
  • ✅ Duas arquiteturas: amd64 e arm64, o mesmo binário estático em todas as suítes
  • ✅ Multi-distribuição: funciona no Debian 13 (trixie) ou mais novo: Trixie, Forky e Sid
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O tldr está nos repositórios oficiais do Debian?

Não, tldr não está empacotado nos arquivos oficiais do Debian. Este repositório é atualmente a única fonte apt, oferecendo tldr 1.13.1.

Como instalo o tldr mais recente no Debian?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install tldr. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Debian são suportadas?

Debian 12 Bookworm, Debian 13 Trixie, Forky e Sid.
