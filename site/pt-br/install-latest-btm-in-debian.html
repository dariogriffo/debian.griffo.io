O que é o bottom?

O bottom — o comando é btm — é um monitor gráfico de processos e do sistema para o terminal, escrito em Rust e inspirado em gtop, gotop e htop. Por padrão ele funciona como um painel: CPU, memória, rede, discos, temperaturas e processos dividem uma única tela, e qualquer widget pode ser ordenado, ampliado ou expandido para ocupar o terminal inteiro.

🚀 Por que a versão mais recente importa: os arquivos oficiais estão várias versões menores atrás, e foi justamente nelas que veio o que interessa: contabilização separada de cache e buffers, uso de GPU no widget de memória, temas de cores embutidos, filtragem de threads do kernel e uma longa lista de correções para kernels e sensores recentes. Um monitor que lê o hardware errado é pior que nenhum monitor, então vale manter esta ferramenta atualizada.

⚡ Principais recursos do bottom

📈 Gráficos ao vivo

CPU (por núcleo ou média), memória, tráfego de rede, E/S de disco e temperaturas como gráficos em movimento que você amplia com + e -.

🔍 Busca de processos

/ filtra a tabela de processos, com alternadores de regex, palavra inteira e maiúsculas, e uma tecla para ordenar por CPU, memória, PID ou nome.

🌲 Modo árvore

t transforma a tabela de processos em árvore, então o worker descontrolado aparece sob o processo que o criou, em vez de solto na lista.

🎛️ Layouts próprios

O arquivo de configuração descreve linhas, colunas e proporções dos widgets, para o painel mostrar as quatro coisas que você realmente acompanha.

🎨 Temas embutidos

--theme gruvbox, nord e suas variantes claras já vêm no binário, e cada cor pode ser redefinida em bottom.toml.

🖥️ Modo básico

btm --basic tira os gráficos e deixa uma leitura numérica compacta, legível em SSH lento ou num painel pequeno do tmux.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

🎯 Exemplos básicos de uso

Monitoramento do dia a dia:

# O painel completo
btm

# Atualizar duas vezes por segundo e guardar dez minutos de histórico
btm --rate 500ms --retention 10m

# Começar no widget de processos, já expandido
btm --default_widget_type proc --expanded

# Árvore de processos, agrupada, com as linhas de comando completas
btm --tree --process_command

Dentro do painel:

# As teclas que fazem o trabalho
#   ?        ajuda integrada com todos os atalhos
#   e        expandir o widget selecionado para o terminal inteiro
#   f        congelar a tela enquanto você lê
#   +  -  =  aproximar, afastar ou restaurar um gráfico
#   /        buscar na tabela de processos
#   c m p n  ordenar por CPU, memória, PID ou nome
#   dd       parar o processo selecionado
#   t        alternar a árvore de processos

Ajustando à sua máquina:

# Fahrenheit, sem a linha de CPU média, marcadores de ponto em vez de braille
btm --fahrenheit --hide_avg_cpu --dot_marker

# Contar cache e buffers como uma linha de memória própria
btm --enable_cache_memory

# Widget de bateria em um notebook
btm --battery

# Um tema de cores combinando com o resto do terminal
btm --theme gruvbox

🔧 Integrações com outras ferramentas

o bottom foi feito para um ambiente centrado no terminal:

  • Arquivo de configuração: ~/.config/bottom/bottom.toml reúne layout, proporções dos widgets, cores e suas opções habituais
  • Entrada de desktop: o pacote instala bottom.desktop e um ícone, então ele também aparece no menu de aplicativos como monitor do sistema
  • tmux e Zellij: vive bem em um painel estreito; --basic o mantém legível quando o painel encolhe
  • GPUs: o uso de NVIDIA e AMD aparece no widget de memória quando os drivers estão presentes, e --disable_gpu desliga a coleta
  • Servidores: a build amd64 é estática: uma máquina Debian ou Ubuntu recém-instalada não precisa de nada além do pacote

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Debian oficial: traz o btm, mas congelado várias versões menores atrás — novos widgets, temas e correções de sensores só chegam com a próxima release do Debian
  • cargo install bottom: atualizado, mas compila por vários minutos, fica fora do apt e não traz página de manual, conclusões nem entrada de desktop
  • Tarball upstream: o binário oficial, que você precisa baixar na mão a cada lançamento
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ Widgets atuais: a versão mais nova, com os widgets, temas e correções de sensores que o upstream adicionou depois de o arquivo congelar
  • ✅ Substituto direto do bottom: o pacote tem o nome do comando, btm, e declara Provides/Replaces para bottom, encaixando onde estava o pacote oficial
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream
  • ✅ Pacote completo: o binário upstream mais a página de manual btm.1, as conclusões de bash, zsh e fish, a entrada de desktop e seu ícone
  • ✅ Cinco arquiteturas: amd64, arm64, armhf, i386 e riscv64 — o mesmo monitor num notebook, num Raspberry Pi e numa placa RISC-V
  • ✅ Multi-distribuição: funciona no Bookworm, Trixie, Forky e Sid
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O bottom está nos repositórios oficiais do Debian?

Sim, mas o arquivo oficial do Debian traz bottom 0.10.2, enquanto este repositório oferece bottom 0.14.8, recompilado poucas horas após cada lançamento upstream.

Como instalo o bottom mais recente no Debian?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install btm. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Debian são suportadas?

Debian 12 Bookworm, Debian 13 Trixie, Forky e Sid.
