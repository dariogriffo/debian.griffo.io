O que é o GitUI?

O GitUI é uma interface de terminal para git, escrita em Rust. Ele entrega as partes de uma GUI de git que realmente valem a pena — preparar hunks e linhas isoladas, ler diffs, navegar e buscar no log, dar stash, blame, criar branches e fazer push — sem sair do terminal e sem os travamentos que as GUIs populares sofrem em repositórios grandes.

🚀 Por que a versão mais recente importa: o GitUI ainda está antes do 1.0 e avança rápido: suporte a submódulos, busca no log, blame, rebase melhor e uma longa fila de correções chegaram em lançamentos comuns. Nem o Debian nem o Ubuntu o empacotam, então a alternativa a uma build atual não é um pacote mais antigo: é pacote nenhum.

⚡ Rápido em repositórios enormes

O benchmark do próprio upstream percorre todo o histórico do kernel Linux em cerca de 24 segundos usando uns 170 MB, onde GUIs mais pesadas travam ou quebram.

✂️ Preparar hunks e linhas

Preparar, desfazer, reverter e resetar arquivos inteiros, hunks isolados ou linhas específicas — o motivo pelo qual a maioria abre uma GUI de git.

📜 Log e diffs

Navegar e buscar no log de commits, inspecionar o diff de qualquer um e fazer blame linha a linha, tudo na mesma interface guiada pelo teclado.

📦 Stash

Salvar, aplicar, tirar, descartar e inspecionar stashes em uma aba própria, em vez de lembrar qual subcomando do git stash faz o quê.

🌿 Branches e remotos

Criar, renomear, apagar e trocar de branch, trabalhar com remotos e fazer push ou fetch sem voltar ao shell.

⌨️ Ajuda contextual

? mostra exatamente as teclas que funcionam na visão atual, e key_bindings.ron permite remapear tudo — no estilo vim, se for o seu costume.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

🎯 Exemplos básicos de uso

Abrindo repositórios:

# O repositório do diretório atual
gitui

# Um repositório específico, sem entrar nele
gitui -d ~/src/linux

# Diretório de trabalho e diretório git separados
gitui -d ~/src/project/.git -w ~/src/project

# Começar com um arquivo já selecionado na aba de arquivos
gitui -f src/main.rs

Aparência e uso:

# Um arquivo de tema de ~/.config/gitui/
gitui -t mytheme.ron

# Um arquivo próprio de atalhos
gitui -k ~/.config/gitui/key_bindings.ron

# Símbolos de tecla personalizados, para teclados que os desenham de outro jeito
gitui -s ~/.config/gitui/key_symbols.ron

# Usar o observador do sistema de arquivos em vez de atualizações periódicas
gitui --watcher

Quando é preciso investigar:

# Reunir dados do ambiente para um relatório de bug
gitui --bugreport

# Gravar um log enquanto reproduz o problema
gitui --logging --logfile /tmp/gitui.log

# A CLI do git continua ali para o que o GitUI não cobre
git rebase -i origin/main

# Push por HTTPS exige um credential helper configurado explicitamente
git config --global credential.helper store

🔧 Integrações com outras ferramentas

o GitUI se apoia na sua configuração de git já existente:

  • Seus repositórios: um repositório git comum, lido e escrito por um backend git em Rust — nada nele é específico do GitUI
  • Hooks: pre-commit, commit-msg, post-commit e prepare-commit-msg rodam igual à linha de comando
  • Assinatura GPG: commits assinados funcionam, com as ressalvas que o upstream documenta no seu rastreador de issues
  • Temas e atalhos: theme.ron, key_bindings.ron e key_symbols.ron em ~/.config/gitui/
  • Via SSH: rápido o bastante em uma máquina remota para arrumar um commit no servidor deixar de ser sofrimento; a build amd64 não precisa de bibliotecas

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Ubuntu oficial: não empacota o GitUI — apt install gitui falha em um sistema padrão
  • cargo install gitui: atualizado, mas é uma compilação Rust longa em cada máquina, fora do apt e fora das suas atualizações
  • Tarball upstream: o binário oficial, rebaixado na mão a cada lançamento
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ Ainda antes do 1.0: o GitUI ganha recursos de verdade em lançamentos comuns, então usar o atual é a diferença entre ter submódulos, busca no log e blame ou não
  • ✅ A única fonte apt: o GitUI não está nos arquivos do Debian nem do Ubuntu; este repositório empacota a build oficial upstream
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream
  • ✅ Empacotamento honesto: o binário upstream em /usr/bin/gitui — o upstream não publica página de manual nem conclusões, então o pacote não inventa nenhuma
  • ✅ Três arquiteturas: amd64 (build musl estática), arm64 e armhf, com as dependências declaradas onde o upstream liga contra a glibc
  • ✅ Multi-distribuição: funciona no Ubuntu 22.04, 24.04, 25.10 e 26.04
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O GitUI está nos repositórios oficiais do Ubuntu?

Não, GitUI não está empacotado nos arquivos oficiais do Ubuntu. Este repositório é atualmente a única fonte apt, oferecendo GitUI 0.28.1.

Como instalo o GitUI mais recente no Ubuntu?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install gitui. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Ubuntu são suportadas?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing e 26.04 Resolute.
