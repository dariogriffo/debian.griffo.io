O que é o jjui?

O jjui é uma interface de terminal para o Jujutsu, o sistema de controle de versão compatível com Git que você usa pelo comando jj. Rode-o dentro de um repositório jj e ele mostra o grafo de revisões e deixa você trabalhar direto nele: mude o revset, com autocompletar, para escolher o que aparece, faça rebase de uma revisão ou de um branch inteiro, faça squash, split e abandon de revisões, mova bookmarks, abra uma revisão para ver os seus arquivos e diffs e restaurar arquivos um a um, veja a saída de jj show e jj diff ao lado do grafo, faça push e fetch por um menu Git e navegue pelo log de operações ou restaure um estado dele. Tudo funciona pelo teclado ou com o mouse. O jjui é escrito em Go por Ibrahim Dursun e tem licença MIT.

🚀 Por que a versão mais recente importa: O jjui anda junto com o Jujutsu: as versões do jj mudam comandos e saídas, e o jjui as acompanha enquanto ganha operações, melhorias no autocompletar e correções em quase toda versão. O Ubuntu não empacota o jjui, então sem este repositório a única forma de ficar em dia é baixar cada nova versão na mão. Aqui um apt upgrade normal atualiza juntos o jjui e o jj de que ele depende.

⚡ Principais recursos do jjui

🌳 O grafo de revisões, ao vivo

O jjui abre no mesmo grafo que o jj log imprime, mas você pode se mover por ele, selecionar revisões e agir sobre elas, e o grafo é redesenhado a cada mudança.

🔎 Revsets com autocompletar

Edite o revset no topo da tela para escolher quais revisões aparecem; funções e aliases são completados enquanto você digita, então não é preciso decorar a linguagem de revsets.

✂️ Rebase, squash, split, abandon

Faça rebase de uma revisão ou de um branch inteiro sobre outro, squash de uma revisão no pai, split em duas, abandon, ou mova um bookmark, tudo a partir do grafo, vendo o resultado na hora.

📄 Arquivos, diffs e prévias

Abra uma revisão para listar os arquivos que ela muda, ler os diffs e restaurar arquivos de forma interativa, ou mantenha um painel com a saída de jj show ou jj diff do que estiver selecionado.

🔄 Menu Git e log de operações

Faça push e fetch por um menu Git sem sair do grafo, e navegue pelo log de operações para ver o que mudou e restaurar o repositório a um estado anterior.

🖱️ Teclado, mouse, Lua e temas

Cada ação tem um atalho de teclado (aperte ? para ver a lista) e o mouse também funciona. Scripts em Lua adicionam as suas próprias ações, e temas mudam as cores.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

🔧 Integrações

O jjui é uma interface para o jj, então se encaixa onde o jj já se encaixa:

  • Jujutsu: cada ação roda o comando jj, então o jjui vê o mesmo repositório, a mesma configuração e os mesmos aliases de revset que o próprio jj; o pacote depende de jujutsu (>= 0.37), e o deb.griffo.io empacota o Jujutsu para todas as versões, então o apt o instala junto com o jjui
  • Remotos Git: num repositório colocado, o push e o fetch do menu Git vão para os seus remotos Git de sempre, com as credenciais que você já usa
  • O seu editor: jjui -config abre o arquivo de configuração no $EDITOR, onde ficam os atalhos, o tema e as ações próprias
  • Scripts em Lua: escreva as suas próprias ações em Lua e associe-as a teclas, para os comandos jj que você roda com frequência
  • Temas: as cores do grafo, da seleção e dos painéis vêm de um tema que você pode trocar ou escrever do zero
  • Mouse: clique para selecionar revisões e role o grafo e a prévia, em qualquer terminal com suporte a mouse
  • Documentação: o upstream não fornece página man, então o guia completo está em idursun.github.io/jjui, e ? dentro do jjui lista os atalhos

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Ubuntu oficial: não empacota o jjui, e apt install jjui falha num sistema padrão
  • Downloads do upstream: um zip com um único binário na página de releases do GitHub, copiado na mão para o seu PATH, a ser baixado de novo a cada versão, e com o jj instalado à parte
  • Compilar do código-fonte: uma toolchain Go e um go install a cada versão, e o jj ainda a instalar de outro jeito
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ A única fonte apt: o jjui não está nem nos arquivos do Debian nem nos do Ubuntu; este repositório empacota a versão oficial do upstream
  • ✅ O jj vem junto: o pacote depende de jujutsu (>= 0.37), o mínimo do upstream, e o deb.griffo.io empacota o Jujutsu para todas as versões, então sudo apt install jjui instala um jj recente no mesmo passo
  • ✅ Empacotamento honesto: o binário do upstream em /usr/bin/jjui: o upstream não fornece página man nem completions de shell, então o pacote não inventa nenhum
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream
  • ✅ Duas arquiteturas: amd64 e arm64 em todas as versões, então o mesmo jjui roda em notebooks, servidores e placas ARM como o Raspberry Pi
  • ✅ Multi-distribuição: funciona no Ubuntu 22.04, 24.04, 25.10 e 26.04
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O jjui está nos repositórios oficiais do Ubuntu?

Não, jjui não está empacotado nos arquivos oficiais do Ubuntu. Este repositório é atualmente a única fonte apt, oferecendo jjui 0.10.12.

Como instalo o jjui mais recente no Ubuntu?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install jjui. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Ubuntu são suportadas?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing e 26.04 Resolute.
