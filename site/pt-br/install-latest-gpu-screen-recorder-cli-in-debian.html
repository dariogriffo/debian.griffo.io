O que é o GPU Screen Recorder?

O GPU Screen Recorder é um gravador de tela que mantém todo o pipeline na GPU: ele captura um monitor, uma janela, uma região ou uma webcam e entrega os quadros direto para o codificador de vídeo da GPU (VA-API na AMD e na Intel, NVENC na NVIDIA, ou Vulkan video), então gravar um jogo a 60 ou 144 FPS custa quase nada em taxa de quadros. Ele grava em um arquivo, transmite por RTMP, SRT ou WHIP, tira capturas de tela, e mantém um buffer de replay instantâneo ao estilo ShadowPlay que salva os últimos minutos quando você pedir. Funciona em X11 e Wayland, e o comando que você digita é gpu-screen-recorder.

🚀 Por que a versão mais recente importa: o Debian 12 e o Debian 13 não empacotam o GPU Screen Recorder de jeito nenhum, e a 5.13.8 presente no forky e no sid é anterior à série 6.x. Essa versão não tem gsr-cli nem a opção -ipc, então um gravador em execução só pode ser controlado por sinais; não tem saída WHIP com -auth para streaming de baixa latência; e não tem -exclude-metadata. Scripts de atalho e configurações de replay escritos com base na documentação atual do upstream partem do princípio de que todos esses recursos existem.

⚡ Principais recursos do GPU Screen Recorder

⏪ Replay instantâneo

-r 60 mantém os últimos 60 segundos na memória (ou em disco com -replay-storage disk), e salvá-los está a um comando de distância: o clipe que você queria, gravado antes de você saber que o queria.

🎮 Overhead quase zero

Captura e codificação nunca saem da GPU, então a CPU fica livre para o jogo. H.264, HEVC, AV1, VP8 e VP9 são suportados, com variantes HDR e de 10 bits para HEVC e AV1.

🖥️ X11 e Wayland

Grave um monitor diretamente, uma janela no X11, a janela em foco, uma região escolhida com slop ou slurp, ou qualquer coisa que o portal do desktop ofereça com -w portal no Wayland.

📡 Streaming

Envie a mesma captura para a Twitch ou o YouTube por RTMP, para um listener SRT, ou por WHIP para latência abaixo de um segundo, com -bm cbr para o bitrate constante que os serviços de streaming esperam.

🎛️ Controle remoto com o gsr-cli

Inicie o gravador com -ipc e o gsr-cli pausa, para, ou salva os últimos 30 segundos do buffer de replay, e imprime o caminho do arquivo salvo, o que torna os atalhos triviais.

🔊 Mixagem de áudio

Misture a saída do desktop e o microfone com -a "default_output|default_input", ou grave o áudio de um único aplicativo com app:firefox pelo PipeWire.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

Como funciona o espelho gratuito →

🧩 Sobre a opção extrepo. extrepo é a ferramenta do próprio Debian para repositórios externos: ela escreve o arquivo de sources e instala a chave de assinatura para você, conferindo a chave contra metadados assinados antes de usá-la. Este repositório está registrado nela como griffo, e o espelho gratuito para sempre como griffo-free, então no Debian (bookworm, trixie, forky e sid) os comandos acima são toda a configuração.

O extrepo configura apenas o arquivo de sources e a chave: as credenciais de uma assinatura continuam indo em /etc/apt/auth.conf.d/deb.griffo.io.conf. O Ubuntu não é coberto, porque o extrepo publica metadados só para as suítes do Debian: lá, use os comandos com sudo ou como root.

🎯 Exemplos básicos de uso

Gravando:

# Áudio do desktop e microfone misturados em uma única faixa
gpu-screen-recorder -w screen -f 60 -a "default_output|default_input" -o video.mp4

# Um único monitor pelo nome, veja --list-monitors
gpu-screen-recorder -w DP-1 -f 144 -k hevc -o video.mp4

# Uma região escolhida com slurp no Wayland, ou slop no X11
gpu-screen-recorder -w region -region $(slurp -f "%wx%h+%x+%y") -o video.mp4

# Tela com a webcam no canto inferior direito
gpu-screen-recorder -w "screen|/dev/video0;halign=end;valign=end;width=30%;height=30%" -o video.mp4

Replay instantâneo:

# Mantenha os últimos 60 segundos, bitrate constante para uso previsível de memória
gpu-screen-recorder -w screen -c mp4 -r 60 -bm cbr -q 40000 -a default_output \
    -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o ~/Videos

# A partir de um atalho: salve o buffer inteiro, ou só os últimos 30 segundos
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay 30

# Os sinais ainda funcionam sem -ipc
pkill -SIGUSR1 -f "^gpu-screen-recorder"

Streaming e capturas de tela:

# Transmita para a Twitch a 8000 kbps constantes
gpu-screen-recorder -w screen -c flv -a default_output -bm cbr -q 8000 \
    -o "rtmp://live.twitch.tv/app/$STREAM_KEY"

# Stream WHIP de baixa latência com um bearer token
gpu-screen-recorder -w screen -bm cbr -q 3500 -c whip -auth "$TOKEN" -o https://whip.example.com/api/whip

# Tire uma captura de tela
gpu-screen-recorder -w screen -o screenshot.png

Controlando uma gravação:

# Inicie uma gravação que pode ser controlada por um socket
gpu-screen-recorder -w screen -f 60 -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o video.mp4 &

# Verifique, pause, depois pare e imprima onde o arquivo foi salvo
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" status
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" set-paused true
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" stop

🔧 Integrações com outras ferramentas

O GPU Screen Recorder é um programa de linha de comando, então ele se encaixa em qualquer lugar onde um atalho possa rodar um comando:

  • Atalhos de desktop: associe gsr-cli save-replay 30 no GNOME, KDE, Sway ou Hyprland para ter uma tecla ao estilo ShadowPlay de "salvar os últimos 30 segundos"
  • Scripts auxiliares: os scripts de toggle, replay e streaming do upstream vêm em /usr/share/gpu-screen-recorder/scripts
  • systemd: um serviço de usuário para um buffer de replay sempre ativo é instalado mas não habilitado; configure ~/.config/gpu-screen-recorder.env, depois systemctl --user enable --now gpu-screen-recorder
  • Streaming sem OBS: as saídas RTMP, SRT e WHIP cobrem Twitch, YouTube e servidores auto-hospedados sem precisar de um segundo programa
  • FFmpeg: -ffmpeg-opts, -ffmpeg-video-opts e -ffmpeg-audio-opts repassam opções para o codificador e o muxer

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Debian oficial: não empacotado no Debian 12 nem no 13; o forky e o sid trazem a 5.13.8, dividida em vários pacotes gpu-screen-recorder-* e sem gsr-cli, -ipc ou WHIP
  • Flatpak: atual e traz seus próprios codificadores, mas é a interface GTK, a linha de comando fica atrás de flatpak run --command=gpu-screen-recorder, e a captura de monitor em AMD/Intel exige uma instalação em todo o sistema
  • Compilando a partir do código-fonte: o install.sh do upstream exige o meson e cerca de vinte pacotes -dev, instala fora do apt, e precisa ser rodado manualmente de novo a cada lançamento
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ Compilado para cada release: compilado a partir da tag upstream em cada suíte, contra o FFmpeg dessa própria suíte, então ele se vincula às bibliotecas que já estão no seu sistema
  • ✅ Sem pedido de senha: o gsr-kms-server recebe a capability que o instalador do upstream define, então gravar um monitor no AMD, Intel ou NVIDIA Wayland não pede sua senha toda vez
  • ✅ Substitui os pacotes divididos: assume o lugar do gpu-screen-recorder-cli do Debian e dos pacotes que o acompanham no forky e no sid, então o apt atualiza em vez de instalar uma segunda cópia
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream
  • ✅ Pacote completo: gpu-screen-recorder, gsr-cli, gsr-kms-server, páginas de manual, o header do plugin, os scripts auxiliares do upstream e um serviço de usuário que fica desativado até você habilitá-lo
  • ✅ Multi-distribuição: funciona no Bookworm, Trixie, Forky e Sid, em amd64
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

Uma ressalva vem direto do upstream: com o FFmpeg da distribuição, placas NVIDIA da geração GTX 1080 ou mais antigas podem não conseguir codificar. O Flatpak e o AppImage do upstream trazem um FFmpeg com patch para esses casos.

❓ Perguntas frequentes

O GPU Screen Recorder está nos repositórios oficiais do Debian?

Não, GPU Screen Recorder não está empacotado nos arquivos oficiais do Debian. Este repositório é atualmente a única fonte apt, oferecendo GPU Screen Recorder 6.1.3.

Como instalo o GPU Screen Recorder mais recente no Debian?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install gpu-screen-recorder-cli. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.
