O que é o superfile?

O superfile é um gerenciador de arquivos de terminal construído em torno de painéis que você deixa abertos. Vários diretórios ficam lado a lado, uma barra lateral guarda seus atalhos da home, as pastas fixadas e os discos montados, e um painel de pré-visualização desenha o que estiver sob o cursor: código com realce de sintaxe, texto puro, o conteúdo de um diretório, uma imagem. Copiar, mover e compactar acontece em segundo plano e se reporta numa barra de processos, então uma transferência grande nunca congela o painel que você está navegando. Os arquivos apagados vão para a lixeira e podem voltar, os arquivos compactados são extraídos e criados no lugar, e cada tecla, cor, caractere de borda e largura de painel é uma linha num arquivo TOML. É um único binário estático em Go, e o comando que você digita é spf.

🚀 Por que a versão mais recente importa: O superfile ainda ganha recursos de base a cada lançamento: o painel de metadados, seções reordenáveis na barra lateral, colunas extras no painel de arquivos, ordenação natural, rolagem por página, o prompt > e uma lista de plugins que só cresce. Cada um deles chega com chaves novas no config.toml e no hotkeys.toml, e um binário antigo ignora em silêncio justamente as opções que a documentação atual manda configurar. Nem o Debian nem o Ubuntu empacotam o superfile, então uma build atual não é um luxo aqui: é a única forma de tê-lo via apt.

⚡ Principais recursos do superfile

🪟 Painéis, não um diretório só

n abre outro painel de arquivos e tab alterna entre eles, cada um com seu caminho, sua ordenação e sua seleção. Copiar entre duas árvores vira duas teclas em vez de dois caminhos longos.

👀 Uma pré-visualização que segue o cursor

O painel lateral desenha o arquivo em destaque conforme você anda: código realçado pelo chroma embutido ou pelo bat, conteúdo de diretórios e imagens nos terminais que sabem desenhá-las. f recolhe tudo quando você quer a largura de volta.

♻️ Exclusões com volta

ctrl+d manda os arquivos para a lixeira em vez de destruí-los, então uma tecla errada tem conserto. D é a exclusão permanente separada e deliberada, para quando você realmente quer isso.

📊 Uma barra de processos para o que demora

Cópias, movimentações e compactações rodam como tarefas de fundo acompanhadas, com progresso próprio, listadas no painel de processos em p. O painel de arquivos continua usável enquanto alguns gigabytes atravessam o disco.

🗜️ Buscar, saltar, compactar, extrair

/ filtra o diretório atual enquanto você digita, z entrega o salto ao zoxide quando ele está instalado, ctrl+a compacta a seleção e ctrl+e extrai um arquivo ali mesmo.

🎨 Configurado do seu jeito

Um config.toml e um hotkeys.toml: toda tecla é remapeável e um conjunto Vim vem junto com o padrão, temas são arquivos que você pode escrever, e largura da barra lateral, caracteres de borda, ordenação padrão e largura da pré-visualização são ajustes.

🚀 Sempre à frente dos arquivos oficiais: Debian e Ubuntu congelam as versões dos pacotes quando lançam uma release — este repositório publica novas versões upstream normalmente em poucas horas. Um simples apt upgrade mantém você na versão mais recente.

Como funciona o espelho gratuito →

🧩 Ou deixe o extrepo fazer isso. No Debian — bookworm, trixie, forky e sid — este repositório está registrado no extrepo, a ferramenta do próprio Debian, que escreve o arquivo de sources e instala a chave de assinatura verificada para você:

sudo apt install extrepo
sudo extrepo enable griffo
sudo apt update
apt install extrepo
extrepo enable griffo
apt update

Use griffo-free no lugar de griffo para habilitar o espelho gratuito para sempre. O extrepo configura apenas o arquivo de sources e a chave: as credenciais de uma assinatura continuam indo em /etc/apt/auth.conf.d/deb.griffo.io.conf. O Ubuntu não é coberto — o extrepo publica metadados só para as suítes do Debian —, então lá use os comandos acima.

🎯 Exemplos básicos de uso

Iniciando:

# O diretório atual
spf

# Um diretório que você indica
spf /var/log

# Um painel por caminho, abertos lado a lado
spf ~/src ~/Downloads /mnt/backup

# Testar ajustes sem tocar nos seus próprios arquivos
spf --config-file /tmp/spf.toml --hotkey-file /tmp/spf-keys.toml

# Qual versão está instalada?
spf --version

Mantendo a configuração em dia:

# Adicionar os campos e as teclas que um lançamento novo trouxe,
# sem mexer no que você já tinha alterado
spf --fix-config-file
spf --fix-hotkeys

# Imprimir todos os caminhos que o superfile usa
spf path-list

# Ambiente, terminal e versão para um relatório de bug
spf --debug-info

Encaixando na sua shell:

# Coloque cd_on_quit = true no config.toml e isto no ~/.bashrc
# ou ~/.zshrc: ao sair com Q você fica no diretório que o painel
# estava mostrando
spf() {
    export SPF_LAST_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/superfile/lastdir"
    command spf "$@"
    [ ! -f "$SPF_LAST_DIR" ] || { . "$SPF_LAST_DIR"; rm -f -- "$SPF_LAST_DIR"; }
}

# O caminho que essa função lê
spf path-list --lastdir-file

# superfile como seletor de arquivos para outro programa: ele
# escreve o caminho escolhido no arquivo e sai
spf --chooser-file /tmp/picked

🔧 Integrações

O superfile deixa de propósito as tarefas especializadas para as ferramentas que você já usa:

  • Seu editor: e abre o arquivo em destaque no $EDITOR e E abre o diretório no dir_editor, então o Neovim ou o Helix continua sendo o editor e o superfile continua sendo o navegador
  • zoxide: com zoxide_support = true, a tecla z salta usando o mesmo banco que sua shell vem construindo há meses
  • exiftool: com libimage-exiftool-perl instalado e metadata = true, o painel de metadados mostra os campos EXIF e de mídia completos em vez do básico
  • bat e chroma: as pré-visualizações são realçadas pelo chroma embutido, ou pelo bat se você preferir os temas dele e definir code_previewer = "bat"
  • Seu terminal e sua shell: a pré-visualização de imagens usa o protocolo de imagens do próprio terminal, o xdg-open cuida dos tipos que você não mapeou em [open_with], e o cd_on_quit devolve o último diretório para o bash, o zsh ou o fish

🚀 Por que escolher o deb.griffo.io?

📊 Comparativo de repositórios:
  • Debian oficial: não empacota o superfile — apt install superfile falha num sistema padrão
  • Compilar do código-fonte: atual, mas exige uma toolchain Go em cada máquina e deixa um binário que o apt desconhece
  • O script de instalação upstream: um curl do superfile.dev, prático, mas escreve no seu sistema por trás do gerenciador de pacotes e depois o próprio binário fica avisando sobre as atualizações dele
  • deb.griffo.io: versão mais recente com atualizações automáticas
  • ✅ A única fonte apt: o superfile não está nos arquivos do Debian nem do Ubuntu; este repositório empacota o lançamento oficial upstream
  • ✅ O comando é spf: o pacote se chama superfile porque o projeto se chama assim, e ele coloca /usr/bin/spf no seu PATH, que é o comando usado por todo tutorial e toda página de teclas
  • ✅ Atualizações automáticas: os pacotes são atualizados poucas horas após cada lançamento upstream, então o auto_check_update pode ir para false e quem confere é o apt
  • ✅ Pacote completo: a build oficial upstream para Linux instalada como /usr/bin/spf, sem nada adicionado nem remendado
  • ✅ Dependências honestas: o binário não precisa de nada, o xdg-utils é apenas recomendado, e exiftool, zoxide, ffmpeg, poppler-utils e uma ferramenta de área de transferência ficam como sugeridos para os recursos opcionais que os usam
  • ✅ Duas arquiteturas: amd64 e arm64, ambos binários Go com ligação estática, então o mesmo pacote roda em todas as suítes
  • ✅ Multi-distribuição: funciona no Bookworm, Trixie, Forky e Sid
  • ✅ Manutenção simples: atualizações com os comandos apt de sempre

❓ Perguntas frequentes

O superfile está nos repositórios oficiais do Debian?

Não, superfile não está empacotado nos arquivos oficiais do Debian. Este repositório é atualmente a única fonte apt, oferecendo superfile 1.6.0.

Como instalo o superfile mais recente no Debian?

Adicione o repositório deb.griffo.io uma única vez com as instruções acima e execute: sudo apt install superfile. Novos lançamentos chegam pelo sudo apt upgrade normal.

Os pacotes são assinados e como são construídos?

Cada pacote é assinado com a chave GPG do repositório (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) e construído a partir de lançamentos upstream em repositórios públicos do GitHub que qualquer pessoa pode inspecionar.

Quais versões do Debian são suportadas?

Debian 12 Bookworm, Debian 13 Trixie, Forky e Sid.
