¿Qué es superfile?

superfile es un gestor de archivos de terminal construido alrededor de paneles que dejas abiertos. Varios directorios conviven uno al lado del otro, una barra lateral guarda tus accesos de home, tus carpetas fijadas y los discos montados, y un panel de vista previa dibuja lo que haya bajo el cursor: código con resaltado, texto plano, el contenido de un directorio, una imagen. Copiar, mover y comprimir ocurre en segundo plano y se informa en una barra de procesos, así que una transferencia grande nunca congela el panel por el que estás navegando. Los archivos borrados van a la papelera y se pueden recuperar, los comprimidos se extraen y se crean en el sitio, y cada tecla, color, carácter de borde y anchura de panel es una línea en un archivo TOML. Es un único binario estático de Go, y el comando que escribes es spf.

🚀 Por qué importa la última versión: superfile todavía gana funciones de base versión a versión: el panel de metadatos, las secciones reordenables de la barra lateral, columnas extra en el panel de archivos, la ordenación natural, el desplazamiento por páginas, el prompt > y una lista de plugins que sigue creciendo. Cada una llega con claves nuevas en config.toml y hotkeys.toml, y un binario viejo ignora en silencio justo las opciones que la documentación actual te dice que pongas. Ni Debian ni Ubuntu lo empaquetan, así que una compilación actual no es un lujo: es la única forma de tenerlo por apt.

⚡ Funciones clave de superfile

🪟 Paneles, no un solo directorio

n abre otro panel de archivos y tab salta entre ellos, cada uno con su ruta, su orden y su selección. Copiar entre dos árboles pasa a ser dos pulsaciones en lugar de dos rutas largas.

👀 Una vista previa que sigue al cursor

El panel lateral dibuja el archivo resaltado según te mueves: código con resaltado del chroma integrado o de bat, contenido de directorios e imágenes en las terminales capaces de pintarlas. f lo pliega cuando quieres recuperar la anchura.

♻️ Borrados con vuelta atrás

ctrl+d manda los archivos a la papelera en vez de destruirlos, así que una tecla equivocada tiene arreglo. D es el borrado permanente aparte y deliberado, para cuando de verdad lo quieres.

📊 Una barra de procesos para lo largo

Copias, movimientos y compresiones corren como trabajos en segundo plano con su propio progreso, listados en el panel de procesos con p. El panel de archivos sigue usable mientras se mueven unos cuantos gigabytes.

🗜️ Buscar, saltar, comprimir, extraer

/ filtra el directorio actual mientras escribes, z delega el salto en zoxide si lo tienes instalado, ctrl+a comprime la selección y ctrl+e extrae un archivo donde está.

🎨 Configurado a tu gusto

Un config.toml y un hotkeys.toml: todas las teclas se pueden reasignar y junto a las de serie viene un juego para Vim, los temas son archivos que puedes escribir, y la anchura de la barra lateral, los caracteres de borde, el orden por defecto y la anchura de la vista previa son ajustes.

🚀 Siempre por delante de los archivos oficiales: Debian y Ubuntu congelan las versiones de los paquetes cuando publican una release; este repositorio publica las nuevas versiones upstream normalmente en cuestión de horas. Un simple apt upgrade te mantiene en la última versión.

🎯 Ejemplos básicos de uso

Arrancarlo:

# El directorio actual
spf

# Un directorio que le indiques
spf /var/log

# Un panel por ruta, abiertos uno al lado del otro
spf ~/src ~/Downloads /mnt/backup

# Probar ajustes sin tocar tus propios archivos
spf --config-file /tmp/spf.toml --hotkey-file /tmp/spf-keys.toml

# ¿Qué versión hay instalada?
spf --version

Mantener la configuración al día:

# Añadir los campos y las teclas que trajo una versión nueva,
# dejando intacto todo lo que ya habías cambiado
spf --fix-config-file
spf --fix-hotkeys

# Imprimir todas las rutas que usa superfile
spf path-list

# Entorno, terminal y versión para un informe de error
spf --debug-info

Integrarlo en tu shell:

# Pon cd_on_quit = true en config.toml y esto en ~/.bashrc o
# ~/.zshrc: al salir con Q te quedas en el directorio que el
# panel estaba mostrando
spf() {
    export SPF_LAST_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/superfile/lastdir"
    command spf "$@"
    [ ! -f "$SPF_LAST_DIR" ] || { . "$SPF_LAST_DIR"; rm -f -- "$SPF_LAST_DIR"; }
}

# La ruta que lee esa función
spf path-list --lastdir-file

# superfile como selector de archivos para otro programa: escribe
# la ruta elegida en el archivo y sale
spf --chooser-file /tmp/picked

🔧 Integraciones

superfile deja a propósito las tareas especializadas a las herramientas que ya usas:

  • Tu editor: e abre el archivo resaltado en $EDITOR y E abre el directorio en dir_editor, así Neovim o Helix sigue siendo el editor y superfile el navegador
  • zoxide: pon zoxide_support = true y la tecla z salta usando la misma base de datos que tu shell lleva meses construyendo
  • exiftool: con libimage-exiftool-perl instalado y metadata = true, el panel de metadatos muestra los campos EXIF y de medios completos en vez de lo básico
  • bat y chroma: las vistas previas las resalta el chroma integrado, o bat si prefieres sus temas y pones code_previewer = "bat"
  • Tu terminal y tu shell: la vista previa de imágenes usa el protocolo de imágenes de la propia terminal, xdg-open se ocupa de los tipos que no hayas mapeado en [open_with], y cd_on_quit devuelve el último directorio a bash, zsh o fish

🚀 ¿Por qué elegir deb.griffo.io?

📊 Comparativa de repositorios:
  • Ubuntu oficial: no empaqueta superfile: apt install superfile falla en un sistema recién instalado
  • Compilar desde el código: actualizado, pero exige una cadena de Go en cada máquina y deja un binario del que apt no sabe nada
  • El script de instalación upstream: un curl desde superfile.dev, cómodo, pero escribe en tu sistema por detrás del gestor de paquetes y luego el binario te avisa él solo de sus actualizaciones
  • deb.griffo.io: última versión con actualizaciones automáticas
  • ✅ La única fuente apt: superfile no está ni en los archivos de Debian ni en los de Ubuntu; este repositorio empaqueta la release oficial upstream
  • ✅ El comando es spf: el paquete se llama superfile porque así se llama upstream, y pone /usr/bin/spf en tu PATH, que es el comando que usan todos los tutoriales y todas las páginas de teclas
  • ✅ Actualizaciones automáticas: los paquetes se actualizan pocas horas después de cada versión upstream, así que auto_check_update puede ir a false y de comprobar se encarga apt
  • ✅ Paquete completo: la compilación oficial upstream para Linux instalada como /usr/bin/spf, sin añadidos ni parches
  • ✅ Dependencias honestas: el binario no necesita nada, xdg-utils solo va como recomendado, y exiftool, zoxide, ffmpeg, poppler-utils y una herramienta de portapapeles quedan como sugeridos para las funciones opcionales que los usan
  • ✅ Dos arquitecturas: amd64 y arm64, ambas binarios de Go enlazados estáticamente, así que el mismo paquete funciona en todas las suites
  • ✅ Multidistribución: funciona en Ubuntu 22.04, 24.04, 25.10 y 26.04
  • ✅ Mantenimiento sencillo: actualizaciones con los comandos apt de siempre

❓ Preguntas frecuentes

¿Está superfile en los repositorios oficiales de Ubuntu?

No, superfile no está empaquetado en los archivos oficiales de Ubuntu. Este repositorio es actualmente la única fuente apt y ofrece superfile 1.6.0.

¿Cómo instalo el último superfile en Ubuntu?

Añade el repositorio deb.griffo.io una sola vez con las instrucciones de arriba y ejecuta: sudo apt install superfile. Las nuevas versiones llegan con el sudo apt upgrade habitual.

¿Los paquetes están firmados y cómo se compilan?

Cada paquete está firmado con la clave GPG del repositorio (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) y se compila a partir de versiones upstream en repositorios públicos de GitHub que cualquiera puede inspeccionar.

¿Qué versiones de Ubuntu son compatibles?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing y 26.04 Resolute.
