¿Qué es rumdl?

rumdl es un linter y formateador de Markdown escrito en Rust. Implementa el conjunto de reglas que todo el mundo conoce ya de markdownlint, las comprobaciones MD001 a MD059 sobre niveles de encabezado, sangrado de listas, longitud de línea, estilo de los bloques de código, sintaxis de los enlaces y espacios al final de línea, y las pasa por un árbol de documentación entero en milisegundos en vez de en segundos. La mayoría de esas reglas trae su corrección, así que rumdl check --fix arregla lo que informa en lugar de dejarte una lista, y rumdl fmt reformatea el archivo directamente. La configuración es un archivo rumdl.toml o una tabla [tool.rumdl] dentro de pyproject.toml, un .markdownlint.json que ya tengas se convierte con rumdl import, y rumdl server habla el Language Server Protocol, así que el mismo binario te subraya los problemas dentro del editor. Piénsalo como lo que Ruff es para Python, aplicado a Markdown.

🚀 Por qué importa la última versión: rumdl sigue añadiendo reglas, correcciones y claves de configuración versión a versión, y cada regla nueva es una comprobación que tu documentación no recibe hasta que actualizas. El comportamiento de las correcciones se afina en esas mismas versiones, así que un binario viejo puede reescribir un archivo de una forma que el actual ya no usaría, y un rumdl.toml escrito con la documentación de hoy puede nombrar opciones que una compilación antigua ignora en silencio. Ni Debian ni Ubuntu empaquetan rumdl, así que una compilación actual no es un lujo: es la única forma de tenerlo por apt.

⚡ Funciones clave de rumdl

🏎️ Las reglas de markdownlint a velocidad de Rust

Las comprobaciones MD001 a MD059 de siempre, ejecutadas por un binario compilado sin ningún intérprete que arrancar. Un árbol de documentación que se llevaba su propio paso en CI termina lo bastante rápido como para pasarlo en cada guardado.

🔧 Correcciones, no solo quejas

rumdl check --fix repara las infracciones que tienen un arreglo seguro: puntuación de los encabezados, marcadores y sangrado de las listas, líneas en blanco alrededor de los bloques, espacios sobrantes y estilo de las vallas, en el sitio y en todo el árbol.

🖊️ Y también un formateador

rumdl fmt reformatea el Markdown como lo hace un formateador de código, así que la forma de un archivo deja de ser un comentario de revisión. Con --check se convierte en una puerta de CI que no toca nada.

🔌 Integración con el editor de serie

rumdl server es un Language Server, así que VS Code, Neovim, Helix y Zed reciben los mismos diagnósticos y las mismas correcciones que la línea de comandos, del único binario que has instalado.

♻️ Conserva tu configuración de markdownlint

rumdl import lee un .markdownlint.json o un .markdownlintrc que ya tengas y escribe el rumdl.toml equivalente, así que pasar un repositorio es un comando, no una auditoría de reglas.

📖 Reglas que se explican solas

rumdl rule lista todas las comprobaciones y rumdl explain MD013 describe una, con lo que arregla y cómo se configura, así que nadie tiene que adivinar qué significaba ese código en un log de CI.

🚀 Siempre por delante de los archivos oficiales: Debian y Ubuntu congelan las versiones de los paquetes cuando publican una release; este repositorio publica las nuevas versiones upstream normalmente en cuestión de horas. Un simple apt upgrade te mantiene en la última versión.

Cómo funciona el espejo gratuito →

🧩 Sobre la opción extrepo. extrepo es la herramienta propia de Debian para repositorios externos: escribe el archivo de sources e instala la clave de firma por ti, comprobándola antes contra metadatos firmados. Este repositorio está registrado en ella como griffo, y el espejo gratuito para siempre como griffo-free, así que en Debian (bookworm, trixie, forky y sid) los comandos de arriba son toda la configuración.

extrepo solo configura el archivo de sources y la clave: las credenciales de una suscripción siguen yendo en /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu no está cubierto, porque extrepo publica metadatos solo para las suites de Debian: allí usa los comandos con sudo o como root.

🔧 Integraciones

rumdl está pensado para entrar en los sitios donde markdownlint ya está:

  • Tu editor: rumdl server es un Language Server, así que Neovim, Helix, VS Code y Zed muestran los diagnósticos en línea y aplican las correcciones como acciones de código
  • Configuraciones de markdownlint: rumdl import convierte .markdownlint.json o .markdownlintrc en rumdl.toml, y los códigos de las reglas son los mismos por los que tu equipo ya discute
  • pyproject.toml: una tabla [tool.rumdl] deja los ajustes junto a los de Ruff y pytest en lugar de añadir otro archivo de configuración
  • CI y pre-commit: rumdl check . sale con código distinto de cero si hay infracciones y rumdl fmt --check controla el formato, sin ningún runtime de Node o de Python que instalar antes en el agente
  • Generadores de sitios estáticos: las fuentes de MkDocs, Hugo, Docusaurus y mdBook son Markdown corriente, así que la misma comprobación pasa por ellas antes que la compilación

🚀 ¿Por qué elegir deb.griffo.io?

📊 Comparativa de repositorios:
  • Debian oficial: no empaqueta rumdl: apt install rumdl falla en un sistema recién instalado
  • npm o pip: funcionan, pero atan una comprobación de Markdown a un entorno de Node o de Python y la reinstalan en cada proyecto y en cada imagen de CI
  • Compilar desde el código: actualizado, pero exige una cadena de Rust en cada máquina y deja un binario del que apt no sabe nada
  • deb.griffo.io: última versión con actualizaciones automáticas
  • ✅ La única fuente apt: rumdl no está ni en los archivos de Debian ni en los de Ubuntu; este repositorio empaqueta la release oficial upstream
  • ✅ Para todo el sistema y sin runtime: un solo /usr/bin/rumdl para todos los repositorios de la máquina, sin npm install y sin ningún entorno virtual por detrás
  • ✅ Actualizaciones automáticas: los paquetes se actualizan pocas horas después de cada versión upstream, así que las reglas y las correcciones nuevas llegan con un apt upgrade normal
  • ✅ Paquete completo: la compilación oficial upstream para Linux instalada como /usr/bin/rumdl, sin añadidos ni parches
  • ✅ Dependencias honestas: un binario de Rust enlazado estáticamente que no necesita nada más instalado para analizar, arreglar, formatear o servir
  • ✅ Dos arquitecturas: amd64 y arm64, así que el mismo paquete cubre tu portátil, tus servidores y tus agentes de compilación arm64
  • ✅ Multidistribución: funciona en Bookworm, Trixie, Forky y Sid
  • ✅ Mantenimiento sencillo: actualizaciones con los comandos apt de siempre

❓ Preguntas frecuentes

¿Está rumdl en los repositorios oficiales de Debian?

No, rumdl no está empaquetado en los archivos oficiales de Debian. Este repositorio es actualmente la única fuente apt y ofrece rumdl 0.2.66.

¿Cómo instalo el último rumdl en Debian?

Añade el repositorio deb.griffo.io una sola vez con las instrucciones de arriba y ejecuta: sudo apt install rumdl. Las nuevas versiones llegan con el sudo apt upgrade habitual.

¿Los paquetes están firmados y cómo se compilan?

Cada paquete está firmado con la clave GPG del repositorio (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) y se compila a partir de versiones upstream en repositorios públicos de GitHub que cualquiera puede inspeccionar.

¿Qué versiones de Debian son compatibles?

Debian 12 Bookworm, Debian 13 Trixie, Forky y Sid.
