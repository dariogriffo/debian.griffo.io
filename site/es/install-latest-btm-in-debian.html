¿Qué es bottom?

bottom —el comando es btm— es un monitor gráfico de procesos y del sistema para la terminal, escrito en Rust e inspirado en gtop, gotop y htop. De forma predeterminada funciona como un panel: CPU, memoria, red, discos, temperaturas y procesos comparten una sola pantalla, y cualquier widget se puede ordenar, ampliar o expandir a toda la terminal.

🚀 Por qué importa la última versión: los archivos oficiales van varias versiones menores por detrás, y justo ahí ocurrió lo interesante: contabilizar la caché y los búferes por separado, uso de GPU en el widget de memoria, temas de color integrados, filtrado de hilos del kernel y una larga lista de arreglos para kernels y sensores recientes. Un monitor que lee mal tu hardware es peor que no tener monitor, así que conviene mantenerlo al día.

⚡ Funciones clave de bottom

📈 Gráficas en vivo

CPU (por núcleo o promediada), memoria, tráfico de red, E/S de disco y temperaturas como gráficas en movimiento que amplías con + y -.

🔍 Búsqueda de procesos

/ filtra la tabla de procesos, con conmutadores de regex, palabra completa y distinción de mayúsculas, y una tecla para ordenar por CPU, memoria, PID o nombre.

🌲 Modo árbol

t convierte la tabla de procesos en un árbol, así el proceso descontrolado aparece bajo el padre que lo lanzó en lugar de suelto en la lista.

🎛️ Diseños propios

El archivo de configuración describe filas, columnas y proporciones de los widgets, para que el panel muestre las cuatro cosas que de verdad vigilas.

🎨 Temas integrados

--theme gruvbox, nord y sus variantes claras vienen en el binario, y cada color se puede redefinir en bottom.toml.

🖥️ Modo básico

btm --basic quita las gráficas y deja una lectura numérica compacta, legible por SSH lento o en un panel pequeño de tmux.

🚀 Siempre por delante de los archivos oficiales: Debian y Ubuntu congelan las versiones de los paquetes cuando publican una release; este repositorio publica las nuevas versiones upstream normalmente en cuestión de horas. Un simple apt upgrade te mantiene en la última versión.

🎯 Ejemplos básicos de uso

Supervisión del día a día:

# El panel completo
btm

# Refrescar dos veces por segundo y guardar diez minutos de historial
btm --rate 500ms --retention 10m

# Arrancar en el widget de procesos, ya expandido
btm --default_widget_type proc --expanded

# Árbol de procesos, agrupado, con la línea de comandos completa
btm --tree --process_command

Dentro del panel:

# Las teclas que hacen el trabajo
#   ?        ayuda integrada con todos los atajos
#   e        expandir el widget seleccionado a toda la terminal
#   f        congelar la pantalla mientras la lees
#   +  -  =  acercar, alejar o restablecer una gráfica
#   /        buscar en la tabla de procesos
#   c m p n  ordenar por CPU, memoria, PID o nombre
#   dd       detener el proceso seleccionado
#   t        alternar el árbol de procesos

Ajustarlo a tu máquina:

# Fahrenheit, sin fila de CPU promedio, marcadores de puntos en vez de braille
btm --fahrenheit --hide_avg_cpu --dot_marker

# Contar caché y búferes como una línea de memoria aparte
btm --enable_cache_memory

# Widget de batería en un portátil
btm --battery

# Un tema de color a juego con el resto de la terminal
btm --theme gruvbox

🔧 Integraciones con otras herramientas

bottom está pensado para un entorno centrado en la terminal:

  • Archivo de configuración: ~/.config/bottom/bottom.toml reúne diseño, proporciones de widgets, colores y tus opciones habituales
  • Entrada de escritorio: el paquete instala bottom.desktop y su icono, así que bottom también aparece en el menú de aplicaciones
  • tmux y Zellij: cómodo en un panel estrecho; --basic lo mantiene legible cuando el panel se reduce
  • GPU: el uso de NVIDIA y AMD aparece en el widget de memoria si están los controladores, y --disable_gpu desactiva la recolección
  • Servidores: la compilación amd64 es estática: un Debian o Ubuntu recién instalado no necesita nada más que el paquete

🚀 ¿Por qué elegir deb.griffo.io?

📊 Comparativa de repositorios:
  • Debian oficial: incluye btm, pero congelado varias versiones menores atrás: los widgets, temas y arreglos de sensores nuevos solo llegan con la siguiente release de Debian
  • cargo install bottom: actualizado, pero compila durante varios minutos, queda fuera de apt y no trae página de manual, completaciones ni entrada de escritorio
  • Tarball upstream: el binario oficial, que tendrás que descargar a mano en cada versión
  • deb.griffo.io: última versión con actualizaciones automáticas
  • ✅ Widgets actuales: la versión más reciente, con los widgets, temas y arreglos de sensores que upstream añadió después de que se congelara el archivo
  • ✅ Reemplazo directo de bottom: el paquete se llama btm, como el comando, y declara Provides/Replaces de bottom, así que encaja donde estaba el paquete oficial
  • ✅ Actualizaciones automáticas: los paquetes se actualizan pocas horas después de cada versión upstream
  • ✅ Paquete completo: el binario upstream más la página de manual btm.1, las completaciones de bash, zsh y fish, la entrada de escritorio y su icono
  • ✅ Cinco arquitecturas: amd64, arm64, armhf, i386 y riscv64: el mismo monitor en un portátil, una Raspberry Pi y una placa RISC-V
  • ✅ Multidistribución: funciona en Bookworm, Trixie, Forky y Sid
  • ✅ Mantenimiento sencillo: actualizaciones con los comandos apt de siempre

❓ Preguntas frecuentes

¿Está bottom en los repositorios oficiales de Debian?

Sí, pero el archivo oficial de Debian trae bottom 0.10.2, mientras que este repositorio ofrece bottom 0.14.8, recompilado pocas horas después de cada versión upstream.

¿Cómo instalo el último bottom en Debian?

Añade el repositorio deb.griffo.io una sola vez con las instrucciones de arriba y ejecuta: sudo apt install btm. Las nuevas versiones llegan con el sudo apt upgrade habitual.

¿Los paquetes están firmados y cómo se compilan?

Cada paquete está firmado con la clave GPG del repositorio (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) y se compila a partir de versiones upstream en repositorios públicos de GitHub que cualquiera puede inspeccionar.

¿Qué versiones de Debian son compatibles?

Debian 12 Bookworm, Debian 13 Trixie, Forky y Sid.
