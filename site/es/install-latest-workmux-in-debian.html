¿Qué es workmux?

workmux convierte una rama en un espacio de trabajo. Un solo workmux add crea un worktree de git, abre la ventana de tmux correspondiente, copia los archivos que a una copia recién creada le faltan (.env, credenciales), enlaza los que no quieres reinstalar (node_modules), ejecuta tus comandos de preparación y monta el diseño de paneles que pediste. workmux merge lo deshace todo de una vez: fusiona la rama, borra el worktree, cierra la ventana y elimina la rama local. Sin stash, sin cambiar de rama, sin una copia a medias bloqueando la siguiente tarea.

🚀 Por qué importa la última versión: workmux publica varias versiones por semana, y casi todas tienen que ver con las herramientas que dirige: qué agentes de código puede seguir, cómo informa su estado, qué multiplexores de terminal soporta y qué muestran el dashboard y la barra lateral. Una integración añadida la semana pasada solo existe en el binario de la semana pasada. Ni Debian ni Ubuntu lo empaquetan, así que una compilación actual no es un lujo: es la única forma de tenerlo por apt.

⚡ Funciones clave de workmux

🌿 Una ventana por rama

workmux add crea el worktree y la ventana de tmux a la vez, así que cambiar de tarea es cambiar de pestaña, con su propio shell, editor y servidor de desarrollo.

🧰 Worktrees que funcionan de verdad

Un worktree recién creado nace roto. workmux copia archivos de configuración, enlaza dependencias y ejecuta tus comandos post_create para que la copia nueva sea usable de inmediato.

🤖 Agentes en paralelo

Ejecuta varios agentes de código a la vez, uno por worktree, y sigue su estado en el nombre de la ventana de tmux, en un dashboard TUI o en una barra lateral en vivo.

🧹 Limpieza con un solo comando

workmux merge fusiona la rama y luego elimina el worktree, la ventana de tmux y la rama local; workmux remove hace la limpieza sin fusionar.

📄 Configurado en YAML

Un config.yaml global para tus valores por defecto y un .workmux.yaml por proyecto para diseños de paneles, hooks y operaciones de archivos, con anidamiento pensado para monorepos.

🖥️ No solo tmux

tmux es el backend por defecto, y kitty, WezTerm y Zellij son alternativas soportadas, así que el flujo se adapta a la terminal que ya usas.

🚀 Siempre por delante de los archivos oficiales: Debian y Ubuntu congelan las versiones de los paquetes cuando publican una release; este repositorio publica las nuevas versiones upstream normalmente en cuestión de horas. Un simple apt upgrade te mantiene en la última versión.

Cómo funciona el espejo gratuito →

🧩 Sobre la opción extrepo. extrepo es la herramienta propia de Debian para repositorios externos: escribe el archivo de sources e instala la clave de firma por ti, comprobándola antes contra metadatos firmados. Este repositorio está registrado en ella como griffo, y el espejo gratuito para siempre como griffo-free, así que en Debian (bookworm, trixie, forky y sid) los comandos de arriba son toda la configuración.

extrepo solo configura el archivo de sources y la clave: las credenciales de una suscripción siguen yendo en /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu no está cubierto, porque extrepo publica metadatos solo para las suites de Debian: allí usa los comandos con sudo o como root.

🎯 Ejemplos básicos de uso

El ciclo del día a día:

# Crear una rama, un worktree y una ventana de tmux
workmux add fix-login

# Una rama existente se reconoce por su nombre
workmux add trabajo-existente

# Partir de una base distinta a la de por defecto
workmux add hotfix --base production

# Sacar un pull request a su propio worktree
workmux add --pr 123

# Ver todo lo que tienes en marcha
workmux list

# Fusionar y desmontarlo todo
workmux merge

# O descartar el trabajo sin fusionar
workmux remove fix-login

Ventanas, paneles y recuperación:

# Crear la ventana sin saltar a ella
workmux add repaso-docs --background

# Cerrar una ventana conservando worktree y rama
workmux close repaso-docs

# Volver a abrirla más tarde
workmux open repaso-docs

# Reconstruir todas las ventanas tras un cuelgue de tmux o de la máquina
workmux resurrect

# Entrar en un worktree desde cualquier sitio
cd "$(workmux path fix-login)"

Agentes trabajando en paralelo:

# Instalar los hooks de estado y las skills de tu agente
workmux setup

# Arrancar un worktree con un prompt para el agente
workmux add add-tests --prompt "Añade tests unitarios para el parser"

# Ver todos los agentes en una TUI
workmux dashboard

# O dejar una barra lateral de estado en tmux
workmux sidebar

# Enviar una instrucción a un agente en marcha
workmux send add-tests "Cubre también las rutas de error"

# Esperar a que ese agente termine
workmux wait add-tests

🔧 Integraciones

workmux se apoya a propósito en las herramientas que ya usas:

  • git: los worktrees son checkouts normales de git worktree, así que git, tus hooks y tu CI no ven nada raro
  • tmux: una ventana por worktree, con el nombre de la rama y tu diseño de paneles aplicado automáticamente
  • kitty, WezTerm y Zellij: backends alternativos soportados si tmux no es tu multiplexor
  • Agentes de código: seguimiento de estado, inyección de prompts y skills para Claude Code y los demás agentes que soporta upstream
  • Tu shell: las completaciones de bash, zsh y fish vienen en este paquete, y alias wm='workmux' es el atajo que recomienda upstream

🚀 ¿Por qué elegir deb.griffo.io?

📊 Comparativa de repositorios:
  • Debian oficial: no empaqueta workmux: apt install workmux falla en un sistema recién instalado
  • cargo install workmux: actualizado, pero es compilar Rust en cada máquina, fuera de apt y sin las completaciones del shell
  • El script de instalación upstream: cómodo, pero escribe en tu sistema a espaldas del gestor de paquetes y se actualiza por su cuenta
  • deb.griffo.io: última versión con actualizaciones automáticas
  • ✅ La única fuente apt: workmux no está ni en los archivos de Debian ni en los de Ubuntu; este repositorio empaqueta la compilación oficial upstream
  • ✅ El soporte de agentes cambia cada semana: qué agentes puede seguir y dirigir workmux cambia versión a versión, así que estar al día es la diferencia entre que la función exista o no
  • ✅ Actualizaciones automáticas: los paquetes se actualizan pocas horas después de cada versión upstream
  • ✅ Paquete completo: el binario upstream como /usr/bin/workmux más las completaciones de bash, zsh y fish
  • ✅ Dependencias honestas: el paquete depende de git y recomienda tmux, porque kitty, WezTerm y Zellij también son backends soportados
  • ✅ Dos arquitecturas: amd64 y arm64, ambas compilaciones estáticas, así que el mismo paquete funciona en todas las suites
  • ✅ Multidistribución: funciona en Bookworm, Trixie, Forky y Sid
  • ✅ Mantenimiento sencillo: actualizaciones con los comandos apt de siempre

❓ Preguntas frecuentes

¿Está workmux en los repositorios oficiales de Debian?

No, workmux no está empaquetado en los archivos oficiales de Debian. Este repositorio es actualmente la única fuente apt y ofrece workmux 0.1.248.

¿Cómo instalo el último workmux en Debian?

Añade el repositorio deb.griffo.io una sola vez con las instrucciones de arriba y ejecuta: sudo apt install workmux. Las nuevas versiones llegan con el sudo apt upgrade habitual.

¿Los paquetes están firmados y cómo se compilan?

Cada paquete está firmado con la clave GPG del repositorio (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) y se compila a partir de versiones upstream en repositorios públicos de GitHub que cualquiera puede inspeccionar.

¿Qué versiones de Debian son compatibles?

Debian 12 Bookworm, Debian 13 Trixie, Forky y Sid.
