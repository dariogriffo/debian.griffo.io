¿Qué es tldr?

tldr es el cliente oficial en Rust de tldr-pages, la colección de páginas man simplificadas que mantiene la comunidad: cada página es una descripción de una línea del comando seguida de un puñado de los ejemplos que la gente escribe de verdad. El proyecto upstream se llama tlrc; el paquete y el comando se llaman tldr. Es un único binario estático sin dependencias, guarda toda la colección en una caché local para que cada consulta sea instantánea y funcione sin conexión, y refresca esa caché por su cuenta cuando envejece. Las páginas vienen por plataforma (Linux, macOS, Windows, Android, los BSD) y en decenas de idiomas, los colores y la disposición de la salida son un archivo TOML, y el paquete incluye la página man y el autocompletado para bash, zsh y fish.

🚀 Por qué importa la última versión: tlrc avanza con la especificación de clientes de tldr-pages: los directorios de plataforma nuevos, las reglas de respaldo entre idiomas, la búsqueda de páginas, el directorio de páginas propias y las claves de configuración que controlan la edad de la caché y los colores llegaron versión a versión, y un binario viejo o las ignora o dibuja mal las páginas más nuevas. El paquete tldr de Debian es otro programa, el cliente en Haskell tldr-hs, y el tealdeer de Debian también instala un /usr/bin/tldr; ninguno de los dos es tlrc, así que este repositorio es la forma de tener el cliente oficial por apt.

⚡ Funciones clave de tldr

📄 Los ejemplos primero

tldr tar imprime las ocho formas en que usas tar de verdad en lugar de las doscientas opciones que acepta. Los comandos de varias palabras funcionan tal como los escribes: tldr git rebase, tldr docker compose.

⚡ Una caché local, no una petición

La primera ejecución descarga toda la colección; cada consulta posterior es leer un archivo, así que la página aparece antes de levantar el dedo de Intro, en un tren o detrás de un proxy. La caché se actualiza sola cuando supera la edad que fijes, o con --update.

🖥️ Todas las plataformas, un comando

Las páginas están organizadas por plataforma. Por defecto obtienes la de Linux, y -p macos o -p windows cuando escribes instrucciones para una máquina que no es la que tienes delante.

🌍 Tu idioma

tldr-pages está traducido a decenas de idiomas. tlrc sigue LANG y LANGUAGE y recurre al inglés página a página, o -L elige uno para una sola consulta.

🔍 Encontrar la página que no conoces

--list imprime todos los nombres de página de la plataforma actual, --search busca en nombres y descripciones, y --info te dice qué edad tiene la caché y qué idiomas contiene.

🎨 Configurado a tu gusto

Un config.toml: cada color y estilo de la página dibujada, la edad de la caché antes de una actualización automática, los idiomas que descargar, la plataforma preferida y un directorio de páginas propias que se consulta antes que la caché.

🚀 Siempre por delante de los archivos oficiales: Debian y Ubuntu congelan las versiones de los paquetes cuando publican una release; este repositorio publica las nuevas versiones upstream normalmente en cuestión de horas. Un simple apt upgrade te mantiene en la última versión.

Cómo funciona el espejo gratuito →

🧩 Sobre la opción extrepo. extrepo es la herramienta propia de Debian para repositorios externos: escribe el archivo de sources e instala la clave de firma por ti, comprobándola antes contra metadatos firmados. Este repositorio está registrado en ella como griffo, y el espejo gratuito para siempre como griffo-free, así que en Debian (bookworm, trixie, forky y sid) los comandos de arriba son toda la configuración.

extrepo solo configura el archivo de sources y la clave: las credenciales de una suscripción siguen yendo en /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu no está cubierto, porque extrepo publica metadatos solo para las suites de Debian: allí usa los comandos con sudo o como root.

🎯 Ejemplos básicos de uso

Consultar:

# La página de un comando
tldr tar

# Subcomandos, escritos como los teclearías
tldr git rebase

# Una página de otra plataforma
tldr -p macos brew
tldr -p windows choco

# Una página en otro idioma para una sola consulta
tldr -L es tar

# Todos los nombres de página de esta plataforma, y una búsqueda
# por nombres y descripciones cuando no sabes el comando
tldr --list
tldr --search "compress"

Dar forma a la salida:

# Markdown en crudo, para encadenarlo a otra cosa
tldr -R tar

# Quitar las líneas en blanco en una terminal pequeña
tldr --compact tar

# Sin colores, para logs y scripts
tldr --color never tar

# No tocar nunca la red, aunque la caché esté caducada
tldr --offline tar

# Dibujar una página que estás escribiendo antes de enviarla upstream
tldr -r my-command.md

Hacerlo tuyo:

# De dónde se lee la configuración, y un valor por defecto para empezar
tldr --config-path
mkdir -p "$(dirname "$(tldr --config-path)")"
tldr --gen-config > "$(tldr --config-path)"

# Luego, en config.toml: edad de la caché antes de una actualización
# automática, los idiomas que conservar, la plataforma preferida
# y los colores de cada parte de una página

# Vaciar la caché si una descarga salió mal
tldr --clean-cache

🔧 Integraciones

tldr es una consulta, así que encaja junto a las herramientas que ya usas:

  • Tu shell: el paquete instala el autocompletado para bash, zsh y fish, así que tldr gi<tab> completa nombres de página desde la caché, y man tldr está ahí para el propio cliente
  • fzf: tldr --list | fzf | xargs tldr es un selector difuso de páginas en una línea, y la salida de --raw alimenta el panel de vista previa
  • Corregir una página: tldr --edit tar imprime un enlace que abre esa página en el editor web de GitHub, así que corregir una página tldr está a un pull request de distancia
  • man: tldr no sustituye al manual, es lo primero que se lee; la página completa está a un man de distancia en cuanto sabes qué opción quieres
  • Scripts y documentación: --color never y --raw hacen que la salida se pueda pegar sin miedo en un README, un ticket o un log

🚀 ¿Por qué elegir deb.griffo.io?

📊 Comparativa de repositorios:
  • Debian oficial: apt install tldr te da tldr-hs, el cliente en Haskell, y tealdeer es otro cliente en Rust con el mismo nombre de comando; ninguno de los dos es el tlrc oficial
  • Compilar desde el código: actualizado, pero exige una cadena de Rust en cada máquina y deja un binario del que apt no sabe nada
  • El tarball de la release upstream: el mismo binario estático, pero desempaquetado a mano en tu PATH, sin autocompletado, sin página man y sin actualizaciones
  • deb.griffo.io: última versión con actualizaciones automáticas
  • ✅ El cliente oficial: tlrc, el cliente que mantiene el propio proyecto tldr-pages, no una de las muchas reimplementaciones
  • ✅ El comando es tldr: el paquete se llama tldr porque ese es el comando, y entra en conflicto con tealdeer y lo reemplaza, así que nunca hay pelea por /usr/bin/tldr
  • ✅ Actualizaciones automáticas: los paquetes se actualizan pocas horas después de cada versión upstream, y la caché de páginas se actualiza sola por encima
  • ✅ Paquete completo: el binario, la página man y el autocompletado para bash, zsh y fish
  • ✅ Cero dependencias: un binario musl enlazado estáticamente, no arrastra nada más
  • ✅ Dos arquitecturas: amd64 y arm64, el mismo binario estático en todas las suites
  • ✅ Multidistribución: funciona en Debian 13 (trixie) o posterior: Trixie, Forky y Sid
  • ✅ Mantenimiento sencillo: actualizaciones con los comandos apt de siempre

❓ Preguntas frecuentes

¿Está tldr en los repositorios oficiales de Debian?

No, tldr no está empaquetado en los archivos oficiales de Debian. Este repositorio es actualmente la única fuente apt y ofrece tldr 1.13.1.

¿Cómo instalo el último tldr en Debian?

Añade el repositorio deb.griffo.io una sola vez con las instrucciones de arriba y ejecuta: sudo apt install tldr. Las nuevas versiones llegan con el sudo apt upgrade habitual.

¿Los paquetes están firmados y cómo se compilan?

Cada paquete está firmado con la clave GPG del repositorio (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) y se compila a partir de versiones upstream en repositorios públicos de GitHub que cualquiera puede inspeccionar.

¿Qué versiones de Debian son compatibles?

Debian 12 Bookworm, Debian 13 Trixie, Forky y Sid.
