kitty とは

kitty は一日中ターミナルで過ごす人のための、GPU ベースのターミナルエミュレーターです。描画は OpenGL で行うので、ビルドログや色付き出力の壁も滑らかにスクロールし、ターミナルをテキストボックスではなくプラットフォームとして扱います。タイル型レイアウトで並ぶウィンドウとタブ、本物の画像を出力の中に描くグラフィックスプロトコル、プログラムが shift+enter と enter を区別できるキーボードプロトコル、クリックできるハイパーリンク、リガチャ、そしてプロンプトと各コマンドの出力がどこで始まりどこで終わるかを知っているシェル統合。ターミナルの隣には kitten が付いてきます。ターミナルの土台になっている小さなツールをまとめた単一の相棒実行ファイルで、kitten icat は画像を表示し、kitten ssh は terminfo とシェル統合をリモートホストに持ち込み、kitten diff は画像も扱える横並びの diff、ほかに kitten clipboard、kitten themes、そしてスクリプトからターミナル自身を操る kitten @。作者は calibre の作者でもある Kovid Goyal で、設定はすべて 1 つの kitty.conf にまとまっています。

🚀 最新版が効いてくる理由: kitty はおよそ月に一度リリースされ、そのたびに、ほかのツールが土台にしているプロトコルが動きます。yazi、viu、Neovim の画像プラグインが描画に使うグラフィックスプロトコル、エディタが交渉するキーボードプロトコル、テキストサイズ、シェル統合のフック、リモートコントロールのコマンド。Ubuntu 26.04 は 0.45.0 で凍結され、Noble は寿命いっぱい 0.32.2 のままで、Jammy の 0.21.2 は独立した kitten 実行ファイルより前のものなので、現在のドキュメントにある kitten ssh や kitten icat というコマンドがそもそも存在しません。古い kitty は、現在のドキュメントが設定を勧めている kitty.conf の項目も黙って無視しますし、新しい kitten (choose-fonts、notify、quick-access-terminal、panel) はただ存在しません。ターミナルは一日中使う唯一のプログラムです。最新であるべきです。

⚡ kitty の主な機能

🎮 GPU レンダリング

kitty は OpenGL で描画し、グリフの処理を GPU に渡して、CPU は実際に動かしているプログラムのために残します。大きな出力はディスプレイのリフレッシュレートでスクロールし、テキストの洪水の中でもターミナルは応答し続けます。

🪟 ウィンドウ、タブ、レイアウト

タブをウィンドウに分割し、レイアウト (tall、fat、grid、splits、stack) に配置を任せます。ctrl+shift+enter でウィンドウ、ctrl+shift+t でタブが開きます。セッションファイルは、各ウィンドウのディレクトリとコマンドごと、ワークスペース全体を再現します。

🖼️ グラフィックスプロトコル

ブロック文字ではなく、本物の画像。kitten icat は画像を出力の中に表示し、yazi、viu、Neovim の画像プラグイン、matplotlib のバックエンドがターミナルに描くときに使うのも同じプロトコルです。

🐈 Kittens

kitten は小さなツールを詰め込んだ 1 つの静的実行ファイルです。icat、ssh、diff、clipboard、themes、画面上の URL やパスやハッシュをキーボードで拾う hints、unicode_input、ssh セッション越しにファイルをコピーする transfer、その他いろいろ。

🎛️ リモートコントロール

allow_remote_control を有効にすると、kitten @ がどんなスクリプトからでもターミナルを操作します。ウィンドウを開く、テキストを送る、色を変える、サイズを変える、何が動いているか一覧する。間にマルチプレクサを挟まない、スクリプトで組むレイアウトです。

🐚 シェル統合

kitty は各プロンプトがどこで始まるかを知っています。ctrl+shift+z でプロンプト間を移動し、直前のコマンドの出力をページャーで開き、クリックで現在行の中のカーソルを動かし、新しいウィンドウは現在のディレクトリで開きます。bash、zsh、fish に対応し、kitty-shell-integration が同梱しています。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

🎯 基本的な使用例

起動する:

# ターミナルを開く
kitty

# 新しい kitty ウィンドウでコマンドを実行し、終了後も開いたままにする
kitty --hold htop

# kitty.conf のどの設定でもコマンドラインで上書きする
kitty -o font_size=14 -o background_opacity=0.9

# ディレクトリを指定して起動する
kitty --directory ~/src

# セッションファイルからワークスペース全体を復元する
kitty --session ~/.config/kitty/work.session

# 入っているのはどのバージョン？
kitty --version

kitten たち:

# 画像をターミナルにそのまま表示する
kitten icat photo.png

# terminfo とシェル統合を連れて ssh する
kitten ssh user@server

# 横並びの diff、画像も含めて
kitten diff old.txt new.txt

# システムのクリップボードにコピーし、読み出す
echo hello | kitten clipboard
kitten clipboard --get-clipboard

# 開いているすべての kitty ウィンドウにテーマを適用する
kitten themes --reload-in=all Catppuccin-Mocha

# フォントを対話的に選ぶ
kitten choose-fonts

リモートコントロール:

# kitty.conf に allow_remote_control yes を書き、kitty の中で動いている
# どのシェルからでも: この右側に新しいウィンドウを開く
kitten @ launch --location=vsplit --cwd=current

# タイトルで選んだ別のウィンドウにコマンドを打ち込む
kitten @ send-text --match title:logs "tail -f /var/log/syslog\n"

# 色をその場で変える
kitten @ set-colors background=#1e1e2e

# いま何が開いているか
kitten @ ls

🔧 ツール連携

kitty はほかのすべての下にあるターミナルなので、連携の話はおもにその中で動くものについてです:

  • リモートサーバー: kitty は TERM=xterm-kitty を設定するので、その terminfo がないホストでは backspace が壊れ、less や clear が文句を言います。kitten ssh は terminfo を自動でコピーしてくれます。素の ssh でつなぐホストには、そちらに kitty-terminfo を入れてください。terminfo エントリだけを収めた、ほかに何も引き込まないアーキテクチャ非依存のパッケージです
  • あなたのシェル: kitty-shell-integration が bash、zsh、fish のフックを /usr/share/kitty/shell-integration に置き、kitty.conf の既定値である shell_integration enabled が、rc ファイルに触れずにそれらを有効にします
  • yazi、viu、Neovim: 3 つとも kitty のグラフィックスプロトコルで画像を描き、Neovim は kitty のキーボードプロトコルをネイティブに話します。つまり、これらがテストされたターミナルです
  • Zellij と tmux: kitty 自身のウィンドウ、タブ、レイアウトで、ローカルのマルチプレクサがやることの大半は足ります。セッションがウィンドウより長生きする必要があるなら Zellij を、tmux を使うなら extended-keys と passthrough を設定して、kitty のプロトコルが途中で失われないようにしてください
  • あなたのデスクトップ: パッケージはデスクトップエントリ、アイコン、man ページを入れ、x-terminal-emulator の alternative を登録するので、kitty はランチャーに現れ、update-alternatives 一発でシステムの既定になります

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Ubuntu: 26.04 では kitty 0.45.0、Noble では 0.32.2、Jammy では 0.21.2 を収録し、どれもリリースの寿命いっぱい凍結されたままです
  • 上流のインストーラー: curl | sh 一発で ~/.local/kitty.app に入り、最新ではありますが、ユーザー単位で、デスクトップエントリも man ページも x-terminal-emulator も自分で配線しない限りなく、更新はインストーラーをもう一度走らせる方式です
  • ソースからビルド: Python、Go、長い -dev パッケージの列と、それなりの時間。その結果が apt の知らないバイナリです
  • deb.griffo.io: 最新版を自動更新でお届け
  • ✅ Ubuntu と同じパッケージ名: kitty、kitty-terminfo、kitty-shell-integration、kitty-doc。Ubuntu のアーカイブとまったく同じ名前なので、このリポジトリは標準の kitty をその場で置き換え、後で apt remove しても何も残りません
  • ✅ 公式ビルド: 上流のビルド済みバンドル、kitty 自身のインストーラーと同じバイト列を /opt/kitty に置き、/usr/bin/kitty と /usr/bin/kitten のシンボリックリンクを張ります。ソースビルドもパッチもありません
  • ✅ きちんと統合: デスクトップエントリ、アイコン、man ページ、terminfo、シェル統合が Debian 標準のパスにあり、x-terminal-emulator の alternative も登録済みです
  • ✅ kitty-terminfo は単独で旅する: xterm-kitty の terminfo だけを収めたアーキテクチャ非依存のパッケージ。ssh で入るサーバー向けです
  • ✅ 自動更新: 上流のリリースから数時間以内にパッケージを更新
  • ✅ 2 つのアーキテクチャ: amd64 と arm64。上流がバンドルを公開しているのがこの 2 つで、i386、armhf、riscv64 のビルドはありません
  • ✅ マルチディストリビューション: Ubuntu 22.04、24.04、25.10、26.04 で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

❓ よくある質問

kitty は公式の Ubuntu リポジトリにありますか？

あります。ただし公式 Ubuntu アーカイブが配布しているのは kitty 0.45.0 で、このリポジトリは上流のリリースから数時間以内に再ビルドした kitty 0.49.2 を配布しています。

Ubuntu に最新の kitty を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install kitty を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Ubuntu のどのリリースに対応していますか？

Ubuntu 22.04 Jammy、24.04 Noble、25.10 Questing、26.04 Resolute。
