lnav とは

lnav (Logfile Navigator) は、複数のソースのログファイルをひとつにまとめ、タイムスタンプ順に表示するターミナル向けのログビューアです。いくつかのファイルやディレクトリ、圧縮アーカイブを指定するだけで、フォーマット (syslog、systemd ジャーナル、Apache や nginx のアクセスログ、JSON Lines など多数) を自動で判別し、メッセージを時刻順に並べ、エラーと警告を色分けして目立たせ、ファイルが伸びていくのを追いかけ続けます。そこからフィルタ、検索、エラー間のジャンプができ、検索では足りない疑問には SQL でログメッセージを問い合わせられます。ssh 越しのリモートのログも、ローカルと同じ手軽さで開けます。lnav は Tim Stack が C++ で書いたもので、BSD-2-Clause ライセンスです。

🚀 最新版が効いてくる理由: lnav はリリースのたびにフォーマット、SQL 関数、ビューアの機能が増え、特定のログの解析方法も修正されています。Debian trixie の lnav は 0.12.4、Bookworm は 0.11.1 で固定されているため、標準のシステムでは現在のリリースと、それに含まれるフォーマットや修正を使えません。このリポジトリは lnav 0.14.1 を同じパッケージ名で配布しているので、次の apt upgrade でディストリビューションの lnav がその場で置き換わります。

⚡ lnav の主な機能

🔀 ひとつにまとまったタイムライン

syslog、アプリのログ、Web サーバーのログを一緒に開くと、lnav が各行をタイムスタンプ順に並べます。システム全体で何が起きたのかを、起きた順に読めます。

🔍 フォーマットの自動判別

syslog、journald の JSON、Apache と nginx のアクセスログ、JSON Lines、logfmt など数十のフォーマットを設定なしで認識します。レベル、タイムスタンプ、フィールドが解析され、エラーと警告が強調表示されます。

🗄️ ログに SQL を

認識されたフォーマットはそれぞれテーブルになります。; を押して SELECT クエリを実行すれば、ホストごとのエラー数、最も遅いリクエスト、ステータスコードの集計などが、同じ画面に表示されます。

🌐 ssh 越しのリモートログ

lnav user@host:/var/log/syslog で、別のマシンのログをいつもの ssh 設定と鍵で開けます。サーバー側にエージェントを入れる必要はありません。

📦 圧縮ファイルとアーカイブ

ローテートされた .gz や .bz2 のログをそのまま開け、.zip や .tar のアーカイブも同様です。サポートバンドルを展開せずに読めます。

👀 追従、フィルタ、検索

ファイルは伸びるそばから追いかけられ、フィルタはパターンで行を隠したり残したりし、検索はすべての一致を強調表示します。キーひとつで次のエラーや警告へジャンプできるので、大事なものを見逃しません。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

無料ミラーの仕組み →

🧩 extrepo オプションについて。 extrepo は外部リポジトリを扱う Debian 標準のツールです。署名済みメタデータと照合して鍵を検証したうえで、sources ファイルの作成と署名鍵のインストールを代わりに行います。このリポジトリは griffo、ずっと無料のミラーは griffo-free という名前で登録されているので、Debian（bookworm、trixie、forky、sid）では上のコマンドだけで設定は完了です。

extrepo が用意するのは sources ファイルと鍵だけなので、サブスクリプションの認証情報は引き続き /etc/apt/auth.conf.d/deb.griffo.io.conf に書きます。extrepo は Debian のスイート向けメタデータしか公開していないため Ubuntu は対象外です。Ubuntu では sudo または root のコマンドを使ってください。

🎯 基本的な使用例

ログを読んで追いかける:

# ローテートされた圧縮ログも、アーカイブもそのまま開けます
lnav /var/log/nginx/access.log.2.gz support-bundle.tar.gz

# 複数のソースを、タイムスタンプ順のひとつのタイムラインに
lnav /var/log/nginx/ ~/app/logs/app.log

# 別のマシンのログを、いつもの ssh 設定で
lnav user@host:/var/log/syslog

フィルタと SQL:

# lnav の中で: e / E で次 / 前のエラーへ、w / W で警告へ
# :filter-in error         一致する行だけを残す
# :filter-out healthcheck  一致する行を隠す
# ;SELECT c_ip, count(*) AS hits FROM access_log GROUP BY c_ip ORDER BY hits DESC

# 同じクエリを UI なしで、スクリプト向けに
lnav -n -c ';SELECT sc_status, count(*) FROM access_log GROUP BY sc_status' /var/log/nginx/access.log

🔧 ツール連携

lnav はテキストを出すものなら何でも読めます。ファイルからも、パイプからも、他のマシンからも:

  • ssh: user@host:/var/log/syslog のようなリモートパスは、既存の ssh 設定と鍵を通して開かれます。パッケージはこのために openssh-client を推奨しています
  • systemd ジャーナル: journalctl -o json (追従するなら -f を追加) を lnav にパイプすれば、ジャーナルのすべてのフィールドを検索でき、クエリにも使えます
  • コンテナ: docker logs -f app 2>&1 | lnav や kubectl logs -f pod | lnav で、コンテナの出力にも同じ強調表示と SQL が使えます
  • クリップボード: 行をマークして c を押すとコピーできます。パッケージは Wayland と X11 向けに wl-clipboard または xclip を提案しています
  • 独自フォーマット: 社内のログフォーマットを JSON ファイルに記述し、lnav -i myformat.json でインストールすれば、判別、強調表示、専用の SQL テーブルが使えるようになります
  • スクリプトと CI: lnav -n -c はコマンドとクエリを UI なしで実行するので、対話的に答えを出した SQL を、そのまま cron ジョブやパイプラインで動かせます
  • ドキュメント: man ページはパッケージに含まれており (man lnav)、完全なマニュアルは docs.lnav.org にあります

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Debian: trixie では lnav 0.12.4、Bookworm では 0.11.1 を収録しており、いずれもリリースの期間中は固定されたままです
  • 上流からのダウンロード: GitHub のリリースページにある静的バイナリの zip を手動で PATH にコピーする形で、man ページは付かず、リリースのたびに取得し直す必要があります
  • ソースからビルド: C++ ツールチェーンに加え、SQLite、PCRE2、ncurses、libarchive、libcurl の開発パッケージ、そして長いコンパイル時間が必要です
  • deb.griffo.io: 最新版を自動更新でお届け
  • ✅ Debian と同じパッケージ名: パッケージ名は Debian のアーカイブと同じ lnav なので、apt upgrade で標準の lnav がその場でアップグレードされ、後で apt remove しても何も残りません
  • ✅ 公式の静的ビルド: 上流自身による musl の静的バイナリなので、実行時の依存関係はまったくなく、どのバージョンでも同じように動作します
  • ✅ 完全なパッケージ: lnav バイナリと man ページ。リモートログ用に openssh-client を推奨し、行のコピー用に wl-clipboard または xclip を提案しています
  • ✅ 自動更新: 上流のリリースから数時間以内にパッケージを更新
  • ✅ 2 つのアーキテクチャ: すべてのバージョンで amd64 と arm64。サーバーでも、ノート PC でも、Raspberry Pi のような ARM ボードでも同じ lnav が動きます
  • ✅ マルチディストリビューション: Bookworm、Trixie、Forky、Sid で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

❓ よくある質問

lnav は公式の Debian リポジトリにありますか？

あります。ただし公式 Debian アーカイブが配布しているのは lnav 0.12.4 で、このリポジトリは上流のリリースから数時間以内に再ビルドした lnav 0.14.1 を配布しています。

Debian に最新の lnav を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install lnav を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Debian のどのリリースに対応していますか？

Debian 12 Bookworm、Debian 13 Trixie、Forky、Sid。
