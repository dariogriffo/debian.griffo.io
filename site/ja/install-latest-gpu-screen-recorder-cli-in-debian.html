GPU Screen Recorder とは

GPU Screen Recorder は、パイプライン全体を GPU 上で完結させるスクリーンレコーダーです。モニター、ウィンドウ、領域、Webカメラのいずれかをキャプチャし、そのフレームを GPU の動画エンコーダー(AMD と Intel では VA-API、NVIDIA では NVENC、または Vulkan video)にそのまま渡すため、60 FPS や 144 FPS でゲームを録画してもフレームレートへの影響はほとんどありません。ファイルへの記録に加え、RTMP、SRT、WHIP でのストリーミング、スクリーンショットの撮影、そして求めた瞬間に直前の数分間を保存する ShadowPlay スタイルのインスタントリプレイバッファにも対応しています。X11 と Wayland の両方で動作し、入力するコマンドは gpu-screen-recorder です。

🚀 最新版であることの意味: Debian 12 と Debian 13 には GPU Screen Recorder がそもそもパッケージ化されておらず、forky と sid に入っている 5.13.8 も 6.x 系より前のバージョンです。このバージョンには gsr-cli も -ipc オプションもないため、実行中のレコーダーはシグナルでしか操作できません。低遅延ストリーミング用の -auth 付き WHIP 出力もなく、-exclude-metadata もありません。今日の上流ドキュメントを前提に書かれたホットキースクリプトやリプレイ設定は、そのすべてを当然のものとして扱います。

⚡ GPU Screen Recorder の主な機能

⏪ インスタントリプレイ

-r 60 でメモリ上に直近 60 秒を保持し(-replay-storage disk でディスク上にも保持可能)、保存はコマンド 1 つで完了します。欲しいと気づく前から録れていたクリップが手に入ります。

🎮 オーバーヘッドほぼゼロ

キャプチャもエンコードも GPU から離れないため、CPU はゲームのために空けておけます。H.264、HEVC、AV1、VP8、VP9 に対応し、HEVC と AV1 は HDR と 10-bit のバリアントもサポートします。

🖥️ X11 と Wayland

モニターを直接、X11 上のウィンドウ、フォーカスされたウィンドウ、slop や slurp で選んだ領域、あるいは Wayland ではデスクトップポータルが提供するものを -w portal で録画できます。

📡 ストリーミング

同じキャプチャを RTMP で Twitch や YouTube に、SRT リスナーに、あるいはサブ秒未満の低遅延を実現する WHIP に送信できます。配信サービスが求める固定ビットレートは -bm cbr で指定します。

🎛️ gsr-cli によるリモート操作

-ipc 付きでレコーダーを起動しておけば、gsr-cli で一時停止、停止、あるいはリプレイバッファの直近 30 秒の保存ができ、保存したファイルのパスも表示されるので、ホットキー化も簡単です。

🔊 オーディオミキシング

デスクトップの出力とマイクを -a "default_output|default_input" でミックスしたり、PipeWire 経由で app:firefox のように単一アプリケーションの音声だけを録音したりできます。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

🧩 extrepo オプションについて。 extrepo は外部リポジトリを扱う Debian 標準のツールです。署名済みメタデータと照合して鍵を検証したうえで、sources ファイルの作成と署名鍵のインストールを代わりに行います。このリポジトリは griffo、ずっと無料のミラーは griffo-free という名前で登録されているので、Debian（bookworm、trixie、forky、sid）では上のコマンドだけで設定は完了です。

extrepo が用意するのは sources ファイルと鍵だけなので、サブスクリプションの認証情報は引き続き /etc/apt/auth.conf.d/deb.griffo.io.conf に書きます。extrepo は Debian のスイート向けメタデータしか公開していないため Ubuntu は対象外です。Ubuntu では sudo または root のコマンドを使ってください。

🎯 基本的な使い方

録画する:

# デスクトップ音声とマイクを 1 つのトラックにミックス
gpu-screen-recorder -w screen -f 60 -a "default_output|default_input" -o video.mp4

# モニターを名前で指定。一覧は --list-monitors
gpu-screen-recorder -w DP-1 -f 144 -k hevc -o video.mp4

# Wayland では slurp、X11 では slop で選んだ領域
gpu-screen-recorder -w region -region $(slurp -f "%wx%h+%x+%y") -o video.mp4

# 右下に Web カメラを重ねた画面
gpu-screen-recorder -w "screen|/dev/video0;halign=end;valign=end;width=30%;height=30%" -o video.mp4

インスタントリプレイ:

# 直近 60 秒を保持。メモリ使用量を予測しやすい固定ビットレートで
gpu-screen-recorder -w screen -c mp4 -r 60 -bm cbr -q 40000 -a default_output \
    -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o ~/Videos

# ホットキーから: バッファ全体、または直近 30 秒だけを保存
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay 30

# -ipc なしでもシグナルは使えます
pkill -SIGUSR1 -f "^gpu-screen-recorder"

ストリーミングとスクリーンショット:

# 固定 8000 kbps で Twitch に配信
gpu-screen-recorder -w screen -c flv -a default_output -bm cbr -q 8000 \
    -o "rtmp://live.twitch.tv/app/$STREAM_KEY"

# ベアラートークンを使った低遅延 WHIP 配信
gpu-screen-recorder -w screen -bm cbr -q 3500 -c whip -auth "$TOKEN" -o https://whip.example.com/api/whip

# スクリーンショットを撮る
gpu-screen-recorder -w screen -o screenshot.png

録画を制御する:

# ソケット経由で制御できる録画を開始
gpu-screen-recorder -w screen -f 60 -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o video.mp4 &

# 状態を確認し、一時停止し、停止してファイルの保存先を表示
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" status
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" set-paused true
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" stop

🔧 ツール連携

GPU Screen Recorder はコマンドラインプログラムなので、ショートカットがコマンドを実行できる場所ならどこにでも組み込めます:

  • デスクトップのホットキー: GNOME、KDE、Sway、Hyprland で gsr-cli save-replay 30 を割り当てれば、ShadowPlay スタイルの「直近 30 秒を保存」キーになります
  • ヘルパースクリプト: 上流のトグル・リプレイ・ストリーミング用スクリプトが /usr/share/gpu-screen-recorder/scripts に同梱されています
  • systemd: 常時オンのリプレイバッファ用ユーザーサービスはインストール済みですが無効化されています。~/.config/gpu-screen-recorder.env を設定してから systemctl --user enable --now gpu-screen-recorder を実行してください
  • OBS 不要の配信: RTMP、SRT、WHIP 出力があれば、別のプログラムなしで Twitch、YouTube、自前サーバーへの配信をカバーできます
  • FFmpeg: -ffmpeg-opts、-ffmpeg-video-opts、-ffmpeg-audio-opts でエンコーダーとマルチプレクサにオプションをそのまま渡せます

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Debian: Debian 12 にも 13 にもパッケージ化されておらず、forky と sid にある 5.13.8 も複数の gpu-screen-recorder-* パッケージに分割されていて、gsr-cli、-ipc、WHIP もありません
  • Flatpak: 最新版で独自のエンコーダーも同梱していますが、実体は GTK インターフェースで、コマンドラインは flatpak run --command=gpu-screen-recorder の裏に隠れており、AMD/Intel でのモニターキャプチャにはシステム全体へのインストールが必要です
  • ソースからビルド: 上流の install.sh は meson と約 20 個の -dev パッケージを必要とし、apt の管理外にインストールされ、リリースのたびに手動で再実行する必要があります
  • deb.griffo.io: 最新版を自動更新でお届け
  • ✅ 各リリース向けにビルド: 各スイート上で、そのスイート自身の FFmpeg に対して上流のタグからコンパイルしているため、システムに既にあるライブラリにリンクされます
  • ✅ パスワード入力不要: gsr-kms-server には上流のインストーラーが設定するのと同じケーパビリティが与えられているため、AMD、Intel、NVIDIA の Wayland でモニターを録画するたびにパスワードを聞かれることはありません
  • ✅ 分割パッケージを置き換え: forky と sid にある Debian の gpu-screen-recorder-cli とその関連パッケージを引き継ぐため、apt は 2 つ目をインストールするのではなくアップグレードとして扱います
  • ✅ 自動更新: 上流のリリースから数時間以内にパッケージを更新
  • ✅ 全部入り: gpu-screen-recorder、gsr-cli、gsr-kms-server、man ページ、プラグインヘッダー、上流のヘルパースクリプト、そして有効化するまで無効なままのユーザーサービス
  • ✅ マルチディストリビューション: Bookworm、Trixie、Forky、Sid の amd64 で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

上流から引き継がれる注意点が 1 つあります。ディストリビューションの FFmpeg では、GTX 1080 世代以前の NVIDIA カードがエンコードできないことがあります。上流の Flatpak と AppImage には、そうしたカード向けにパッチ済みの FFmpeg が同梱されています。

❓ よくある質問

GPU Screen Recorder は公式の Debian リポジトリにありますか？

ありません。GPU Screen Recorder は公式 Debian アーカイブにパッケージ化されていません。現在このリポジトリが唯一の apt ソースで、GPU Screen Recorder 6.1.3 を配布しています。

Debian に最新の GPU Screen Recorder を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install gpu-screen-recorder-cli を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Debian のどのリリースに対応していますか？

Debian 12 Bookworm、Debian 13 Trixie、Forky、Sid。
