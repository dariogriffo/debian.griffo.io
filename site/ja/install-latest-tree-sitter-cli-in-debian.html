tree-sitter-cli とは

tree-sitter-cli は、Tree-sitter パーサーを開発するためのコマンドラインツールです。Tree-sitter はパーサージェネレーターであり、インクリメンタルなパースライブラリでもあります。ソースファイルの具象構文木を作り、編集に合わせて少ないコストで更新するため、Neovim、Helix、Zed、GitHub がハイライト、折りたたみ、テキストオブジェクト、コードナビゲーションに使っています。文法はこの CLI で作られます。文法リポジトリの雛形を作り、grammar.js から C のパーサーを生成し、共有ライブラリや WebAssembly にコンパイルし、コーパステストを走らせ、ファイルのパース・クエリ・ハイライト・タグ付けを行い、Web の playground も立ち上げます。Rust 製の単一バイナリで、入力するコマンドは tree-sitter です。

🚀 最新版であることの意味: 文法は CLI と歩調を合わせて進みます。現行のパーサー ABI、tree-sitter init が書き出す tree-sitter.json の構成、--js-runtime native の裏にある組み込み QuickJS ランタイムは、どれもアーカイブで固定されたバージョンより後に登場しました。現行の CLI で生成した文法リポジトリは、コントリビューター全員のマシンと CI に同じかそれ以降のバージョンを求めます。Debian stable の 0.22.6 も Ubuntu 24.04 の 0.20.8 もその大半より前のもので、上流の Linux バイナリは glibc 2.39 を必要とするため、Debian 12 や Ubuntu 22.04 では起動すらしません。

⚡ tree-sitter-cli の主な機能

🧱 コマンド 1 つで文法リポジトリ

tree-sitter init がいくつか質問し、grammar.js、tree-sitter.json、バインディングとパッケージのファイルを書き出します。文法は初日から Node.js、Python、Rust、Go、Swift、C 向けに公開できます。

⚙️ パーサー生成

tree-sitter generate は grammar.js を src/ 内の依存のない C パーサーに変換し、コンフリクトを報告します。文法の実行には node を使うか、--js-runtime native で組み込みの QuickJS ランタイムを使います。

🔨 ネイティブと WebAssembly のビルド

tree-sitter build はパーサーをエディタが読み込む共有ライブラリにコンパイルし、--wasm は web-tree-sitter と playground 用の .wasm モジュールを出力します。

🧪 コーパステスト

tree-sitter test は test/corpus の例をパースし、期待される S 式と木を比較し、ハイライトとタグのテストも実行します。意図した変更の後は --update で期待値を書き換えます。

🔍 パース・クエリ・ハイライト・タグ

parse は構文木を表示し、query は .scm クエリを実行してキャプチャを一覧にし、highlight はターミナルや HTML に描画し、tags は定義と参照を抽出します。

🛝 Web playground

tree-sitter playground はローカルのページを立ち上げます。コードを打ち込むと編集に合わせて木が更新され、その場でクエリも試せます。ルールがなぜマッチしないのかを知る一番の近道です。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

無料ミラーの仕組み →

🧩 extrepo オプションについて。 extrepo は外部リポジトリを扱う Debian 標準のツールです。署名済みメタデータと照合して鍵を検証したうえで、sources ファイルの作成と署名鍵のインストールを代わりに行います。このリポジトリは griffo、ずっと無料のミラーは griffo-free という名前で登録されているので、Debian（bookworm、trixie、forky、sid）では上のコマンドだけで設定は完了です。

extrepo が用意するのは sources ファイルと鍵だけなので、サブスクリプションの認証情報は引き続き /etc/apt/auth.conf.d/deb.griffo.io.conf に書きます。extrepo は Debian のスイート向けメタデータしか公開していないため Ubuntu は対象外です。Ubuntu では sudo または root のコマンドを使ってください。

🎯 基本的な使い方

文法を開発する:

# grammar.js を変更するたびに再生成。組み込み QuickJS を使えば node は不要
tree-sitter generate --js-runtime native

# 名前が一致するテストだけを実行し、新しい出力を期待値として受け入れる
tree-sitter test --include 'function'
tree-sitter test --update

# 共有ライブラリ、または web-tree-sitter 用の WebAssembly モジュールをビルド
tree-sitter build -o mylang.so
tree-sitter build --wasm

ファイルをパースする:

# ファイルの構文木を表示
tree-sitter parse examples/hello.mylang

# 多数のファイルを静かにパースし、成功した数を報告
tree-sitter parse examples/*.mylang --quiet --stat

# パースの時間を計測。文法の変更で遅くなったときに便利
tree-sitter parse examples/big.mylang --time

クエリ、ハイライト、タグ:

# ファイルにクエリを実行し、キャプチャしたものを一覧表示
tree-sitter query queries/highlights.scm examples/hello.mylang

# ファイルをターミナルでハイライト、または単体の HTML ページに描画
tree-sitter highlight examples/hello.mylang
tree-sitter highlight --html examples/hello.mylang > hello.html

# tags クエリで定義と参照を抽出
tree-sitter tags examples/hello.mylang

既存の文法と playground:

# 既存の文法で作業する
git clone https://github.com/tree-sitter/tree-sitter-json
cd tree-sitter-json
tree-sitter generate && tree-sitter test

# 設定ファイルを作り、parser-directories に文法のチェックアウト先を書く
tree-sitter init-config

# WebAssembly にビルドし、ブラウザで対話型の playground を開く
tree-sitter build --wasm
tree-sitter playground

🔧 ツール連携

Tree-sitter CLI は、文法とそれを読み込むツールの間に位置します:

  • Neovim: nvim-treesitter の main ブランチは tree-sitter CLI でパーサーをコンパイルし、Debian stable や Ubuntu LTS に入っているものより新しいリリースを求めます
  • Helix: ハイライト、インデント、テキストオブジェクトは Tree-sitter クエリです。highlights.scm の変更は、hx --grammar build で文法を再ビルドする前に tree-sitter query で確認できます
  • Zed: 言語拡張は文法リポジトリとコミットを固定するので、固定先を更新する前にローカルで文法を生成・テストします
  • CI: tree-sitter generate の後に git diff --exit-code src/ を実行すれば、コミット済みのパーサーが古いプルリクエストを失敗させられます
  • パッケージレジストリ: tree-sitter init が書き出すバインディングで、同じ文法を npm、PyPI、crates.io に公開できます

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Debian: tree-sitter-cli は入っていますが、Debian 13 は 0.22.6 で、現行の文法が使うパーサー ABI や tree-sitter.json の構成より古く、Debian 12 にはパッケージ自体がありません
  • 上流のバイナリ: 最新ではありますが、上流のビルド済み Linux バイナリは glibc 2.39 にリンクされているため Debian 12 や Ubuntu 22.04 では起動せず、apt の管理外の /usr/local/bin に置くことになります
  • cargo または npm: cargo install tree-sitter-cli には Rust ツールチェーンが必要で、更新のたびにフルビルドになります。npm パッケージは同じビルド済みバイナリをダウンロードするので、glibc の要件も同じです
  • deb.griffo.io: 最新版を自動更新で
  • ✅ 同じパッケージの、新しい版: Debian 自身の tree-sitter-cli と同じ名前で、同じ /usr/bin/tree-sitter に入るので、apt はこれを 2 つ目のインストールではなくアップグレードとして扱います
  • ✅ 上流タグからビルド: 上流のビルド済み Linux バイナリが glibc 2.39 を要求するため、Ubuntu 22.04 上で上流のタグ付きソースから cargo でコンパイルしています。Bookworm と Jammy 以降のすべてのスイートで動作します
  • ✅ 自動更新: 上流のリリースから数時間以内にパッケージを更新
  • ✅ 全部入り: 上流のソースタグからビルドした tree-sitter バイナリに、bash、zsh、fish、nushell の補完。依存は libc6 と libgcc-s1 だけです
  • ✅ 4 つのアーキテクチャ: amd64、arm64、armhf、i386。Raspberry Pi にも古い 32 ビットのノート PC にも同じ tree-sitter を
  • ✅ マルチディストリビューション: Bookworm、Trixie、Forky、Sid で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

❓ よくある質問

tree-sitter-cli は公式の Debian リポジトリにありますか？

あります。ただし公式 Debian アーカイブが配布しているのは tree-sitter-cli 0.22.6 で、このリポジトリは上流のリリースから数時間以内に再ビルドした tree-sitter-cli 0.27.0 を配布しています。

Debian に最新の tree-sitter-cli を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install tree-sitter-cli を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Debian のどのリリースに対応していますか？

Debian 12 Bookworm、Debian 13 Trixie、Forky、Sid。
