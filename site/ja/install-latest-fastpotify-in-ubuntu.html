Fastpotify とは？

Fastpotify は デスクトップ向けのネイティブな Spotify クライアント です。Rust と egui で書かれ、librespot を通して音楽を再生します。プロセスのどこにもブラウザエンジンが入っておらず、そこが肝心です。1 秒をはるかに切って起動し、動作中も軽いままで、公式クライアントがそのどちらもできないマシンでもそうです。それ自体が Spotify Connect デバイスなので、このコンピュータで再生しつつ、アカウント上の他のすべてのデバイスの再生も操作できます。ライブラリはまるごとそこにあります。プレイリスト、お気に入りの曲、保存したアルバム、フォロー中のアーティスト、ポッドキャストとエピソード。加えて検索、アーティスト・アルバム・プレイリストの各ページ、キュー、イコライザ、メディアキー、そしてトレイアイコンも。

🚀 最新バージョンが重要な理由: Fastpotify はまだ若く、週に何度もリリースされるほど速く動いています。しかもその足元では、Spotify の Web API と librespot という二つのものが変わり続けています。Spotify 側の変更でページやログインが壊れても、直るのは今週のリリースであって、先月のビルドではありません。Debian も Ubuntu も Fastpotify をパッケージ化していないため、最新ビルドはここでは贅沢ではなく、apt で導入する唯一の方法です。

⚡ Fastpotify の主な機能

⚡ ネイティブで、しかも小さい

Rust と egui で、GPU に直接描画します。Electron も、埋め込みの Chromium も、WebView もありません。1 秒をはるかに切って開き、メモリ使用量も始めた場所から動きません。だからこそ古いノート PC や Raspberry Pi でも実用になります。

🔊 ひとつの Spotify Connect デバイス

librespot 経由でこの機械で再生します。ギャップレスで最大 320 kbps、音量の正規化とディスク上の音声キャッシュも任意で使えます。スマートフォンからこの機械を選ぶこともできます。デバイス選択でスピーカーや別のコンピュータへ再生を移し、そのままここから操作し続けられます。

📡 LAN 上のスピーカーを見つける

ネットワークで待機している librespot、spotifyd、ハードウェアレシーバは、アカウントが紐づくまで Spotify の API からは見えません。Fastpotify は mDNS でそれらを見つけて代わりに接続します。以後は他の Connect デバイスと同じように扱えます。

📚 ライブラリまるごと

プレイリスト、お気に入りの曲、保存したアルバム、フォロー中のアーティスト、ポッドキャスト、保存したエピソードを、サイドバーで絞り込めます。すべての種類を横断する検索、「あなたのための」と最近再生した項目が並ぶホーム、そしてどの行からでも再生できるアーティスト・アルバム・プレイリスト・ポッドキャストの各ページ。

🎛️ Winamp ミニプレーヤー

Ctrl+M でウィンドウが往年のミニプレーヤーに縮み、本物の .wsz スキンをまといます。1 倍から 4 倍までピクセル単位で描かれ、その下にスペクトラムアナライザ、プレイリスト、10 バンドのイコライザがぶら下がります。MilkDrop のビジュアルは projectM を通して専用ウィンドウで動きます。

🖥️ 本物のデスクトップ統合

D-Bus 上の MPRIS に対応するので、メディアキー、シェル、playerctl から他のプレーヤーと同じように見えます。ウィンドウを閉じても音楽はトレイから鳴り続け、二重に起動しても既存のウィンドウが前に出るだけ。よく使う操作にはすべてショートカットがあります。

🚀 常に公式アーカイブの先を行く: Debian と Ubuntu はリリース時にパッケージのバージョンを凍結します。このリポジトリは新しい上流リリースを通常は数時間以内に公開します。apt upgrade だけで常に最新バージョンを維持できます。

🎯 基本的な使用例

MPRIS 経由でシェルから操作する:

# playerctl は他のプレーヤーと同じように Fastpotify と話せます

# いま何が鳴っているか、ステータスバー向けに

🔧 ツール連携

Fastpotify は、デスクトップにすでにあるものの上に意図的に組み立てられています:

  • PulseAudio と PipeWire: 音声はセッションのサウンドサーバ経由で出力され、その下は ALSA です。パッケージが libpulse0 と libasound2t64 に依存しているのはそのためです
  • D-Bus 上の MPRIS: キーボードのメディアキー、デスクトップの「再生中」ウィジェット、playerctl のいずれもが、他のプレーヤーと同じように操作できます
  • システムトレイ: ステータス通知アイテムなので、ウィンドウを閉じても音楽は鳴り続け、トレイをクリックすれば戻ります。GNOME でも KDE でも、どのタイル型コンポジタでも同じ挙動です
  • Wayland と X11: どちらも、一般的なクライアントライブラリ経由で。パッケージは自前の複製を抱えずにそれらへ依存します
  • Noto フォント: 推奨依存で、中国語・日本語・韓国語・アラビア語・ヘブライ語・タイ語・インド系文字の曲名を豆腐ではなく文字として描くのがこれです

🚀 なぜ deb.griffo.io を選ぶのか？

📊 リポジトリの比較:
  • 公式 Ubuntu: Fastpotify をパッケージ化していないため、素の環境では apt install fastpotify は失敗します
  • cargo install: 最新にはなりますが、マシンごとに libprojectM をソースからビルドするため、先に CMake、C++ コンパイラ、libclang、そして ALSA・PulseAudio・ウィンドウシステムの開発ヘッダが必要です
  • 上流のバイナリ: 自分で置く 1 つのファイルで、パッケージ管理の外にあります。デスクトップエントリもアイコンもなく、依存関係の検査もありません
  • deb.griffo.io: 自動更新付きの最新バージョン
  • ✅ 唯一の apt ソース: Fastpotify は Debian にも Ubuntu のアーカイブにもありません。このリポジトリが公式の上流ビルドをパッケージ化しています
  • ✅ 動きが速い: 週に何度もリリースがあり、ページを壊す Spotify 側の変更も数日のうちに上流で直ります。だから最新でいることに実際の意味があります
  • ✅ 自動更新: 上流リリースの数時間以内にパッケージを更新
  • ✅ 完全なパッケージ: /usr/bin/fastpotify、デスクトップエントリ、アプリアイコン。ほかのアプリと同じようにアプリケーションメニューに並びます
  • ✅ 正直な依存関係: ALSA、PulseAudio、OpenGL、X11、Wayland の実際のライブラリを宣言し、Noto フォントは黙って入れずに推奨依存にとどめています
  • ✅ 2 つのアーキテクチャ: amd64 と arm64。上流が公開している Linux 向けビルドはこれで全部です
  • ✅ マルチディストリビューション: Ubuntu 24.04、25.10、26.04 で動作
  • ✅ 簡単なメンテナンス: 更新は標準の apt コマンドで
ℹ️ Jammy は対象外です。 上流が公開しているバイナリは glibc にリンクされ、glibc 2.39 上でビルドされています。そのためパッケージは libc6 (>= 2.39) を宣言しており、glibc 2.35 の Ubuntu 22.04 にはインストールできるものがありません。Noble、Questing、Resolute はいずれも問題ありません。

❓ よくある質問

Fastpotify は公式の Ubuntu リポジトリにありますか？

ありません。Fastpotify は公式 Ubuntu アーカイブにパッケージ化されていません。現在このリポジトリが唯一の apt ソースで、Fastpotify 0.6.0 を配布しています。

Ubuntu に最新の Fastpotify を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install fastpotify を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Ubuntu のどのリリースに対応していますか？

Ubuntu 22.04 Jammy、24.04 Noble、25.10 Questing、26.04 Resolute。
