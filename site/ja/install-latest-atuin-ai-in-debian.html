Atuin AI とは

Atuin AI は Atuin のシェルエージェントです。Atuin は 18.24 までこれを内蔵していましたが 18.25 で削除し、現在は単体のバイナリ atuin-ai として提供されています。空のプロンプトで ? を押すと、端末の中でそのままチャットが開きます。やりたいことを説明すればコマンドを提案し、質問すれば答えてくれます。許可すれば、Atuin の履歴の検索、ファイルの読み書き、コマンドの実行も行えます。接続先は自分でホストする Atuin AI サーバー（上流が Docker イメージとして公開）で、そのサーバーは OpenAI 互換のエンドポイントなら何でも使えます。Ollama、vLLM、ホスト型の API などです。クライアントは Atuin チームが Rust で書いたもので、MIT ライセンスです。

🚀 最新版が効いてくる理由: Atuin AI は新しく、変化も速いうえに、上流はリリースを一切出さず、main へのコミットだけです。このリポジトリは毎週金曜日、main が動いていればスナップショットをビルドし、<クライアントのバージョン>.<YYYYMMDD>（例: 0.1.0.20261127）という形式でバージョンを付けます。Rust ツールチェーンなしで、apt upgrade がその週の変更を届けます。Debian は atuin-ai をまったくパッケージしていません。

⚡ Atuin AI の主な機能

❓ キー 1 つで

空のプロンプトで ? を押すとエージェントが開きます。それ以外の場所では ? はいつもどおり疑問符を入力するので、入力中のコマンドの邪魔になりません。

💡 コマンドの提案

やりたいことを普通の言葉で説明すれば（「今週変更された 1 GB 超のファイルを探して」）、読んで、直して、実行できるコマンドが返ってきます。man ページを掘り返す必要はありません。

📜 履歴を知っている

許可すれば、エージェントは Atuin の履歴を検索します。先月実行したコマンドを見つけたり、このマシンでのいつものやり方を踏まえたりできます。

🛠️ ファイルとコマンド

ファイルの読み書きやコマンドの実行も代わりに行い、その前に必ず確認します。システムに何をさせるかは自分で決められます。

🏠 自分のサーバー

クライアントは自分で動かす Atuin AI サーバーとやり取りするので、プロンプトや履歴の行き先は自分で決められます。上流はサーバーを ghcr.io/atuinsh/atuin-ai-server として配布しています。

🔌 OpenAI 互換ならどのモデルでも

サーバーは OpenAI 互換のエンドポイントなら何でも使えます。Ollama や vLLM のローカルモデルでも、ホスト型の API でも構いません。モデルの切り替えはサーバー側で行い、クライアントには触れません。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

無料ミラーの仕組み →

🧩 extrepo オプションについて。 extrepo は外部リポジトリを扱う Debian 標準のツールです。署名済みメタデータと照合して鍵を検証したうえで、sources ファイルの作成と署名鍵のインストールを代わりに行います。このリポジトリは griffo、ずっと無料のミラーは griffo-free という名前で登録されているので、Debian（bookworm、trixie、forky、sid）では上のコマンドだけで設定は完了です。

extrepo が用意するのは sources ファイルと鍵だけなので、サブスクリプションの認証情報は引き続き /etc/apt/auth.conf.d/deb.griffo.io.conf に書きます。extrepo は Debian のスイート向けメタデータしか公開していないため Ubuntu は対象外です。Ubuntu では sudo または root のコマンドを使ってください。

ステップ 3: 最初の起動

# クライアントの接続先を自分の Atuin AI サーバーにする
# （コメント付きの例: /usr/share/doc/atuin-ai/examples/ai.example.toml）
mkdir -p ~/.atuin
cat > ~/.atuin/ai.toml <<'EOF'
endpoint = "http://localhost:8080"
# api_token = "..."   # サーバーで AUTH_TOKEN を設定した場合のみ
EOF

# シェルで ? を割り当てる。Atuin 自身の init 行の後に
echo 'eval "$(atuin-ai init bash)"' >> ~/.bashrc

# 新しいシェルを開き、空のプロンプトで ? を押す
exec bash

🎯 基本的な使用例

シェルの設定:

# bash は ~/.bashrc に
eval "$(atuin init bash)"
eval "$(atuin-ai init bash)"

# zsh は ~/.zshrc に
eval "$(atuin init zsh)"
eval "$(atuin-ai init zsh)"

# fish は ~/.config/fish/config.fish に
atuin init fish | source
atuin-ai init fish | source

サーバーの起動:

# パッケージに含まれるのはクライアントだけ。サーバーは上流の Docker イメージ
docker pull ghcr.io/atuinsh/atuin-ai-server

# 上流の Self-Hosting ガイドに従い、OpenAI 互換のエンドポイント（Ollama、vLLM、ホスト型 API）を設定し、
# 応答するか確認する
curl http://localhost:8080/api/cli/models

普段の使い方:

# 空のプロンプトで ? を押して、たとえばこう聞く:
#   ポート 5432 で待ち受けているプロセスは?
#   このディレクトリの 7 日より古い .log ファイルをすべて圧縮して
#   バックアップに使った rsync コマンドは何だった?

# クライアントでできることの一覧
atuin-ai --help

# インストールされるシェルコード
atuin-ai init bash

🔧 ツール連携

Atuin AI は、シェル、Atuin の履歴、そして自分で選んだモデルの間に入ります:

  • Atuin: 必須の依存関係で、deb.griffo.io から一緒にインストールされます。エージェントは atuin search と同じ履歴データベースを、許可したときだけ検索します
  • Atuin 18.25 以降: 18.25 で内蔵エージェントが削除されたため、最新の Atuin で ? チャットを使い続けるにはこのパッケージが必要です
  • bash、zsh、fish: atuin-ai init bash、zsh、fish がキーバインドを出力します。Atuin 自身の init の後に読み込めば、両方のバインドが共存します
  • Atuin AI サーバー: ghcr.io/atuinsh/atuin-ai-server を Docker か Podman で、同じマシンでもクライアントから届く場所ならどこでも動かせます。保護するにはサーバー側で AUTH_TOKEN、~/.atuin/ai.toml で api_token を設定します
  • Ollama と vLLM: サーバーをローカルの OpenAI 互換エンドポイントに向ければ、プロンプトはすべて自分のハードウェアの中に留まります
  • ホスト型 API: OpenAI API を話すプロバイダーならどれも同じように使えます。設定はサーバー側で、クライアントには書きません

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Debian: Atuin AI をパッケージしておらず、素のシステムでは apt install atuin-ai が失敗します
  • upstream のダウンロード: ありません。上流はクライアントのリリースもタグもバイナリも公開していません
  • ソースから cargo build: クローン、Rust ツールチェーン、数分のコンパイルが必要で、main が動くたびに手作業でやり直しです
  • deb.griffo.io: 最新版を自動更新でお届け
  • ✅ 上流の main からビルド: 上流自身の Cargo.lock を使って上流のソースからコンパイル。リリースノートと /usr/share/doc/atuin-ai/changelog.Debian に、各スナップショットの上流コミットが正確に記載されています
  • ✅ Atuin も一緒に: atuin に依存し、それも deb.griffo.io にあるので、apt install atuin-ai 1 回で両方が入ります
  • ✅ クライアントのみ: パッケージがインストールするのは /usr/bin/atuin-ai とサンプルの ai.toml。サーバーは上流が配布しているとおり Docker のままです
  • ✅ 自動更新: 新しいスナップショットはいつもの apt upgrade で届きます
  • ✅ 2 つのアーキテクチャ: amd64 と arm64 を Bookworm、Trixie、Forky、Sid で提供。依存先の Atuin パッケージと同じ 2 つで、i386 と armhf のビルドはありません
  • ✅ マルチディストリビューション: Bookworm、Trixie、Forky、Sid で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

❓ よくある質問

Atuin AI は公式の Debian リポジトリにありますか？

ありません。Atuin AI は公式 Debian アーカイブにパッケージ化されていません。現在このリポジトリが唯一の apt ソースで、Atuin AI 0.1.0.20261125 を配布しています。

Debian に最新の Atuin AI を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install atuin-ai を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Debian のどのリリースに対応していますか？

Debian 12 Bookworm、Debian 13 Trixie、Forky、Sid。
