fresh-editor とは

fresh-editor は、Noam Lewis が Rust で書いたターミナル向けの IDE 兼テキストエディタ Fresh のパッケージです。言語サーバー対応、シンタックスハイライト、マルチカーソル、TypeScript で書けるプラグインシステムといった IDE に期待する機能をターミナルに持ち込みつつ、すぐに使い始められる手軽さを保っています。巨大なファイルも待たずに開け、編集セッションはバックグラウンドのデーモンが保持するので fresh -a で再接続でき、fresh --web で Web ブラウザにエディタを配信することもできます。パッケージ名は fresh-editor、入力するコマンドは fresh です。

🚀 最新版であることの意味: Fresh は若く活発に開発されているプロジェクトで、リリースのたびに言語サーバー連携、プラグイン API、性能の改良が入ります。Debian と Ubuntu の公式アーカイブにはまったく含まれておらず、上流は GitHub のリリースに単体の .deb ファイルを公開していますが apt リポジトリはないため、手動で入れた .deb は自動では更新されません。現在の TypeScript API 向けに書かれたプラグインは、現在のエディタを前提にしています。

⚡ fresh-editor の主な機能

🧠 言語サーバー対応

Fresh は Language Server Protocol に対応しており、診断、補完、定義へのジャンプ、ホバー情報を rust-analyzer、gopls、clangd など他のエディタと同じサーバーから得られます。

🎨 シンタックスハイライト

開いた瞬間からコードがハイライトされます。いつものターミナルのままで、最初のファイルを正しく表示するための別途の設定作業は要りません。

✏️ マルチカーソル

複数の場所に同時にカーソルを置いて一度に入力できます。ブロック内の変数名の変更や、似た行の列をまとめて書き換えるのに便利です。

🧩 TypeScript プラグイン

Fresh はプラグイン用の TypeScript ランタイムを内蔵しています。エディタの拡張は独自の設定言語を覚えることではなく、プラグイン API に対して TypeScript を書くことです。

🔌 生き残るセッション

セッションデーモンが、ターミナルを閉じても SSH 接続が切れても、エディタと開いているファイルを保持します。fresh -a で再接続できます。

🌐 ターミナルでもブラウザでも

fresh --web は同じエディタを Web ブラウザに配信します。ターミナルよりブラウザの方が届きやすいマシンで便利です。

🚀 公式アーカイブより、いつも先へ: Debian と Ubuntu は、リリース時点でパッケージのバージョンを固定します。このリポジトリは上流の新しいリリースを、たいてい数時間以内に公開します。apt upgrade を実行するだけで、常に最新版を使い続けられます。

🔧 ツール連携

Fresh は既存のターミナル中心の作業にそのまま組み込めます:

  • Git: git config --global core.editor fresh でコミットメッセージや対話的 rebase を Fresh で開きます
  • シェル: ~/.bashrc に export EDITOR=fresh を書けば、crontab -e や sudoedit なども Fresh を使います
  • コンパイラと grep: それらが出力する file:line:col を渡すと、その位置でそのまま開きます
  • デスクトップ: パッケージがデスクトップエントリとアイコンを入れるので、Fresh がアプリケーションメニューに表示されます
  • SSH と tmux: セッションデーモンがリモート側で作業を開いたまま保ち、fresh -a で再開できます

🚀 deb.griffo.io を選ぶ理由

📊 リポジトリの比較:
  • 公式 Ubuntu: パッケージなし: Fresh はどの Ubuntu リリースの main にも universe にも含まれていません
  • 上流の .deb: ダウンロードした日には最新ですが、上流は GitHub のリリースに単体の .deb ファイルを公開するだけで apt リポジトリがないため、apt upgrade が新しいバージョンを見つけることはなく、リリースのたびに手動でダウンロードし直すことになります
  • cargo でビルド: Rust ツールチェーンが必要で、アップグレードのたびにフルコンパイルになり、デスクトップエントリ、アイコン、man ページも入りません
  • deb.griffo.io: 最新版を自動更新で
  • ✅ パッケージは fresh-editor、コマンドは fresh: sudo apt install fresh-editor を実行したら fresh を起動します。fresh-editor は上流自身のパッケージ名で、上流の .deb、AUR、Homebrew、winget でも使われています。そのため上流の .deb を入れているマシンも、次のリリースからそのまま置き換えでアップグレードされます
  • ✅ 上流リリースを apt で更新: 上流は .deb ファイルを出しますがリポジトリはありません。ここではすべてのリリースが GPG 署名付きの apt リポジトリに入り、Debian と Ubuntu の各スイート向けにビルドされます
  • ✅ 自動更新: 上流のリリースから数時間以内にパッケージを更新
  • ✅ 完全なパッケージ: fresh バイナリ、アプリケーションメニュー用のデスクトップエントリとアイコン、man ページ fresh(1)
  • ✅ 2 つのアーキテクチャ: amd64 と arm64。ノート PC、サーバー、64 ビット ARM ボードで同じ Fresh が使えます
  • ✅ マルチディストリビューション: Ubuntu 22.04、24.04、25.10、26.04 で動作
  • ✅ 手間のかからない運用: 更新は通常の apt コマンドだけ

❓ よくある質問

fresh-editor は公式の Ubuntu リポジトリにありますか？

ありません。fresh-editor は公式 Ubuntu アーカイブにパッケージ化されていません。現在このリポジトリが唯一の apt ソースで、fresh-editor 0.5.2 を配布しています。

Ubuntu に最新の fresh-editor を入れるには？

上の手順で deb.griffo.io リポジトリを一度追加してから、sudo apt install fresh-editor を実行してください。新しいリリースは、いつもの sudo apt upgrade で届きます。

パッケージは署名されていますか？ どのようにビルドされていますか？

すべてのパッケージはリポジトリの GPG 鍵（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）で署名されており、誰でも中身を確認できる公開の GitHub パッケージングリポジトリで、上流のリリースからビルドされています。

Ubuntu のどのリリースに対応していますか？

Ubuntu 22.04 Jammy、24.04 Noble、25.10 Questing、26.04 Resolute。
