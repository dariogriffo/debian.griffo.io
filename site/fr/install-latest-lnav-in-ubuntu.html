Qu'est-ce que lnav ?

lnav, le Logfile Navigator, est un visualiseur de logs pour le terminal qui fusionne des fichiers de logs de nombreuses sources en une seule vue ordonnée par horodatage. Donnez-lui quelques fichiers, un répertoire ou une archive compressée et il reconnaît seul les formats (syslog, le journal systemd, les logs d'accès Apache et nginx, JSON Lines et bien d'autres), entrelace les messages dans l'ordre chronologique, colore les erreurs et les avertissements pour qu'ils sautent aux yeux, et continue de suivre les fichiers à mesure qu'ils grossissent. À partir de là, vous filtrez, cherchez, sautez d'une erreur à l'autre, et quand une question demande plus qu'une recherche, vous interrogez les messages de log en SQL. Il ouvre les logs distants via ssh aussi facilement que les logs locaux. lnav est écrit en C++ par Tim Stack et distribué sous licence BSD-2-Clause.

🚀 Pourquoi la dernière version compte : lnav gagne sans cesse de nouveaux formats, de nouvelles fonctions SQL et de nouvelles fonctionnalités de visualisation, et chaque version corrige l'analyse de certains logs. Ubuntu 26.04 est figé sur lnav 0.13.2, Noble sur la 0.11.2 et Jammy sur la 0.9.0 : un système de base passe donc à côté de la version actuelle et des formats et corrections qu'elle apporte. Ce dépôt fournit lnav 0.14.1 sous le même nom de paquet, il remplace donc le lnav de la distribution sur place au prochain apt upgrade.

⚡ Fonctionnalités clés de lnav

🔀 Une seule chronologie fusionnée

Ouvrez ensemble le syslog, un log applicatif et un log de serveur web : lnav entrelace leurs lignes par horodatage, et vous lisez ce qui s'est passé dans tout le système dans l'ordre où c'est arrivé.

🔍 Détection automatique des formats

syslog, JSON de journald, logs d'accès Apache et nginx, JSON Lines, logfmt et des dizaines d'autres sont reconnus sans configuration ; niveaux, horodatages et champs sont analysés, erreurs et avertissements mis en évidence.

🗄️ Du SQL sur vos logs

Chaque format reconnu est une table. Appuyez sur ; et lancez des requêtes SELECT sur les messages : compter les erreurs par hôte, trouver les requêtes les plus lentes, regrouper les codes de statut, avec le résultat affiché dans la même fenêtre.

🌐 Logs distants via ssh

lnav user@host:/var/log/syslog ouvre un log sur une autre machine à travers votre configuration ssh et vos clés habituelles, sans agent à installer sur le serveur.

📦 Fichiers compressés et archives

Les logs rotés en .gz et .bz2 s'ouvrent directement, tout comme les archives .zip et .tar : un bundle de support se lit sans le décompresser d'abord.

👀 Suivre, filtrer et chercher

Les fichiers sont suivis à mesure qu'ils grossissent, les filtres masquent ou gardent des lignes selon un motif, les recherches surlignent chaque occurrence, et une seule touche saute à l'erreur ou à l'avertissement suivant, pour que rien d'important ne défile sans être vu.

🚀 Toujours en avance sur les dépôts officiels : Debian et Ubuntu gèlent les versions des paquets à la sortie d'une release. Ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient sur la dernière version.

🎯 Exemples d'utilisation de base

Lire et suivre des logs :

# Les logs rotés et compressés s'ouvrent directement, les archives aussi
lnav /var/log/nginx/access.log.2.gz support-bundle.tar.gz

# Plusieurs sources, fusionnées en une seule chronologie par horodatage
lnav /var/log/nginx/ ~/app/logs/app.log

# Un log sur une autre machine, via votre configuration ssh habituelle
lnav user@host:/var/log/syslog

Filtres et SQL :

# Dans lnav : e / E saute à l'erreur suivante / précédente, w / W aux avertissements
# :filter-in error         garder seulement les lignes qui correspondent
# :filter-out healthcheck  masquer les lignes qui correspondent
# ;SELECT c_ip, count(*) AS hits FROM access_log GROUP BY c_ip ORDER BY hits DESC

# La même requête sans interface, pour les scripts
lnav -n -c ';SELECT sc_status, count(*) FROM access_log GROUP BY sc_status' /var/log/nginx/access.log

🔧 Intégrations

lnav lit tout ce qui produit du texte, depuis des fichiers, des pipes et d'autres machines :

  • ssh : les chemins distants comme user@host:/var/log/syslog passent par votre configuration ssh et vos clés existantes ; le paquet recommande openssh-client pour cela
  • Journal systemd : envoyez journalctl -o json (ajoutez -f pour suivre) dans lnav et chaque champ du journal devient consultable et interrogeable
  • Conteneurs : docker logs -f app 2>&1 | lnav ou kubectl logs -f pod | lnav donne à la sortie des conteneurs la même coloration et le même SQL
  • Presse-papiers : marquez des lignes et appuyez sur c pour les copier ; le paquet suggère wl-clipboard ou xclip pour Wayland et X11
  • Formats personnalisés : décrivez un format de log maison dans un fichier JSON et installez-le avec lnav -i myformat.json ; il obtient alors la détection, la coloration et sa propre table SQL
  • Scripts et CI : lnav -n -c exécute commandes et requêtes sans interface, si bien que le SQL qui répond à une question en interactif peut tourner dans une tâche cron ou un pipeline
  • Documentation : la page de manuel est fournie avec le paquet (man lnav), et le manuel complet se trouve sur docs.lnav.org

❓ Questions fréquentes

lnav est-il dans les dépôts officiels de Ubuntu ?

Oui, mais l'archive officielle de Ubuntu fournit lnav 0.13.2, alors que ce dépôt propose lnav 0.14.1, reconstruit quelques heures après chaque version upstream.

Comment installer le dernier lnav sur Ubuntu ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install lnav. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Ubuntu sont prises en charge ?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing et 26.04 Resolute.
