Qu'est-ce que bottom ?

bottom — la commande s'appelle btm — est un moniteur graphique de processus et de système pour le terminal, écrit en Rust et inspiré de gtop, gotop et htop. Par défaut il se comporte comme un tableau de bord : CPU, mémoire, réseau, disques, températures et processus partagent un seul écran, et chaque widget peut être trié, zoomé ou agrandi à tout le terminal.

🚀 Pourquoi les dernières versions comptent : les archives officielles ont plusieurs versions mineures de retard, et c'est précisément là que les choses intéressantes se sont passées : comptabilisation séparée du cache et des tampons, usage GPU dans le widget mémoire, thèmes de couleurs intégrés, filtrage des threads du noyau et une longue liste de correctifs pour les noyaux et capteurs récents. Un moniteur qui lit mal votre matériel est pire que pas de moniteur : autant le garder à jour.

⚡ Fonctionnalités clés de bottom

📈 Graphiques en direct

CPU (par cœur ou moyenné), mémoire, débit réseau, E/S disque et températures sous forme de graphiques défilants que vous zoomez avec + et -.

🔍 Recherche de processus

/ filtre la table des processus, avec bascules regex, mot entier et casse, et une touche pour trier par CPU, mémoire, PID ou nom.

🌲 Mode arbre

t transforme la table des processus en arbre : le worker qui s'emballe apparaît sous le parent qui l'a lancé au lieu de flotter seul dans la liste.

🎛️ Dispositions personnalisées

Le fichier de configuration décrit lignes, colonnes et proportions des widgets, pour que le tableau de bord affiche les quatre choses que vous surveillez vraiment.

🎨 Thèmes intégrés

--theme gruvbox, nord et leurs variantes claires sont dans le binaire, et chaque couleur se redéfinit dans bottom.toml.

🖥️ Mode basique

btm --basic supprime les graphiques et laisse un relevé numérique compact, lisible sur un lien SSH lent ou dans un petit panneau tmux.

🚀 Toujours en avance sur les archives officielles : Debian et Ubuntu figent les versions des paquets à la sortie d'une release — ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient à jour.

🎯 Exemples d'utilisation de base

Surveillance au quotidien :

# Le tableau de bord complet
btm

# Rafraîchir deux fois par seconde et garder dix minutes d'historique
btm --rate 500ms --retention 10m

# Démarrer sur le widget des processus, déjà agrandi
btm --default_widget_type proc --expanded

# Arbre des processus, groupé, avec les lignes de commande complètes
btm --tree --process_command

Dans le tableau de bord :

# Les touches qui font le travail
#   ?        aide intégrée avec tous les raccourcis
#   e        agrandir le widget sélectionné à tout le terminal
#   f        figer l'affichage le temps de le lire
#   +  -  =  zoomer, dézoomer ou réinitialiser un graphique
#   /        rechercher dans la table des processus
#   c m p n  trier par CPU, mémoire, PID ou nom
#   dd       arrêter le processus sélectionné
#   t        basculer l'arbre des processus

L'adapter à votre machine :

# Fahrenheit, sans ligne CPU moyenne, marqueurs points au lieu de braille
btm --fahrenheit --hide_avg_cpu --dot_marker

# Compter cache et tampons sur leur propre ligne mémoire
btm --enable_cache_memory

# Widget batterie sur un portable
btm --battery

# Un thème de couleurs accordé au reste du terminal
btm --theme gruvbox

🔧 Intégrations avec d'autres outils

bottom est fait pour un environnement centré sur le terminal :

  • Fichier de configuration : ~/.config/bottom/bottom.toml réunit disposition, proportions des widgets, couleurs et vos options habituelles
  • Entrée de bureau : le paquet installe bottom.desktop et son icône : bottom apparaît aussi dans le menu des applications
  • tmux et Zellij : à l'aise dans un panneau étroit ; --basic le garde lisible quand le panneau rétrécit
  • GPU : l'usage NVIDIA et AMD apparaît dans le widget mémoire si les pilotes sont présents, et --disable_gpu coupe la collecte
  • Serveurs : la version amd64 est liée statiquement : un Debian ou Ubuntu nu n'a besoin de rien d'autre que le paquet

🚀 Pourquoi choisir deb.griffo.io ?

📊 Comparatif des dépôts :
  • Debian officiel : fournit btm, mais figé plusieurs versions mineures en arrière : nouveaux widgets, thèmes et correctifs de capteurs n'arrivent qu'à la prochaine release Debian
  • cargo install bottom : à jour, mais compile plusieurs minutes, s'installe hors d'apt et n'apporte ni page de manuel, ni complétions, ni entrée de bureau
  • Archive upstream : le binaire officiel, à retélécharger à la main à chaque version
  • deb.griffo.io : dernière version avec mises à jour automatiques
  • ✅ Widgets à jour : la version la plus récente, avec les widgets, thèmes et correctifs de capteurs ajoutés en amont après le gel de l'archive
  • ✅ Remplacement direct de bottom : le paquet porte le nom de la commande, btm, et déclare Provides/Replaces pour bottom : il se glisse là où était le paquet de l'archive
  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Paquet complet : le binaire upstream plus la page de manuel btm.1, les complétions bash, zsh et fish, l'entrée de bureau et son icône
  • ✅ Cinq architectures : amd64, arm64, armhf, i386 et riscv64 — le même moniteur sur un portable, un Raspberry Pi et une carte RISC-V
  • ✅ Multi-distribution : fonctionne sur Bookworm, Trixie, Forky et Sid
  • ✅ Maintenance simple : des mises à jour avec les commandes apt habituelles

❓ Questions fréquentes

bottom est-il dans les dépôts officiels de Debian ?

Oui, mais l'archive officielle de Debian fournit bottom 0.10.2, alors que ce dépôt propose bottom 0.14.8, reconstruit quelques heures après chaque version upstream.

Comment installer le dernier bottom sur Debian ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install btm. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Debian sont prises en charge ?

Debian 12 Bookworm, Debian 13 Trixie, Forky et Sid.
