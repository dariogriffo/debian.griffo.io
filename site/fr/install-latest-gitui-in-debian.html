Qu'est-ce que GitUI ?

GitUI est une interface terminal pour git, écrite en Rust. Elle offre les parties d'une interface graphique git qui valent vraiment le détour — indexer des hunks et des lignes, lire des diffs, parcourir et chercher dans le log, remiser, blâmer, gérer les branches et pousser — sans quitter le terminal et sans les blocages que connaissent les GUI populaires sur les gros dépôts.

🚀 Pourquoi les dernières versions comptent : GitUI est encore avant la 1.0 et avance vite : gestion des sous-modules, recherche dans le log, blame, meilleur rebase et une longue liste de correctifs sont arrivés dans des versions ordinaires. Ni Debian ni Ubuntu ne l'empaquettent : l'alternative à une version récente n'est pas un paquet plus ancien, c'est aucun paquet.

⚡ Fonctionnalités clés de GitUI

⚡ Rapide sur les dépôts énormes

Le benchmark d'upstream parcourt tout l'historique du noyau Linux en environ 24 secondes avec quelque 170 Mo de mémoire, là où des GUI plus lourdes se figent ou plantent.

✂️ Indexer hunks et lignes

Indexer, désindexer, annuler et réinitialiser des fichiers entiers, des hunks isolés ou des lignes précises — la raison même d'ouvrir une interface git.

📜 Log et diffs

Parcourir et chercher dans le log des commits, inspecter le diff de n'importe lequel et blâmer un fichier ligne à ligne, dans la même interface au clavier.

📦 Remisage

Créer, appliquer, dépiler, supprimer et inspecter les stashes depuis un onglet dédié, plutôt que de retenir quelle sous-commande git stash fait quoi.

🌿 Branches et dépôts distants

Créer, renommer, supprimer et basculer de branche, travailler avec les remotes, pousser ou récupérer sans revenir au shell.

⌨️ Aide contextuelle

? affiche exactement les touches actives dans la vue courante, et key_bindings.ron permet de tout redéfinir — à la vim si c'est votre habitude.

🚀 Toujours en avance sur les archives officielles : Debian et Ubuntu figent les versions des paquets à la sortie d'une release — ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient à jour.

Exécuter les commandes

Étape 1 : ajouter le dépôt

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://deb.griffo.io/EA0F721D231FDD3A0A17B9AC7808B4DD62C41256.asc | sudo gpg --dearmor --yes -o /etc/apt/keyrings/deb.griffo.io.gpg
echo "deb [signed-by=/etc/apt/keyrings/deb.griffo.io.gpg] https://deb.griffo.io/apt $(lsb_release -sc 2>/dev/null) main" | sudo tee /etc/apt/sources.list.d/deb.griffo.io.list > /dev/null
sudo apt update

Comment fonctionne le miroir gratuit →

🧩 À propos de l'option extrepo. extrepo est l'outil de Debian pour les dépôts externes : il écrit le fichier de sources et installe la clé de signature à votre place, après l'avoir vérifiée face à des métadonnées signées. Ce dépôt y est enregistré sous le nom griffo, et le miroir gratuit à vie sous griffo-free ; sur Debian (bookworm, trixie, forky et sid), les commandes ci-dessus constituent donc toute l'installation.

extrepo ne met en place que le fichier de sources et la clé : les identifiants d'un abonnement vont toujours dans /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu n'est pas couvert, car extrepo ne publie de métadonnées que pour les suites Debian : utilisez-y les commandes avec sudo ou en root.

🎯 Exemples d'utilisation de base

Ouvrir des dépôts :

# Le dépôt du répertoire courant
gitui

# Un dépôt précis, sans s'y déplacer
gitui -d ~/src/linux

# Répertoire de travail et répertoire git séparés
gitui -d ~/src/project/.git -w ~/src/project

# Démarrer avec un fichier déjà sélectionné dans l'onglet fichiers
gitui -f src/main.rs

Apparence et confort :

# Un fichier de thème depuis ~/.config/gitui/
gitui -t mytheme.ron

# Un fichier de raccourcis personnalisé
gitui -k ~/.config/gitui/key_bindings.ron

# Des symboles de touches personnalisés, pour un clavier qui les dessine autrement
gitui -s ~/.config/gitui/key_symbols.ron

# Utiliser le watcher du système de fichiers plutôt que des rafraîchissements périodiques
gitui --watcher

Quand il faut diagnostiquer :

# Rassembler les informations d'environnement pour un rapport de bogue
gitui --bugreport

# Écrire un journal en reproduisant un problème
gitui --logging --logfile /tmp/gitui.log

# La CLI git reste là pour ce que GitUI ne couvre pas
git rebase -i origin/main

# Les push HTTPS demandent un credential helper configuré explicitement
git config --global credential.helper store

🔧 Intégrations avec d'autres outils

GitUI s'appuie sur votre installation git existante :

  • Vos dépôts : un dépôt git tout à fait ordinaire, lu et écrit par un backend git en Rust — rien n'y est spécifique à GitUI
  • Hooks : pre-commit, commit-msg, post-commit et prepare-commit-msg s'exécutent comme en ligne de commande
  • Signature GPG : les commits signés fonctionnent, avec les réserves qu'upstream documente dans son gestionnaire de tickets
  • Thèmes et raccourcis : theme.ron, key_bindings.ron et key_symbols.ron dans ~/.config/gitui/
  • En SSH : assez rapide sur une machine distante pour que remettre un commit au propre sur le serveur cesse d'être une corvée ; la version amd64 n'a besoin d'aucune bibliothèque

🚀 Pourquoi choisir deb.griffo.io ?

📊 Comparatif des dépôts :
  • Debian officiel : n'empaquette pas GitUI — apt install gitui échoue sur un système standard
  • cargo install gitui : à jour, mais c'est une longue compilation Rust sur chaque machine, hors d'apt et hors de vos mises à jour
  • Archive upstream : le binaire officiel, à retélécharger à la main à chaque version
  • deb.griffo.io : dernière version avec mises à jour automatiques
  • ✅ Encore avant la 1.0 : GitUI gagne de vraies fonctionnalités dans des versions ordinaires : utiliser la version courante décide si vous avez les sous-modules, la recherche dans le log et le blame, ou non
  • ✅ La seule source apt : GitUI n'est ni dans les archives Debian ni dans celles d'Ubuntu ; ce dépôt empaquette la construction officielle upstream
  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Empaquetage honnête : le binaire upstream dans /usr/bin/gitui — upstream ne fournit ni page de manuel ni complétions, le paquet n'en invente donc aucune
  • ✅ Trois architectures : amd64 (build musl statique), arm64 et armhf, avec les dépendances déclarées là où upstream se lie à la glibc
  • ✅ Multi-distribution : fonctionne sur Bookworm, Trixie, Forky et Sid
  • ✅ Maintenance simple : des mises à jour avec les commandes apt habituelles

❓ Questions fréquentes

GitUI est-il dans les dépôts officiels de Debian ?

Non, GitUI n'est pas empaqueté dans les archives officielles de Debian. Ce dépôt est actuellement la seule source apt et propose GitUI 0.28.1.

Comment installer le dernier GitUI sur Debian ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install gitui. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Debian sont prises en charge ?

Debian 12 Bookworm, Debian 13 Trixie, Forky et Sid.
