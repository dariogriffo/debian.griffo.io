Qu'est-ce que rumdl ?

rumdl est un linter et formateur Markdown écrit en Rust. Il implémente le jeu de règles que tout le monde connaît déjà par markdownlint, les contrôles MD001 à MD059 sur les niveaux de titre, l'indentation des listes, la longueur des lignes, le style des blocs de code, la syntaxe des liens et les espaces en fin de ligne, et il les passe sur une arborescence de documentation en millisecondes plutôt qu'en secondes. La plupart de ces règles ont une correction, si bien que rumdl check --fix répare ce qu'il signale au lieu de vous laisser une liste, et rumdl fmt reformate un fichier de bout en bout. La configuration tient dans un fichier rumdl.toml ou dans une table [tool.rumdl] de pyproject.toml, un .markdownlint.json existant se convertit avec rumdl import, et rumdl server parle le Language Server Protocol : le même binaire souligne donc les problèmes dans votre éditeur. Voyez-le comme ce que Ruff est à Python, appliqué au Markdown.

🚀 Pourquoi la dernière version compte : rumdl ajoute encore des règles, des corrections et des clés de configuration de version en version, et chaque nouvelle règle est un contrôle dont votre documentation ne profite pas tant que vous ne mettez pas à jour. Le comportement des corrections s'affine dans les mêmes versions, si bien qu'un vieux binaire peut réécrire un fichier d'une façon que l'actuel n'emploierait plus, et un rumdl.toml écrit d'après la documentation du jour peut nommer des options qu'une compilation plus ancienne ignore en silence. Ni Debian ni Ubuntu ne l'empaquettent, donc une compilation à jour n'est pas un confort ici : c'est la seule façon de l'avoir via apt.

⚡ Fonctionnalités clés de rumdl

🏎️ Les règles markdownlint à la vitesse de Rust

Les contrôles familiers MD001 à MD059, exécutés par un binaire compilé sans interpréteur à démarrer. Une arborescence de documentation qui occupait une étape de CI à elle seule passe assez vite pour tourner à chaque enregistrement.

🔧 Des corrections, pas seulement des reproches

rumdl check --fix répare les infractions qui ont une correction sûre : ponctuation des titres, marqueurs et indentation des listes, lignes vides autour des blocs, espaces en fin de ligne, style des délimiteurs de code, sur place et sur toute l'arborescence.

🖊️ Un formateur aussi

rumdl fmt reformate le Markdown comme le ferait un formateur de code : la forme d'un fichier cesse d'être un commentaire de revue. --check en fait un garde-fou de CI qui ne modifie rien.

🔌 L'intégration à l'éditeur incluse

rumdl server est un Language Server : VS Code, Neovim, Helix et Zed reçoivent les mêmes diagnostics et les mêmes corrections que la ligne de commande, depuis l'unique binaire installé.

♻️ Votre configuration markdownlint conservée

rumdl import lit un .markdownlint.json ou un .markdownlintrc existant et écrit le rumdl.toml équivalent : basculer un dépôt tient en une commande, pas en un audit des règles.

📖 Des règles qui s'expliquent elles-mêmes

rumdl rule liste tous les contrôles et rumdl explain MD013 en décrit un, avec ce qu'il corrige et comment le configurer : personne n'a plus à deviner ce que voulait dire un code dans un journal de CI.

🚀 Toujours en avance sur les dépôts officiels : Debian et Ubuntu gèlent les versions des paquets à la sortie d'une release. Ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous garde sur la dernière version.

🔧 Intégrations

rumdl est fait pour prendre la place que markdownlint occupe déjà :

  • Votre éditeur : rumdl server est un Language Server, donc Neovim, Helix, VS Code et Zed affichent les diagnostics dans le texte et appliquent les corrections comme actions de code
  • Les configurations markdownlint : rumdl import transforme .markdownlint.json ou .markdownlintrc en rumdl.toml, et les codes de règles sont ceux dont votre équipe débat déjà
  • pyproject.toml : une table [tool.rumdl] garde les réglages à côté de votre configuration Ruff et pytest au lieu d'ajouter un fichier caché de plus
  • CI et pre-commit : rumdl check . sort avec un code non nul en cas d'infraction et rumdl fmt --check verrouille la mise en forme, sans aucun runtime Node ou Python à installer d'abord sur l'agent
  • Générateurs de sites statiques : les sources de MkDocs, Hugo, Docusaurus et mdBook sont du Markdown ordinaire, le même contrôle passe donc dessus avant la construction

❓ Questions fréquentes

rumdl est-il dans les dépôts officiels de Ubuntu ?

Non, rumdl n'est pas empaqueté dans les archives officielles de Ubuntu. Ce dépôt est actuellement la seule source apt et propose rumdl 0.3.0.

Comment installer le dernier rumdl sur Ubuntu ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install rumdl. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Ubuntu sont prises en charge ?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing et 26.04 Resolute.
