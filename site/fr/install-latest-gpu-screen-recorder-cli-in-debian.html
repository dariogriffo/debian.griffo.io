Qu'est-ce que GPU Screen Recorder ?

GPU Screen Recorder est un enregistreur d'écran qui garde tout le pipeline sur le GPU : il capture un moniteur, une fenêtre, une région ou une webcam et transmet les images directement à l'encodeur vidéo du GPU (VA-API sur AMD et Intel, NVENC sur NVIDIA, ou Vulkan video), si bien qu'enregistrer un jeu à 60 ou 144 FPS ne coûte presque rien en fréquence d'images. Il enregistre dans un fichier, diffuse en streaming via RTMP, SRT ou WHIP, prend des captures d'écran, et garde un tampon de relecture instantanée façon ShadowPlay qui sauvegarde les dernières minutes sur demande. Il fonctionne sur X11 et Wayland, et la commande à taper est gpu-screen-recorder.

🚀 Pourquoi les dernières versions comptent : Debian 12 et Debian 13 ne fournissent aucun paquet pour GPU Screen Recorder, et la 5.13.8 de forky et sid précède la série 6.x. Cette version n'a ni gsr-cli ni option -ipc, donc un enregistreur en cours ne peut être piloté que par des signaux ; pas de sortie WHIP avec -auth pour le streaming à faible latence ; et pas de -exclude-metadata. Les scripts de raccourcis et les configurations de relecture écrits d'après la documentation upstream actuelle supposent que tout cela est disponible.

⚡ Fonctions clés de GPU Screen Recorder

⏪ Relecture instantanée

-r 60 garde les 60 dernières secondes en mémoire (ou sur disque avec -replay-storage disk), et les sauvegarder tient en une seule commande : le clip que vous vouliez, enregistré avant même que vous sachiez le vouloir.

🎮 Surcoût quasi nul

La capture et l'encodage ne quittent jamais le GPU, donc le CPU reste disponible pour le jeu. H.264, HEVC, AV1, VP8 et VP9 sont pris en charge, avec des variantes HDR et 10 bits pour HEVC et AV1.

🖥️ X11 et Wayland

Enregistrez un moniteur directement, une fenêtre sur X11, la fenêtre active, une région choisie avec slop ou slurp, ou tout ce qu'offre le portail du bureau avec -w portal sur Wayland.

📡 Streaming

Envoyez la même capture vers Twitch ou YouTube via RTMP, vers un récepteur SRT, ou via WHIP pour une latence inférieure à la seconde, avec -bm cbr pour le débit constant qu'attendent les services de streaming.

🎛️ Contrôle à distance avec gsr-cli

Démarrez l'enregistreur avec -ipc et gsr-cli peut le mettre en pause, l'arrêter, ou sauvegarder les 30 dernières secondes du tampon de relecture, et affiche le chemin du fichier sauvegardé, ce qui rend les raccourcis clavier triviaux.

🔊 Mixage audio

Mixez la sortie audio du bureau et le microphone avec -a "default_output|default_input", ou enregistrez l'audio d'une seule application avec app:firefox via PipeWire.

🚀 Toujours en avance sur les archives officielles : Debian et Ubuntu figent les versions des paquets à la sortie d'une release — ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient à jour.

🧩 À propos de l'option extrepo. extrepo est l'outil de Debian pour les dépôts externes : il écrit le fichier de sources et installe la clé de signature à votre place, après l'avoir vérifiée face à des métadonnées signées. Ce dépôt y est enregistré sous le nom griffo, et le miroir gratuit à vie sous griffo-free ; sur Debian (bookworm, trixie, forky et sid), les commandes ci-dessus constituent donc toute l'installation.

extrepo ne met en place que le fichier de sources et la clé : les identifiants d'un abonnement vont toujours dans /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu n'est pas couvert, car extrepo ne publie de métadonnées que pour les suites Debian : utilisez-y les commandes avec sudo ou en root.

🎯 Exemples d'utilisation de base

Enregistrement :

# Audio du bureau et microphone mixés dans une seule piste
gpu-screen-recorder -w screen -f 60 -a "default_output|default_input" -o video.mp4

# Un seul moniteur par son nom, voir --list-monitors
gpu-screen-recorder -w DP-1 -f 144 -k hevc -o video.mp4

# Une région choisie avec slurp sur Wayland, ou slop sur X11
gpu-screen-recorder -w region -region $(slurp -f "%wx%h+%x+%y") -o video.mp4

# Écran avec la webcam dans le coin inférieur droit
gpu-screen-recorder -w "screen|/dev/video0;halign=end;valign=end;width=30%;height=30%" -o video.mp4

Relecture instantanée :

# Garder les 60 dernières secondes, débit constant pour une utilisation mémoire prévisible
gpu-screen-recorder -w screen -c mp4 -r 60 -bm cbr -q 40000 -a default_output \
    -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o ~/Videos

# Depuis un raccourci clavier : sauvegarder tout le tampon, ou seulement les 30 dernières secondes
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay 30

# Les signaux fonctionnent toujours sans -ipc
pkill -SIGUSR1 -f "^gpu-screen-recorder"

Streaming et captures d'écran :

# Diffuser vers Twitch à un débit constant de 8000 kbps
gpu-screen-recorder -w screen -c flv -a default_output -bm cbr -q 8000 \
    -o "rtmp://live.twitch.tv/app/$STREAM_KEY"

# Flux WHIP à faible latence avec un jeton bearer
gpu-screen-recorder -w screen -bm cbr -q 3500 -c whip -auth "$TOKEN" -o https://whip.example.com/api/whip

# Prendre une capture d'écran
gpu-screen-recorder -w screen -o screenshot.png

Contrôler un enregistrement :

# Démarrer un enregistrement pilotable via un socket
gpu-screen-recorder -w screen -f 60 -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o video.mp4 &

# Le vérifier, le mettre en pause, puis l'arrêter et afficher où le fichier a été sauvegardé
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" status
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" set-paused true
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" stop

🔧 Intégrations avec d'autres outils

GPU Screen Recorder est un programme en ligne de commande, il s'intègre donc partout où un raccourci peut exécuter une commande :

  • Raccourcis du bureau : associez gsr-cli save-replay 30 à une touche dans GNOME, KDE, Sway ou Hyprland pour obtenir une touche « sauvegarder les 30 dernières secondes » façon ShadowPlay
  • Scripts d'aide : les scripts upstream de bascule, de relecture et de streaming sont livrés dans /usr/share/gpu-screen-recorder/scripts
  • systemd : un service utilisateur pour un tampon de relecture toujours actif est installé mais non activé ; configurez ~/.config/gpu-screen-recorder.env, puis systemctl --user enable --now gpu-screen-recorder
  • Streaming sans OBS : les sorties RTMP, SRT et WHIP couvrent Twitch, YouTube et les serveurs auto-hébergés sans second programme
  • FFmpeg : -ffmpeg-opts, -ffmpeg-video-opts et -ffmpeg-audio-opts transmettent des options à l'encodeur et au muxer

🚀 Pourquoi choisir deb.griffo.io ?

📊 Comparatif des dépôts :
  • Debian officiel : non empaqueté dans Debian 12 ou 13 ; forky et sid proposent la 5.13.8, découpée en plusieurs paquets gpu-screen-recorder-* et sans gsr-cli, -ipc ni WHIP
  • Flatpak : à jour et embarque ses propres encodeurs, mais c'est l'interface GTK, la ligne de commande passe par flatpak run --command=gpu-screen-recorder, et la capture d'un moniteur sur AMD/Intel nécessite une installation au niveau du système
  • Compilation depuis les sources : le install.sh d'upstream nécessite meson et une vingtaine de paquets -dev, installe hors d'apt, et doit être relancé à la main à chaque version
  • deb.griffo.io : dernière version avec mises à jour automatiques
  • ✅ Compilé pour chaque version : compilé depuis le tag upstream sur chaque suite avec le FFmpeg propre à cette suite, donc il se lie aux bibliothèques déjà présentes sur votre système
  • ✅ Aucune demande de mot de passe : gsr-kms-server reçoit la capability que définit l'installeur upstream, donc enregistrer un moniteur sur AMD, Intel ou NVIDIA Wayland ne demande pas votre mot de passe à chaque fois
  • ✅ Remplace les paquets scindés : prend le relais du gpu-screen-recorder-cli de Debian et de ses paquets compagnons dans forky et sid, donc apt fait une mise à jour au lieu d'installer une seconde copie
  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Paquet complet : gpu-screen-recorder, gsr-cli, gsr-kms-server, les pages de manuel, l'en-tête de plugin, les scripts d'aide upstream et un service utilisateur qui reste désactivé tant que vous ne l'activez pas
  • ✅ Multi-distribution : fonctionne sur Bookworm, Trixie, Forky et Sid, en amd64
  • ✅ Maintenance simple : des mises à jour avec les commandes apt habituelles

Une réserve hérite d'upstream : avec le FFmpeg de la distribution, les cartes NVIDIA de la génération GTX 1080 et antérieures peuvent ne pas être capables d'encoder. Le Flatpak et l'AppImage d'upstream embarquent un FFmpeg patché pour ces cartes.

❓ Questions fréquentes

GPU Screen Recorder est-il dans les dépôts officiels de Debian ?

Non, GPU Screen Recorder n'est pas empaqueté dans les archives officielles de Debian. Ce dépôt est actuellement la seule source apt et propose GPU Screen Recorder 6.1.3.

Comment installer le dernier GPU Screen Recorder sur Debian ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install gpu-screen-recorder-cli. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Debian sont prises en charge ?

Debian 12 Bookworm, Debian 13 Trixie, Forky et Sid.
