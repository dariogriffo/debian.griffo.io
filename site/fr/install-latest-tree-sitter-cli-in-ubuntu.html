Qu'est-ce que tree-sitter-cli ?

tree-sitter-cli est l'outil en ligne de commande pour développer des parseurs Tree-sitter. Tree-sitter est un générateur de parseurs et une bibliothèque d'analyse incrémentale : il construit l'arbre syntaxique concret d'un fichier source et le met à jour à moindre coût pendant l'édition, ce qui explique pourquoi Neovim, Helix, Zed et GitHub s'en servent pour la coloration, le repliement, les objets textuels et la navigation dans le code. Les grammaires se fabriquent avec cette CLI : elle crée le dépôt d'une grammaire, génère un parseur C à partir de grammar.js, le compile en bibliothèque partagée ou en WebAssembly, lance les tests de corpus, analyse, interroge, colore et étiquette des fichiers, et sert un playground web. C'est un binaire Rust unique, et la commande que vous tapez est tree-sitter.

🚀 Pourquoi les dernières versions comptent : les grammaires suivent la CLI de près : l'ABI actuelle des parseurs, la structure de tree-sitter.json qu'écrit tree-sitter init et le runtime QuickJS intégré derrière --js-runtime native sont tous arrivés après les versions figées dans les archives. Un dépôt de grammaire généré avec une CLI récente attend la même version ou une plus récente sur la machine de chaque contributeur et dans la CI. La 0.22.6 de Debian stable et la 0.20.8 d'Ubuntu 24.04 précèdent l'essentiel de ces changements, et les binaires Linux d'upstream exigent glibc 2.39 : ils ne démarrent même pas sur Debian 12 ni sur Ubuntu 22.04.

⚡ Fonctions clés de tree-sitter-cli

🧱 Un dépôt de grammaire en une commande

tree-sitter init pose quelques questions et écrit grammar.js, tree-sitter.json ainsi que les fichiers de bindings et de paquets : la grammaire est publiable pour Node.js, Python, Rust, Go, Swift et C dès le premier jour.

⚙️ Génération de parseurs

tree-sitter generate transforme grammar.js en un parseur C sans dépendance dans src/ et signale les conflits. La grammaire s'exécute avec node ou, via --js-runtime native, avec le runtime QuickJS intégré.

🔨 Builds natifs et WebAssembly

tree-sitter build compile le parseur en bibliothèque partagée que chargent les éditeurs, et --wasm produit un module .wasm pour web-tree-sitter et le playground.

🧪 Tests de corpus

tree-sitter test analyse les exemples de test/corpus, compare les arbres aux S-expressions attendues et lance aussi les tests de coloration et de tags. --update réécrit les attentes après un changement voulu.

🔍 Analyser, interroger, colorer, étiqueter

parse affiche l'arbre syntaxique, query exécute une requête .scm et liste ses captures, highlight produit une sortie terminal ou HTML, et tags extrait définitions et références.

🛝 Playground web

tree-sitter playground sert une page locale où vous tapez du code, voyez l'arbre se mettre à jour pendant l'édition et lancez des requêtes dessus : le moyen le plus rapide de comprendre pourquoi une règle ne correspond pas.

🚀 Toujours en avance sur les archives officielles : Debian et Ubuntu figent les versions des paquets à la sortie d'une release — ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient à jour.

🎯 Exemples d'utilisation de base

Travailler sur une grammaire :

# Régénérer après chaque modification de grammar.js, sans node, avec le QuickJS intégré
tree-sitter generate --js-runtime native

# Lancer uniquement les tests dont le nom correspond, puis accepter la nouvelle sortie comme attendue
tree-sitter test --include 'function'
tree-sitter test --update

# Compiler une bibliothèque partagée, ou un module WebAssembly pour web-tree-sitter
tree-sitter build -o mylang.so
tree-sitter build --wasm

Analyser des fichiers :

# Afficher l'arbre syntaxique d'un fichier
tree-sitter parse examples/hello.mylang

# Analyser de nombreux fichiers sans bruit et indiquer combien ont réussi
tree-sitter parse examples/*.mylang --quiet --stat

# Chronométrer une analyse, utile quand un changement de grammaire ralentit tout
tree-sitter parse examples/big.mylang --time

Requêtes, coloration et tags :

# Exécuter une requête sur un fichier et lister ce qu'elle capture
tree-sitter query queries/highlights.scm examples/hello.mylang

# Colorer un fichier dans le terminal, ou produire une page HTML autonome
tree-sitter highlight examples/hello.mylang
tree-sitter highlight --html examples/hello.mylang > hello.html

# Extraire définitions et références avec la requête de tags
tree-sitter tags examples/hello.mylang

Grammaires existantes et playground :

# Travailler sur une grammaire existante
git clone https://github.com/tree-sitter/tree-sitter-json
cd tree-sitter-json
tree-sitter generate && tree-sitter test

# Créer un fichier de configuration, puis y lister vos grammaires dans parser-directories
tree-sitter init-config

# Compiler en WebAssembly et ouvrir le playground interactif dans le navigateur
tree-sitter build --wasm
tree-sitter playground

🔧 Intégrations avec d'autres outils

La CLI Tree-sitter se place entre une grammaire et les outils qui la chargent :

  • Neovim : la branche main de nvim-treesitter compile les parseurs avec la CLI tree-sitter et demande une version récente, plus récente que celle de Debian stable ou d'Ubuntu LTS
  • Helix : coloration, indentation et objets textuels sont des requêtes Tree-sitter ; vérifiez une modification de highlights.scm avec tree-sitter query avant de recompiler les grammaires avec hx --grammar build
  • Zed : les extensions de langage épinglent un dépôt de grammaire et un commit, donc générez et testez la grammaire en local avant de mettre à jour l'épinglage
  • CI : tree-sitter generate suivi de git diff --exit-code src/ fait échouer une pull request dont le parseur commité n'est plus à jour
  • Registres de paquets : les bindings qu'écrit tree-sitter init permettent de publier la même grammaire sur npm, PyPI et crates.io

  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Paquet complet : le binaire tree-sitter construit depuis le tag des sources upstream, les complétions bash, zsh, fish et nushell, et aucune dépendance hormis libc6 et libgcc-s1

❓ Questions fréquentes

tree-sitter-cli est-il dans les dépôts officiels de Ubuntu ?

Oui, mais l'archive officielle de Ubuntu fournit tree-sitter-cli 0.25.9, alors que ce dépôt propose tree-sitter-cli 0.27.0, reconstruit quelques heures après chaque version upstream.

Comment installer le dernier tree-sitter-cli sur Ubuntu ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install tree-sitter-cli. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Ubuntu sont prises en charge ?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing et 26.04 Resolute.
