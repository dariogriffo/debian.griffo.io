Qu'est-ce que kitty ?

kitty est un émulateur de terminal basé sur le GPU, pour ceux qui y passent leurs journées. Il rend avec OpenGL, donc un journal de compilation ou un mur de sortie colorée défile sans à-coups, et il traite le terminal comme une plateforme plutôt que comme une boîte de texte : des fenêtres et des onglets disposés par des agencements en mosaïque, un protocole graphique qui dessine de vraies images dans le flux, un protocole clavier qui permet aux programmes de distinguer shift+enter de enter, des hyperliens cliquables, des ligatures, et une intégration au shell qui sait où commence et où finit chaque invite et la sortie de chaque commande. À côté du terminal vient kitten, un unique exécutable compagnon qui réunit les petits outils autour desquels le terminal est construit : kitten icat affiche une image, kitten ssh emporte votre terminfo et votre intégration shell sur un hôte distant, kitten diff est un diff côte à côte qui gère aussi les images, kitten clipboard, kitten themes, et kitten @ pilote le terminal lui-même depuis un script. Il est écrit par Kovid Goyal, l'auteur de calibre, et tout se configure dans un seul kitty.conf.

🚀 Pourquoi la dernière version compte : kitty sort une version à peu près tous les mois, et chacune fait bouger les protocoles sur lesquels d'autres outils s'appuient : le protocole graphique avec lequel dessinent yazi, viu et les plugins d'images de Neovim, le protocole clavier que négocient les éditeurs, le dimensionnement du texte, les hooks d'intégration shell, les commandes de contrôle à distance. Debian trixie est gelée à 0.41.1, et la 0.26.5 de Bookworm est antérieure à l'exécutable kitten autonome, si bien que les commandes kitten ssh et kitten icat de la documentation actuelle n'y existent tout simplement pas. Un vieux kitty ignore aussi en silence les options de kitty.conf que la documentation actuelle vous dit de régler, et chaque kitten récent (choose-fonts, notify, quick-access-terminal, panel) manque purement et simplement. Le terminal est le seul programme que vous utilisez toute la journée ; il devrait être à jour.

⚡ Fonctionnalités clés de kitty

🎮 Rendu par le GPU

kitty dessine avec OpenGL, confie le travail des glyphes au GPU et garde le CPU pour le programme que vous exécutez vraiment. Les grosses sorties défilent à la fréquence de rafraîchissement de l'écran et le terminal reste réactif sous un déluge de texte.

🪟 Fenêtres, onglets et agencements

Découpez un onglet en fenêtres et laissez un agencement (tall, fat, grid, splits, stack) les ranger : ctrl+shift+enter ouvre une fenêtre, ctrl+shift+t un onglet. Un fichier de session recrée tout un espace de travail, chaque fenêtre avec son répertoire et sa commande.

🖼️ Le protocole graphique

De vraies images, pas des caractères en blocs. kitten icat affiche une image dans le flux, et ce même protocole est celui qu'utilisent yazi, viu, les plugins d'images de Neovim et les backends matplotlib quand ils dessinent dans votre terminal.

🐈 Kittens

kitten est un unique exécutable statique rempli de petits outils : icat, ssh, diff, clipboard, themes, hints pour attraper au clavier des URL, des chemins ou des hachages affichés à l'écran, unicode_input, transfer pour copier des fichiers à travers une session ssh, et d'autres encore.

🎛️ Contrôle à distance

Avec allow_remote_control activé, kitten @ pilote le terminal depuis n'importe quel script : ouvrir des fenêtres, leur envoyer du texte, changer les couleurs, redimensionner, lister ce qui tourne. Des agencements scriptés sans multiplexeur entre les deux.

🐚 Intégration au shell

kitty sait où commence chaque invite : sautez d'une invite à l'autre avec ctrl+shift+z, ouvrez la sortie de la dernière commande dans un pager, cliquez pour déplacer le curseur dans la ligne courante, et faites s'ouvrir les nouvelles fenêtres dans le répertoire courant. bash, zsh et fish, fournis par kitty-shell-integration.

🚀 Toujours en avance sur les dépôts officiels : Debian et Ubuntu gèlent les versions des paquets à la sortie d'une release. Ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous garde sur la dernière version.

🧩 À propos de l'option extrepo. extrepo est l'outil de Debian pour les dépôts externes : il écrit le fichier de sources et installe la clé de signature à votre place, après l'avoir vérifiée face à des métadonnées signées. Ce dépôt y est enregistré sous le nom griffo, et le miroir gratuit à vie sous griffo-free ; sur Debian (bookworm, trixie, forky et sid), les commandes ci-dessus constituent donc toute l'installation.

extrepo ne met en place que le fichier de sources et la clé : les identifiants d'un abonnement vont toujours dans /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu n'est pas couvert, car extrepo ne publie de métadonnées que pour les suites Debian : utilisez-y les commandes avec sudo ou en root.

🎯 Exemples d'utilisation de base

Le lancer :

# Un terminal
kitty

# Lancer une commande dans une nouvelle fenêtre kitty et la garder ouverte ensuite
kitty --hold htop

# Surcharger n'importe quelle option de kitty.conf en ligne de commande
kitty -o font_size=14 -o background_opacity=0.9

# Démarrer dans un répertoire
kitty --directory ~/src

# Restaurer tout un espace de travail depuis un fichier de session
kitty --session ~/.config/kitty/work.session

# Quelle version est installée ?
kitty --version

Les kittens :

# Afficher une image directement dans le terminal
kitten icat photo.png

# ssh en emportant terminfo et intégration shell
kitten ssh user@server

# Diff côte à côte, images comprises
kitten diff old.txt new.txt

# Copier vers le presse-papiers du système et y lire
echo hello | kitten clipboard
kitten clipboard --get-clipboard

# Appliquer un thème à toutes les fenêtres kitty ouvertes
kitten themes --reload-in=all Catppuccin-Mocha

# Choisir une police de manière interactive
kitten choose-fonts

Contrôle à distance :

# Mettez allow_remote_control yes dans kitty.conf, puis depuis n'importe
# quel shell lancé dans kitty : ouvrir une nouvelle fenêtre à droite de celle-ci
kitten @ launch --location=vsplit --cwd=current

# Taper une commande dans une autre fenêtre, choisie par son titre
kitten @ send-text --match title:logs "tail -f /var/log/syslog\n"

# Changer les couleurs à la volée
kitten @ set-colors background=#1e1e2e

# Ce qui est ouvert en ce moment
kitten @ ls

🔧 Intégrations

kitty est le terminal sous tout le reste, donc l'intégration concerne surtout ce qui tourne dedans :

  • Serveurs distants : kitty positionne TERM=xterm-kitty, et un hôte sans ce terminfo vous laisse un retour arrière cassé et des plaintes de less et clear. kitten ssh le copie pour vous ; pour les hôtes que vous atteignez avec un simple ssh, installez-y kitty-terminfo, un paquet indépendant de l'architecture qui ne contient que l'entrée terminfo et n'entraîne rien d'autre
  • Votre shell : kitty-shell-integration fournit les hooks bash, zsh et fish sous /usr/share/kitty/shell-integration, et shell_integration enabled dans kitty.conf, la valeur par défaut, les active sans toucher à vos fichiers rc
  • yazi, viu et Neovim : tous trois dessinent les images par le protocole graphique de kitty, et Neovim parle nativement le protocole clavier de kitty : c'est le terminal dans lequel ils ont été testés
  • Zellij et tmux : les fenêtres, onglets et agencements de kitty couvrent l'essentiel de ce que fait un multiplexeur local ; passez à Zellij quand une session doit survivre à la fenêtre, et donnez à tmux extended-keys et le passthrough pour que les protocoles de kitty survivent au trajet
  • Votre bureau : le paquet installe l'entrée de bureau, les icônes et les pages de manuel et enregistre l'alternative x-terminal-emulator, donc kitty apparaît dans votre lanceur et un appel à update-alternatives en fait le terminal par défaut du système

  • deb.griffo.io: dernière version avec mises à jour automatiques
  • ✅ Les mêmes noms de paquets que Debian : kitty, kitty-terminfo, kitty-shell-integration et kitty-doc, exactement comme l'archive Debian les nomme, donc ce dépôt met à jour le kitty d'origine sur place et un apt remove ultérieur ne laisse rien derrière
  • ✅ La construction officielle : le bundle précompilé upstream, les mêmes octets que l'installateur de kitty, placé sous /opt/kitty avec les liens /usr/bin/kitty et /usr/bin/kitten ; pas de compilation, pas de rustine
  • ✅ Bien intégré : entrée de bureau, icônes, pages de manuel, terminfo et intégration shell aux emplacements Debian standard, et l'alternative x-terminal-emulator enregistrée
  • ✅ kitty-terminfo voyage seul : un paquet indépendant de l'architecture qui ne contient que le terminfo xterm-kitty, pour les serveurs où vous vous connectez en ssh
  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Deux architectures : amd64 et arm64, les deux pour lesquelles upstream publie des bundles ; pas de construction i386, armhf ni riscv64
  • ✅ Multi-distribution : fonctionne sur Bookworm, Trixie, Forky et Sid
  • ✅ Maintenance simple : des mises à jour avec les commandes apt habituelles

❓ Questions fréquentes

kitty est-il dans les dépôts officiels de Debian ?

Oui, mais l'archive officielle de Debian fournit kitty 0.41.1, alors que ce dépôt propose kitty 0.49.2, reconstruit quelques heures après chaque version upstream.

Comment installer le dernier kitty sur Debian ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install kitty. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Debian sont prises en charge ?

Debian 12 Bookworm, Debian 13 Trixie, Forky et Sid.
