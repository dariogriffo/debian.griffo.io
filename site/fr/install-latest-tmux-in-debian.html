Qu'est-ce que tmux ?

tmux est le multiplexeur de terminal : il fait tourner plusieurs shells dans un seul terminal, répartis en fenêtres et en panneaux, et les garde actifs après votre déconnexion. Une session tmux vit dans un processus serveur, pas dans votre fenêtre de terminal : vous pouvez vous en détacher, fermer la fenêtre ou perdre la connexion ssh, puis vous y rattacher plus tard avec chaque programme toujours en cours, exactement là où vous l'aviez laissé. Dans une session, vous ouvrez des fenêtres comme des onglets, divisez chacune en panneaux côte à côte ou superposés, remontez l'historique et copiez du texte au clavier, et pilotez le tout depuis un fichier de configuration ou des scripts. tmux est écrit en C, lancé par Nicholas Marriott, et distribué sous licence ISC.

🚀 Pourquoi la dernière version compte : tmux ne cesse d'étendre ce qu'un terminal sait faire : tmux 3.8 a apporté les panneaux flottants et modaux, et chaque version ajoute des options et corrige la gestion du terminal. Debian trixie fournit tmux 3.5a, figé pour toute la durée de vie de la release : un système de base passe donc à côté de tout ce qui est sorti depuis. Ce dépôt fournit tmux 3.8 sous le même nom de paquet, il remplace donc le tmux de la distribution sur place au prochain apt upgrade.

⚡ Fonctionnalités clés de tmux

🔌 Se détacher et se rattacher

Lancez une longue compilation ou un processus serveur dans tmux, détachez-vous, déconnectez-vous ou perdez le réseau, puis rattachez-vous depuis n'importe où : la session et tout ce qu'elle contient ont continué de tourner pendant votre absence.

🪟 Fenêtres et panneaux

Chaque session contient des fenêtres comme des onglets, et chaque fenêtre se divise en panneaux : un éditeur, un shell et un suivi de log partagent un seul écran. Les panneaux se redimensionnent, s'agrandissent en plein écran et se réorganisent en quelques touches.

🎈 Panneaux flottants et modaux

tmux 3.8 ajoute des panneaux flottants qui se placent au-dessus de la disposition et des panneaux modaux qui occupent la fenêtre jusqu'à ce que vous les fermiez, pour une commande rapide ou un sélecteur sans déranger vos divisions.

📋 Mode copie et presse-papiers

Remontez l'historique d'un panneau, cherchez-y et sélectionnez du texte avec les touches de vi ou d'emacs. Le texte copié atteint le presse-papiers de votre bureau via OSC 52, même depuis un tmux qui tourne sur un serveur distant.

🖼️ Des images dans le terminal

Ce build active la prise en charge de sixel : les programmes qui dessinent des images sixel les affichent dans un panneau tmux quand votre terminal prend lui aussi en charge sixel.

🧰 Scriptable et configurable

Chaque action est une commande : associez-la à une touche dans ~/.tmux.conf, ou lancez-la depuis un script shell pour construire toute une disposition de session d'un coup. Les gestionnaires de plugins et les outils de session reposent précisément là-dessus.

🚀 Toujours en avance sur les dépôts officiels : Debian et Ubuntu gèlent les versions des paquets à la sortie d'une release. Ce dépôt publie les nouvelles versions upstream généralement en quelques heures. Un simple apt upgrade vous maintient sur la dernière version.

🧩 À propos de l'option extrepo. extrepo est l'outil de Debian pour les dépôts externes : il écrit le fichier de sources et installe la clé de signature à votre place, après l'avoir vérifiée face à des métadonnées signées. Ce dépôt y est enregistré sous le nom griffo, et le miroir gratuit à vie sous griffo-free ; sur Debian (bookworm, trixie, forky et sid), les commandes ci-dessus constituent donc toute l'installation.

extrepo ne met en place que le fichier de sources et la clé : les identifiants d'un abonnement vont toujours dans /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu n'est pas couvert, car extrepo ne publie de métadonnées que pour les suites Debian : utilisez-y les commandes avec sudo ou en root.

🎯 Exemples d'utilisation de base

Sessions, fenêtres et panneaux :

# Lister les sessions en cours
tmux ls

# Dans tmux, le préfixe est Ctrl-b, suivi de :
# c  nouvelle fenêtre          n / p   fenêtre suivante / précédente
# %  diviser gauche/droite     "       diviser haut/bas
# flèches  passer d'un panneau à l'autre   z  agrandir le panneau courant
# [  mode copie, pour remonter l'historique et sélectionner du texte
# d  se détacher

Scripter une disposition :

# Une session détachée avec un éditeur à gauche et un shell à droite
tmux new-session -d -s dev -n code
tmux split-window -h -t dev:code
tmux send-keys -t dev:code.0 'nvim' Enter
tmux attach -t dev

# Recharger votre configuration sans rien redémarrer
tmux source-file ~/.tmux.conf

Rester à jour :

# tmux se met à jour avec le reste du système
sudo apt update && sudo apt upgrade

# Quelle version est installée, et quelle est la plus récente disponible
apt policy tmux

# Les sessions ouvertes gardent l'ancien serveur ; quittez-les ou arrêtez-le pour basculer
tmux kill-server
# tmux se met à jour avec le reste du système
apt update && apt upgrade

# Quelle version est installée, et quelle est la plus récente disponible
apt policy tmux

🔧 Intégrations

Comme le paquet s'appelle tmux, tout ce qui repose sur tmux continue de fonctionner après la mise à jour :

  • ssh : lancez tmux sur le serveur, pas sur votre portable, et une connexion coupée ne fait que vous détacher ; ssh -t host tmux attach reprend la session
  • Plugins : tmux-plugin-manager (tpm) et les plugins qu'il installe se chargent depuis ~/.tmux.conf exactement comme avant
  • Outils de session : tmuxinator et byobu pilotent la commande tmux, ils profitent donc de la nouvelle version sans rien reconfigurer
  • Presse-papiers : avec OSC 52, le texte copié en mode copie atteint le presse-papiers du terminal devant lequel vous êtes assis, même à travers ssh
  • Fonctionnalités du terminal : ncurses 6.6 est lié statiquement, si bien que le presse-papiers, la couleur et la forme du curseur et les soulignements stylés se comportent de la même façon sur chaque version prise en charge
  • systemd : compilé avec la prise en charge de systemd, comme le paquet propre à Debian, et ses sockets dans /tmp sont protégés du nettoyage de systemd-tmpfiles de la même manière
  • Documentation : le wiki de tmux sur github.com/tmux/tmux/wiki couvre la prise en main, la FAQ et chaque option

📊 Comparaison des dépôts :
  • Debian officiel : fournit tmux 3.5a dans trixie, figé pour toute la durée de vie de sa release
  • Téléchargements upstream : tmux ne publie que les sources, il n'existe donc aucun binaire prêt à télécharger, quelle que soit la version
  • Compiler depuis les sources : une toolchain C plus les paquets de développement de libevent et ncurses, un configure et un make à chaque version, et rien pour le mettre à jour à votre place
  • deb.griffo.io: dernière version avec mises à jour automatiques
  • ✅ Le même nom de paquet que Debian : le paquet s'appelle tmux, exactement comme dans l'archive Debian, ce dépôt met donc à jour le tmux d'origine sur place lors d'un apt upgrade
  • ✅ Compilé à partir de chaque version taguée : construit depuis l'archive de la release avec la prise en charge de systemd, jemalloc et des images sixel activée, comme le build propre à Debian, et enregistré dans /etc/shells
  • ✅ Sid prend le plus récent des deux : les versions d'ici se terminent par ~griffo, donc quand l'archive de Sid a construit la même version de tmux, son paquet passe devant celui-ci et apt le choisit de lui-même
  • ✅ Mises à jour automatiques : les paquets sont mis à jour quelques heures après chaque version upstream
  • ✅ Deux architectures : amd64 et arm64 sur chaque version, le même tmux tourne donc sur les serveurs, les portables et les cartes ARM comme le Raspberry Pi
  • ✅ Multi-distribution : fonctionne sur Bookworm, Trixie, Forky et Sid
  • ✅ Maintenance simple : des mises à jour avec les commandes apt habituelles

❓ Questions fréquentes

tmux est-il dans les dépôts officiels de Debian ?

Oui, mais l'archive officielle de Debian fournit tmux 3.5a, alors que ce dépôt propose tmux 3.8, reconstruit quelques heures après chaque version upstream.

Comment installer le dernier tmux sur Debian ?

Ajoutez le dépôt deb.griffo.io une seule fois (instructions ci-dessus), puis exécutez : sudo apt install tmux. Les nouvelles versions arrivent via le sudo apt upgrade habituel.

Les paquets sont-ils signés et comment sont-ils construits ?

Chaque paquet est signé avec la clé GPG du dépôt (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) et construit à partir des versions upstream dans des dépôts GitHub publics que chacun peut inspecter.

Quelles versions de Debian sont prises en charge ?

Debian 12 Bookworm, Debian 13 Trixie, Forky et Sid.
