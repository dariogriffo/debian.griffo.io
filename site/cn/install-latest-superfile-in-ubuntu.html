什么是 superfile？

superfile 是一个围绕常开面板设计的终端文件管理器。多个目录并排显示，侧边栏放着家目录快捷方式、置顶文件夹和已挂载的磁盘，预览面板会画出光标当前所在的内容：带语法高亮的源码、纯文本、目录列表，或者一张图片。复制、移动和压缩都在后台进行，并在进程栏里汇报进度，因此大文件传输永远不会卡住你正在浏览的面板。删掉的文件会进回收站，可以再取回来；压缩包就地解压和创建；每一个按键、颜色、边框字符和面板宽度都是 TOML 文件里的一行。它是一个静态链接的 Go 二进制文件，而你敲的命令叫 spf。

🚀 为什么最新版本很重要： superfile 仍在一个版本接一个版本地补齐核心功能：元数据面板、可重排的侧边栏分区、文件面板的额外列、自然排序、翻页滚动、> 提示符，以及还在变长的插件列表。这些功能都会带来 config.toml 和 hotkeys.toml 里的新配置项，而旧的二进制文件会默默忽略当前文档让你设置的那些选项。Debian 和 Ubuntu 根本没有收录 superfile，所以最新构建在这里不是锦上添花，而是通过 apt 获得它的唯一途径。

⚡ superfile 的主要功能

🪟 面板，而不是一个目录

n 再开一个文件面板，tab 在面板之间切换，每个面板有自己的路径、排序和选中项。在两棵目录树之间复制，从此是两次按键，而不是两条长路径。

👀 跟着光标走的预览

侧边面板会随着你移动渲染选中的文件：由内置 chroma 或 bat 高亮的源码、目录内容，以及在支持绘图的终端里显示的图片。想要宽度时，f 就能把它收起来。

♻️ 可以反悔的删除

ctrl+d 把文件送进回收站而不是销毁，按错一下还有救。D 是单独且明确的永久删除，留给你真的想这么做的时候。

📊 长任务有进程栏

复制、移动和压缩作为受跟踪的后台任务运行，各有各的进度，列在 p 打开的进程面板里。几个 GB 在搬家的时候，文件面板照样能用。

🗜️ 搜索、跳转、压缩、解压

/ 边打字边过滤当前目录，装了 zoxide 时 z 把跳转交给它，ctrl+a 压缩选中项，ctrl+e 就地解压一个压缩包。

🎨 由你来配置

一个 config.toml 和一个 hotkeys.toml：每个按键都能重新绑定，默认配置旁边还附带一套 Vim 键位；主题是你可以自己写的文件；侧边栏宽度、边框字符、默认排序和预览宽度全都是设置项。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🎯 基本用法示例

启动它：

# 当前目录
spf

# 你指定的目录
spf /var/log

# 每个路径一个面板，并排打开
spf ~/src ~/Downloads /mnt/backup

# 试配置而不动你自己的文件
spf --config-file /tmp/spf.toml --hotkey-file /tmp/spf-keys.toml

# 装的是哪个版本？
spf --version

让配置保持最新：

# 补上新版本带来的配置项和快捷键，
# 你已经改过的内容一律不动
spf --fix-config-file
spf --fix-hotkeys

# 打印 superfile 用到的所有路径
spf path-list

# 提交问题报告时用的环境、终端和版本信息
spf --debug-info

接进你的 shell：

# 在 config.toml 里设置 cd_on_quit = true，再把下面这段
# 放进 ~/.bashrc 或 ~/.zshrc，这样用 Q 退出时，你就会停在
# 面板最后显示的那个目录里
spf() {
    export SPF_LAST_DIR="${XDG_STATE_HOME:-$HOME/.local/state}/superfile/lastdir"
    command spf "$@"
    [ ! -f "$SPF_LAST_DIR" ] || { . "$SPF_LAST_DIR"; rm -f -- "$SPF_LAST_DIR"; }
}

# 这个函数读取的路径
spf path-list --lastdir-file

# 把 superfile 当作别的程序的文件选择器：它会把选中的路径
# 写进这个文件然后退出
spf --chooser-file /tmp/picked

🔧 工具集成

superfile 刻意把专门的活儿留给你已经在用的工具：

  • 你的编辑器： e 用 $EDITOR 打开选中的文件，E 用 dir_editor 打开目录，编辑器还是 Neovim 或 Helix，superfile 只负责浏览
  • zoxide： 设置 zoxide_support = true，z 键就会用你 shell 攒了几个月的同一个数据库来跳转
  • exiftool： 装上 libimage-exiftool-perl 并设置 metadata = true 后，元数据面板会显示完整的 EXIF 和媒体字段，而不只是基础信息
  • bat 与 chroma： 预览由内置的 chroma 高亮，如果你更喜欢 bat 的主题，设置 code_previewer = "bat" 即可
  • 你的终端和 shell： 图片预览走终端自己的图像协议，xdg-open 处理你没有在 [open_with] 里映射的文件类型，cd_on_quit 则把最后所在的目录交回给 bash、zsh 或 fish

🚀 为什么选择 deb.griffo.io？

📊 仓库对比：
  • 官方 Ubuntu： 没有收录 superfile，标准系统上 apt install superfile 会失败
  • 自己从源码构建： 版本够新，但每台机器都要一套 Go 工具链，而且留下一个 apt 完全不知道的二进制文件
  • 上游的安装脚本： 从 superfile.dev 拉一条 curl，很方便，但它绕过包管理器往系统里写文件，之后二进制文件还会自己提醒你更新
  • deb.griffo.io: 最新版本，并自动更新
  • ✅ 唯一的 apt 来源： Debian 与 Ubuntu 官方源都没有 superfile；本仓库打包官方上游发布版
  • ✅ 命令是 spf： 软件包叫 superfile 是因为上游项目就叫这个名字，而它装进 PATH 的是 /usr/bin/spf，也就是所有教程和快捷键文档里用的那条命令
  • ✅ 自动更新： 上游发布后数小时内更新软件包，所以 auto_check_update 可以关掉，检查交给 apt
  • ✅ 完整的软件包： 官方上游的 Linux 构建，安装为 /usr/bin/spf，不加料、不打补丁
  • ✅ 诚实的依赖： 二进制文件本身什么都不需要，xdg-utils 只是推荐，exiftool、zoxide、ffmpeg、poppler-utils 和剪贴板工具则作为建议，供用到它们的可选功能使用
  • ✅ 两种架构： amd64 和 arm64，都是静态链接的 Go 二进制文件，同一个包在所有版本上都能运行
  • ✅ 多发行版： 支持 Ubuntu 22.04、24.04、25.10 和 26.04
  • ✅ 易于维护： 使用标准 apt 命令即可更新
