什么是 tmux？

tmux 是终端复用器：它在一个终端里运行多个 shell，把它们分成窗口和窗格，并在你断开连接后让它们继续运行。tmux 会话运行在一个服务器进程中，而不是你的终端窗口里，因此你可以从会话中分离、关闭窗口或者丢失 ssh 连接，之后再重新连接，所有程序都还在你离开时的位置照常运行。在会话里，你可以像标签页一样打开窗口，把每个窗口左右或上下拆分成多个窗格，用键盘向后滚动并复制文本，并通过配置文件或脚本控制这一切。tmux 用 C 编写，由 Nicholas Marriott 发起，采用 ISC 许可证。

🚀 为什么最新版本很重要： tmux 不断扩展终端能做的事：tmux 3.8 带来了浮动窗格和模态窗格，每个版本都会增加新选项并改进终端处理。Debian trixie 提供 tmux 3.5a，在整个版本生命周期内保持冻结，所以默认系统会错过此后发布的所有内容。本仓库以相同的软件包名提供 tmux 3.8，因此下一次 apt upgrade 时就会原地替换发行版自带的 tmux。

⚡ tmux 的主要功能

🔌 分离与重新连接

在 tmux 中启动一个漫长的构建或服务器进程，分离会话，注销或断网，之后从任何地方重新连接：你离开期间，会话及其中的一切都在继续运行。

🪟 窗口与窗格

每个会话像标签页一样包含多个窗口，每个窗口又可以拆分成窗格，让编辑器、shell 和日志跟踪共享同一个屏幕。只需几个按键，窗格就能调整大小、放大到全屏或重新排列。

🎈 浮动窗格与模态窗格

tmux 3.8 新增了悬浮在布局之上的浮动窗格，以及在你关闭之前占据整个窗口的模态窗格，适合快速执行一条命令或打开一个选择器，而不打乱你的拆分布局。

📋 复制模式与剪贴板

向后滚动窗格的历史记录、在其中搜索，并用 vi 或 emacs 按键选择文本。复制的文本通过 OSC 52 到达你桌面的剪贴板，即使 tmux 运行在远程服务器上也一样。

🖼️ 终端中的图像

此构建启用了 sixel 支持，因此只要你的终端也支持 sixel，绘制 sixel 图像的程序就能在 tmux 窗格中显示图像。

🧰 可脚本化、可配置

每个操作都是一条命令：在 ~/.tmux.conf 中把它绑定到按键上，或者在 shell 脚本中运行它，一次性搭建出整个会话布局。插件管理器和会话工具正是建立在这一点之上。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🎯 基本用法示例

会话、窗口和窗格：

# 列出正在运行的会话
tmux ls

# 在 tmux 中，前缀键是 Ctrl-b，之后按：
# c  新建窗口            n / p   下一个 / 上一个窗口
# %  左右拆分            "       上下拆分
# 方向键  在窗格间移动   z  放大当前窗格
# [  复制模式，用于向后滚动和选择文本
# d  分离

用脚本搭建布局：

# 一个已分离的会话，左边是编辑器，右边是 shell
tmux new-session -d -s dev -n code
tmux split-window -h -t dev:code
tmux send-keys -t dev:code.0 'nvim' Enter
tmux attach -t dev

# 无需重启任何东西即可重新加载配置
tmux source-file ~/.tmux.conf

🔧 工具集成

由于软件包名为 tmux，所有基于 tmux 的工具在升级后都能继续正常工作：

  • ssh：在服务器上而不是在笔记本上运行 tmux，连接断开只会让你与会话分离；ssh -t host tmux attach 即可重新接上会话
  • 插件：tmux-plugin-manager (tpm) 及其安装的插件会像以前一样从 ~/.tmux.conf 加载
  • 会话工具：tmuxinator 和 byobu 调用的是 tmux 命令，因此无需任何重新配置就能用上新版本
  • 剪贴板：借助 OSC 52，在复制模式中复制的文本会到达你面前那台终端的剪贴板，即使经过 ssh 也一样
  • 终端特性：静态链接 ncurses 6.6，因此剪贴板、光标颜色和样式以及带样式的下划线在每个受支持的版本上表现都一样
  • systemd：与 Debian 自己的软件包一样启用了 systemd 支持，并以同样的方式保护其位于 /tmp 中的套接字不被 systemd-tmpfiles 清理
  • 文档：tmux wiki 位于 github.com/tmux/tmux/wiki，涵盖入门、常见问题以及每一个选项

🚀 为什么选择 deb.griffo.io？

📊 仓库对比：
  • 官方 Debian： trixie 提供 tmux 3.5a，在整个版本生命周期内保持冻结
  • 上游下载：tmux 只发布源代码，因此任何版本都没有现成的二进制文件可供下载
  • 从源码构建：需要 C 工具链以及 libevent 和 ncurses 的开发包，每个版本都要运行一次 configure 和 make，而且没有任何东西会替你更新
  • deb.griffo.io: 最新版本，并自动更新
  • ✅ 与 Debian 相同的软件包名：软件包名为 tmux，与 Debian 官方仓库中的名称完全一致，因此本仓库会在 apt upgrade 时原地升级自带的 tmux
  • ✅ 基于每个打了标签的版本构建：从发布的源码包编译，启用了 systemd、jemalloc 和 sixel 图像支持，与 Debian 自己的构建一样，并注册到 /etc/shells
  • ✅ Sid 会选用两者中较新的那个：这里的版本号以 ~griffo 结尾，因此当 Sid 的软件源已经构建了同一个 tmux 版本时，它的软件包排序高于本仓库的软件包，apt 会自动选择它
  • ✅ 自动更新： 上游发布后数小时内更新软件包
  • ✅ 两种架构： 每个版本都提供 amd64 和 arm64，同一个 tmux 可以运行在服务器、笔记本以及树莓派这样的 ARM 开发板上
  • ✅ 多发行版： 支持 Bookworm、Trixie、Forky 和 Sid
  • ✅ 易于维护： 使用标准 apt 命令即可更新

tmux 在官方 Debian 软件源中吗？

在，但官方 Debian 源只提供 tmux 3.5a，而本仓库提供 tmux 3.8，每次上游发布后数小时内重新构建。

如何在 Debian 上安装最新版 tmux？

按上方说明一次性添加 deb.griffo.io 仓库，然后运行：sudo apt install tmux。之后通过常规的 sudo apt upgrade 获取新版本。

软件包是否有签名？如何构建？

每个软件包都使用仓库的 GPG 密钥（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）签名，并基于上游发布在公开的 GitHub 仓库中构建，任何人都可以审查。
