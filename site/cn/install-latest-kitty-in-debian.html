什么是 kitty？

kitty 是一个为整天泡在终端里的人准备的、基于 GPU 的终端模拟器。它用 OpenGL 渲染，所以构建日志或者满屏彩色输出都能流畅滚动；它把终端当作平台而不是文本框：由平铺布局排列的窗口和标签页、能在输出里直接绘制真实图片的图形协议、让程序分得清 shift+enter 和 enter 的键盘协议、可点击的超链接、连字，以及知道每个提示符和每条命令的输出从哪开始到哪结束的 shell 集成。终端旁边还有 kitten，一个把终端赖以构建的小工具装在一起的单一伴生可执行文件：kitten icat 显示图片，kitten ssh 把你的 terminfo 和 shell 集成带到远程主机，kitten diff 是连图片也能比的并排 diff，还有 kitten clipboard、kitten themes，以及从脚本里操控终端本身的 kitten @。作者是 calibre 的作者 Kovid Goyal，所有配置都在一个 kitty.conf 里。

🚀 为什么最新版本很重要： kitty 大约每月发布一版，每一版都会推进其他工具所依赖的协议：yazi、viu 和 Neovim 图片插件绘图用的图形协议、编辑器协商的键盘协议、文本尺寸、shell 集成钩子、远程控制命令。Debian trixie 冻结在 0.41.1，而 Bookworm 的 0.26.5 比独立的 kitten 可执行文件还要早，所以当前文档里的 kitten ssh 和 kitten icat 命令在那里根本不存在。旧版 kitty 还会默默忽略当前文档让你设置的 kitty.conf 选项，新的 kitten（choose-fonts、notify、quick-access-terminal、panel）也一概没有。终端是你唯一整天都在用的程序，它应该是最新的。

⚡ kitty 的主要功能

🎮 GPU 渲染

kitty 用 OpenGL 绘制，把字形的活交给 GPU，CPU 留给你真正在跑的程序。大量输出以显示器的刷新率滚动，哪怕被文本淹没，终端也照样响应。

🪟 窗口、标签页和布局

把一个标签页拆成多个窗口，让布局（tall、fat、grid、splits、stack）来排列它们：ctrl+shift+enter 开窗口，ctrl+shift+t 开标签页。一个会话文件就能重建整个工作区，每个窗口带着自己的目录和命令。

🖼️ 图形协议

真正的图片，不是方块字符。kitten icat 把图片直接显示在输出里，yazi、viu、Neovim 的图片插件和 matplotlib 后端在你终端里作画时用的也是同一个协议。

🐈 Kittens

kitten 是一个装满小工具的静态可执行文件：icat、ssh、diff、clipboard、themes、用键盘从屏幕上挑出 URL、路径或哈希的 hints、unicode_input、通过 ssh 会话复制文件的 transfer，等等。

🎛️ 远程控制

打开 allow_remote_control 之后，kitten @ 就能从任何脚本操控终端：开窗口、往里发文本、改颜色、调大小、列出正在运行的东西。不经过复用器，用脚本搭布局。

🐚 Shell 集成

kitty 知道每个提示符从哪开始：用 ctrl+shift+z 在提示符之间跳转，把上一条命令的输出丢进分页器，点击就能在当前行里移动光标，新窗口在当前目录打开。支持 bash、zsh 和 fish，由 kitty-shell-integration 提供。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🔧 工具集成

kitty 是其他一切下面的那个终端，所以集成主要是关于在它里面运行的东西：

  • 远程服务器： kitty 设置 TERM=xterm-kitty，没有这份 terminfo 的主机会给你一个坏掉的退格键，less 和 clear 也会抱怨。kitten ssh 会替你把它复制过去；对于用普通 ssh 连的主机，在那边装上 kitty-terminfo 即可，这是一个与架构无关的包，只有 terminfo 条目，不会再拖进任何别的东西
  • 你的 shell： kitty-shell-integration 把 bash、zsh 和 fish 的钩子放在 /usr/share/kitty/shell-integration，而 kitty.conf 里默认的 shell_integration enabled 会启用它们，不碰你的 rc 文件
  • yazi、viu 和 Neovim： 三者都通过 kitty 图形协议绘制图片，Neovim 还原生支持 kitty 键盘协议，所以这就是它们被测试过的那个终端
  • Zellij 和 tmux： kitty 自己的窗口、标签页和布局已经覆盖了本地复用器的大部分功能；需要会话比窗口活得更久时用 Zellij，用 tmux 的话给它配上 extended-keys 和 passthrough，kitty 的协议才能一路通过
  • 你的桌面： 软件包安装桌面入口、图标和 man 手册页，并注册 x-terminal-emulator 候选项，所以 kitty 会出现在你的启动器里，一条 update-alternatives 就能把它设为系统默认

  • 官方 Debian： trixie 收录 kitty 0.41.1，Bookworm 收录 0.26.5，各自在整个版本生命周期内冻结
  • 上游的安装脚本： 一条 curl | sh 装进 ~/.local/kitty.app，够新，但只对单个用户生效，没有桌面入口、man 手册页和 x-terminal-emulator，除非你自己接好，而且更新靠再跑一遍安装脚本
  • 自己从源码构建： Python、Go、一长串 -dev 包和不短的时间，换来一个 apt 完全不知道的二进制文件
  • deb.griffo.io: 最新版本，并自动更新
  • ✅ 和 Debian 相同的包名： kitty、kitty-terminfo、kitty-shell-integration 和 kitty-doc，与 Debian 软件源里的叫法完全一致，所以本仓库会就地升级系统自带的 kitty，之后 apt remove 也不会留下任何东西
  • ✅ 官方构建： 上游预编译的 bundle，和 kitty 自己的安装脚本是同一份字节，放在 /opt/kitty，并有 /usr/bin/kitty 和 /usr/bin/kitten 两个符号链接；不从源码构建，不打补丁
  • ✅ 集成到位： 桌面入口、图标、man 手册页、terminfo 和 shell 集成都放在 Debian 的标准路径下，并注册了 x-terminal-emulator 候选项
  • ✅ kitty-terminfo 可以单独走： 一个与架构无关的包，只有 xterm-kitty 的 terminfo，给你 ssh 进去的那些服务器用
  • ✅ 自动更新： 上游发布后数小时内更新软件包
  • ✅ 两种架构： amd64 和 arm64，也就是上游发布 bundle 的那两种；没有 i386、armhf 或 riscv64 的构建
  • ✅ 多发行版： 支持 Bookworm、Trixie、Forky 和 Sid
  • ✅ 易于维护： 使用标准 apt 命令即可更新
