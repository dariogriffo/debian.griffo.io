什么是 rumdl？

rumdl 是一个用 Rust 写的 Markdown 检查与格式化工具。它实现了大家早已从 markdownlint 熟悉的那套规则，也就是 MD001 到 MD059 这些针对标题层级、列表缩进、行长度、代码围栏风格、链接语法和行尾空格的检查，而它跑完一整棵文档树只要几毫秒，不是几秒。这些规则大多带有修复方案，所以 rumdl check --fix 会把它报出来的问题直接改好，而不是丢给你一份清单，rumdl fmt 则能把一个文件整体重新排版。配置是一个 rumdl.toml 文件，或者 pyproject.toml 里的一张 [tool.rumdl] 表；已经有的 .markdownlint.json 可以用 rumdl import 转换过来；rumdl server 讲的是 Language Server Protocol，所以同一个二进制文件也会在你的编辑器里把问题标出来。把它理解成 Ruff 之于 Python，只是对象换成了 Markdown。

🚀 为什么最新版本很重要： rumdl 仍在一个版本接一个版本地增加规则、修复方案和配置项，而每一条新规则，都是你的文档在升级之前享受不到的一项检查。修复行为也在同样这些版本里被不断打磨，所以旧的二进制文件可能会用当前版本早已不再采用的方式改写文件，而照着今天的文档写出来的 rumdl.toml，里面的选项旧构建可能会默默忽略。Debian 和 Ubuntu 根本没有收录 rumdl，所以最新构建在这里不是锦上添花，而是通过 apt 获得它的唯一途径。

⚡ rumdl 的主要功能

🏎️ 用 Rust 的速度跑 markdownlint 规则

熟悉的 MD001 到 MD059 检查，由一个编译好的二进制文件执行，没有解释器要启动。以前在 CI 里要单独占一步的文档树，现在快到每次保存都能跑一遍。

🔧 会修，而不只是抱怨

rumdl check --fix 会修好那些有安全修复方案的问题：标题标点、列表标记与缩进、块前后的空行、行尾空格、围栏风格，整棵树就地改完。

🖊️ 它同时也是格式化工具

rumdl fmt 像代码格式化工具那样重排 Markdown，一个文件长什么样，从此不再是评审意见。--check 则把它变成一道什么都不改的 CI 关卡。

🔌 编辑器集成是内置的

rumdl server 是一个 Language Server，所以 VS Code、Neovim、Helix 和 Zed 得到的诊断和修复，跟命令行上的一模一样，都出自你装的那一个二进制文件。

♻️ 保留你的 markdownlint 配置

rumdl import 读取已有的 .markdownlint.json 或 .markdownlintrc，写出等价的 rumdl.toml，所以把一个仓库切过来是一条命令，而不是一次规则审计。

📖 会自己解释的规则

rumdl rule 列出每一条检查，rumdl explain MD013 把其中一条讲清楚，包括它修什么、怎么配置，谁都不用再猜 CI 日志里那个代码是什么意思。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🔧 工具集成

rumdl 生来就是要顶替 markdownlint 已经待着的那些位置：

  • 你的编辑器： rumdl server 是一个 Language Server，所以 Neovim、Helix、VS Code 和 Zed 会把诊断直接显示在行内，并以代码操作的形式应用修复
  • markdownlint 配置： rumdl import 把 .markdownlint.json 或 .markdownlintrc 变成 rumdl.toml，而规则代码还是你的团队早就在争论的那些
  • pyproject.toml： 一张 [tool.rumdl] 表让这些设置和你的 Ruff、pytest 配置待在一起，而不是再多一个点文件
  • CI 与 pre-commit： rumdl check . 有违规就以非零状态退出，rumdl fmt --check 则守住格式这一关，而构建机上不必先装 Node 或 Python 运行时
  • 静态站点生成器： MkDocs、Hugo、Docusaurus 和 mdBook 的文档源文件都是普通 Markdown，所以同一条检查可以在构建之前先跑一遍

🚀 为什么选择 deb.griffo.io？

📊 仓库对比：
  • 官方 Ubuntu： 没有收录 rumdl，标准系统上 apt install rumdl 会失败
  • npm 或 pip： 能用，但会把一次 Markdown 检查绑在 Node 或 Python 环境上，而且每个项目、每个 CI 镜像都要重装一遍
  • 自己从源码构建： 版本够新，但每台机器都要一套 Rust 工具链，而且留下一个 apt 完全不知道的二进制文件
  • deb.griffo.io: 最新版本，并自动更新
  • ✅ 唯一的 apt 来源： Debian 与 Ubuntu 官方源都没有 rumdl；本仓库打包官方上游发布版
  • ✅ 全系统可用，不带运行时： 机器上所有仓库共用一个 /usr/bin/rumdl，背后既没有 npm install，也没有虚拟环境
  • ✅ 自动更新： 上游发布后数小时内更新软件包，所以新规则和新修复靠一条普通的 apt upgrade 就能到手
  • ✅ 完整的软件包： 官方上游的 Linux 构建，安装为 /usr/bin/rumdl，不加料、不打补丁
  • ✅ 诚实的依赖： 一个静态链接的 Rust 二进制文件，检查、修复、格式化和跑服务都不需要再装别的东西
  • ✅ 两种架构： amd64 和 arm64，同一个包覆盖你的笔记本、服务器和 arm64 构建机
  • ✅ 多发行版： 支持 Ubuntu 22.04、24.04、25.10 和 26.04
  • ✅ 易于维护： 使用标准 apt 命令即可更新

rumdl 在官方 Ubuntu 软件源中吗？

不在, 官方 Ubuntu 源没有打包 rumdl。本仓库目前是唯一的 apt 来源，提供 rumdl 0.2.64。

如何在 Ubuntu 上安装最新版 rumdl？

按上方说明一次性添加 deb.griffo.io 仓库，然后运行：sudo apt install rumdl。之后通过常规的 sudo apt upgrade 获取新版本。

软件包是否有签名？如何构建？

每个软件包都使用仓库的 GPG 密钥（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）签名，并基于上游发布在公开的 GitHub 仓库中构建，任何人都可以审查。
