什么是 bottom？

bottom（命令名为 btm）是一个终端图形化进程与系统监视器，用 Rust 编写，灵感来自 gtop、gotop 和 htop。默认情况下它就像一块仪表盘：CPU、内存、网络、磁盘、温度和进程等组件共享一个屏幕，每个组件都可以排序、缩放，或展开占满整个终端。

🚀 为什么最新版本很重要： 官方软件源落后好几个小版本，而恰恰是这些版本带来了真正有用的东西：缓存与缓冲区单独统计、内存组件中的 GPU 占用、内置配色主题、隐藏内核线程，以及一长串针对新内核和新传感器的修复。一个读错硬件数据的监视器比没有监视器更糟，所以这类工具值得保持最新。

⚡ bottom 的主要功能

📈 实时图表

CPU（按核心或平均）、内存、网络吞吐、磁盘 I/O 和温度都以滚动图表呈现，可用 + 和 - 缩放。

🔍 进程搜索

/ 可过滤进程表，支持正则、全词匹配和大小写开关，并各有一个按键按 CPU、内存、PID 或名称排序。

🌲 树形模式

t 把进程表切换成树形视图，失控的子进程会显示在启动它的父进程之下，而不是孤零零地排在列表里。

🎛️ 自定义布局

配置文件描述行、列与各组件比例，让仪表盘只显示你真正关心的那四项，而不是默认的九个组件。

🎨 内置主题

--theme gruvbox、nord 及其浅色变体都内置在二进制文件中，每个元素的颜色都能在 bottom.toml 中覆盖。

🖥️ 基础模式

btm --basic 去掉图表，只留紧凑的数字读数，在慢速 SSH 连接或很小的 tmux 窗格里依然清晰。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🎯 基本用法示例

日常监控：

# 完整仪表盘
btm

# 每秒刷新两次，保留十分钟历史
btm --rate 500ms --retention 10m

# 启动即进入进程组件，并直接展开
btm --default_widget_type proc --expanded

# 进程树，分组显示，并展示完整命令行
btm --tree --process_command

仪表盘内的操作：

# 真正常用的按键
#   ?        内置帮助，列出所有快捷键
#   e        把所选组件展开到整个终端
#   f        阅读时冻结画面
#   +  -  =  放大、缩小或还原图表
#   /        搜索进程表
#   c m p n  按 CPU、内存、PID 或名称排序
#   dd       结束所选进程
#   t        切换进程树

按机器调整：

# 使用华氏度、隐藏 CPU 平均行、用点状标记代替盲文字符
btm --fahrenheit --hide_avg_cpu --dot_marker

# 把缓存和缓冲区单列为一行内存
btm --enable_cache_memory

# 笔记本上的电池组件
btm --battery

# 与终端整体风格一致的配色主题
btm --theme gruvbox

🔧 工具集成

bottom 天生适合以终端为中心的工作方式：

  • 配置文件：~/.config/bottom/bottom.toml 把布局、组件比例、颜色和常用参数集中在一处
  • 桌面入口：软件包会安装 bottom.desktop 和图标，因此它也会作为系统监视器出现在应用菜单中
  • tmux 与 Zellij：在狭窄的窗格中也很自在；窗格变小时用 --basic 保持可读
  • GPU：安装了驱动时，NVIDIA 和 AMD 的占用会显示在内存组件中，--disable_gpu 可关闭采集
  • 服务器：amd64 版本为静态链接，全新的 Debian 或 Ubuntu 机器只需这个软件包
