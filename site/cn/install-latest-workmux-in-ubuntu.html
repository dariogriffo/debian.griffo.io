什么是 workmux？

workmux 把一条分支变成一个工作区。一条 workmux add 就会创建 git worktree、打开对应的 tmux 窗口、复制新检出缺少的文件（.env、凭据），为你不想重装的目录建立软链接（node_modules），执行你的准备命令，并按你要求的方式排布窗格。workmux merge 再一步把这一切收回：合并分支、删除 worktree、关闭窗口、移除本地分支。不用 stash，不用切分支，也不会有半成品检出挡住下一件事。

🚀 为什么最新版本很重要： workmux 每周都会发布多个版本，而且大多与它所驱动的工具有关：能追踪哪些编码代理、如何上报它们的状态、支持哪些终端复用器、仪表盘和侧边栏显示什么。上周新增的代理集成，只存在于上周的二进制文件里。Debian 和 Ubuntu 根本没有收录 workmux，所以最新构建在这里不是锦上添花，而是通过 apt 获得它的唯一途径。

⚡ workmux 的主要功能

🌿 一条分支一个窗口

workmux add 同时创建 worktree 和 tmux 窗口，于是切换任务就是切换标签页，各自拥有自己的 shell、编辑器和开发服务器。

🧰 真正能用的 worktree

新建的 worktree 一开始是残缺的。workmux 会复制配置文件、软链接依赖并运行你的 post_create 命令，让新检出立刻可用。

🤖 并行运行代理

同时运行多个 AI 编码代理，每个 worktree 一个，并在 tmux 窗口名、TUI 仪表盘或实时侧边栏中查看它们的状态。

🧹 一条命令收尾

workmux merge 合并分支后会删除 worktree、tmux 窗口和本地分支；workmux remove 则只清理、不合并。

📄 用 YAML 配置

全局 config.yaml 保存你的默认设置，项目级 .workmux.yaml 定义窗格布局、钩子和文件操作，并支持适合 monorepo 的嵌套。

🖥️ 不只是 tmux

tmux 是默认后端，kitty、WezTerm 和 Zellij 也是受支持的替代方案，工作流可以跟着你已有的终端走。

🚀 始终领先于官方软件源： Debian 和 Ubuntu 在发布时冻结软件包版本，而本仓库通常在上游发布后数小时内就发布新版本。一条简单的 apt upgrade 就能让你保持最新。

🎯 基本用法示例

日常流程：

# 创建分支、worktree 和 tmux 窗口
workmux add fix-login

# 已有分支按名字识别
workmux add existing-work

# 从默认基准之外的分支切出
workmux add hotfix --base production

# 把 pull request 检出到独立的 worktree
workmux add --pr 123

# 查看所有进行中的工作
workmux list

# 合并并全部拆除
workmux merge

# 或者不合并直接丢弃
workmux remove fix-login

窗口、窗格与恢复：

# 创建窗口但不切换过去
workmux add docs-pass --background

# 关闭窗口，保留 worktree 和分支
workmux close docs-pass

# 之后再打开
workmux open docs-pass

# tmux 或机器崩溃后重建全部窗口
workmux resurrect

# 从任何地方进入某个 worktree
cd "$(workmux path fix-login)"

让多个代理并行工作：

# 为你的代理安装状态钩子和技能
workmux setup

# 带上给代理的提示词启动一个 worktree
workmux add add-tests --prompt "为解析器补充单元测试"

# 在一个 TUI 里观察所有代理
workmux dashboard

# 或者在 tmux 中常驻一个状态侧边栏
workmux sidebar

# 给运行中的代理发送指令
workmux send add-tests "也把错误路径覆盖上"

# 等待该代理完成
workmux wait add-tests

🔧 工具集成

workmux 刻意建立在你已经在用的工具之上：

  • git: worktree 就是普通的 git worktree 检出，git、你的钩子和 CI 都察觉不到异常
  • tmux: 每个 worktree 一个窗口，以分支命名，并自动套用你的窗格布局
  • kitty、WezTerm 和 Zellij： 如果你的复用器不是 tmux，这些都是受支持的替代后端
  • 编码代理： 为 Claude Code 及上游支持的其他代理提供状态追踪、提示词注入和技能安装
  • 你的 shell： 本软件包自带 bash、zsh 和 fish 补全，alias wm='workmux' 是上游推荐的简写

❓ 常见问题

workmux 在官方 Ubuntu 软件源中吗？

不在, 官方 Ubuntu 源没有打包 workmux。本仓库目前是唯一的 apt 来源，提供 workmux 0.1.244。

如何在 Ubuntu 上安装最新版 workmux？

按上方说明一次性添加 deb.griffo.io 仓库，然后运行：sudo apt install workmux。之后通过常规的 sudo apt upgrade 获取新版本。

软件包是否有签名？如何构建？

每个软件包都使用仓库的 GPG 密钥（EA0F721D231FDD3A0A17B9AC7808B4DD62C41256）签名，并基于上游发布在公开的 GitHub 仓库中构建，任何人都可以审查。

支持哪些 Ubuntu 版本？

Ubuntu 22.04 Jammy、24.04 Noble、25.10 Questing 和 26.04 Resolute。
