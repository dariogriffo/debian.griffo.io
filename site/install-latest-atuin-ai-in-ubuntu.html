What is Atuin AI?

Atuin AI is the shell agent for Atuin. Atuin shipped it built in up to 18.24 and removed it in 18.25; it now lives on as a standalone binary, atuin-ai. Press ? at an empty prompt and a chat opens right in your terminal: describe what you want and it suggests the command, or ask a question and it answers. With your permission it can also search your Atuin history, read and edit files and run commands. It talks to an Atuin AI server that you host yourself (upstream publishes it as a Docker image), and that server can sit in front of any OpenAI-compatible endpoint: Ollama, vLLM or a hosted API. The client is written in Rust by the Atuin team and is MIT licensed.

🚀 Why Latest Versions Matter: Atuin AI is young and moves fast, and upstream publishes no releases at all, only commits to main. This repository builds a snapshot every Friday when main has moved, versioned <client version>.<YYYYMMDD> (for example 0.1.0.20261127), so apt upgrade brings you the week's changes without a Rust toolchain. Ubuntu does not package atuin-ai at all.

⚡ Key Features of Atuin AI

❓ One Key Away

Press ? on an empty prompt to open the agent. Anywhere else ? types a question mark as usual, so it never gets in the way of a command you are writing.

💡 Command Suggestions

Describe the task in plain words ("find files over 1 GB changed this week") and get back a command you can read, edit and run, instead of digging through man pages.

📜 Knows Your History

With permission, the agent searches your Atuin history, so it can find the command you ran last month or build on how you usually do things on this machine.

🛠️ Files and Commands

It can read and edit files and run commands for you, and it asks before it does. You stay in charge of what touches your system.

🏠 Your Own Server

The client talks to an Atuin AI server you run yourself, so your prompts and history go where you decide. Upstream ships the server as ghcr.io/atuinsh/atuin-ai-server.

🔌 Any OpenAI-Compatible Model

The server works with any OpenAI-compatible endpoint: a local model through Ollama or vLLM, or a hosted API. Swap models on the server without touching the client.

🚀 Always ahead of the official archives: Debian and Ubuntu freeze package versions when a release ships. This repository publishes new upstream releases typically within hours. A simple apt upgrade keeps you on the latest version.

Step 3: First run

# Point the client at your Atuin AI server
# (a commented example: /usr/share/doc/atuin-ai/examples/ai.example.toml)
mkdir -p ~/.atuin
cat > ~/.atuin/ai.toml <<'EOF'
endpoint = "http://localhost:8080"
# api_token = "..."   # only when the server sets AUTH_TOKEN
EOF

# Bind ? in your shell, after Atuin's own init line
echo 'eval "$(atuin-ai init bash)"' >> ~/.bashrc

# Open a new shell, then press ? at an empty prompt
exec bash

🎯 Basic Usage Examples

Shell setup:

# bash, in ~/.bashrc
eval "$(atuin init bash)"
eval "$(atuin-ai init bash)"

# zsh, in ~/.zshrc
eval "$(atuin init zsh)"
eval "$(atuin-ai init zsh)"

# fish, in ~/.config/fish/config.fish
atuin init fish | source
atuin-ai init fish | source

Running the server:

# Only the client is packaged; the server is upstream's Docker image
docker pull ghcr.io/atuinsh/atuin-ai-server

# Configure it with your OpenAI-compatible endpoint (Ollama, vLLM, a hosted API)
# as upstream's Self-Hosting guide describes, then check it answers
curl http://localhost:8080/api/cli/models

🔧 Tool Integrations

Atuin AI sits between your shell, your Atuin history and a model you choose:

  • Atuin: a hard dependency, installed with it from deb.griffo.io; the agent searches the same history database atuin search uses, and only when you allow it
  • Atuin 18.25 and later: 18.25 dropped the built-in agent, so this package is how you keep the ? chat on a current Atuin
  • bash, zsh and fish: atuin-ai init bash, zsh or fish prints the key binding; load it after Atuin's own init so both bindings coexist
  • Atuin AI server: ghcr.io/atuinsh/atuin-ai-server, run with Docker or Podman on the same machine or anywhere the client can reach; set AUTH_TOKEN there and api_token in ~/.atuin/ai.toml to lock it down
  • Ollama and vLLM: keep every prompt on your own hardware by pointing the server at a local OpenAI-compatible endpoint
  • Hosted APIs: any provider that speaks the OpenAI API works the same way, configured on the server, never in the client

❓ Frequently asked questions

Is Atuin AI in the official Ubuntu repositories?

No, Atuin AI is not packaged in the official Ubuntu archives. This repository is currently the only apt source, serving Atuin AI 0.1.0.20261125.

How do I install the latest Atuin AI on Ubuntu?

Add the deb.griffo.io repository once using the instructions above, then run: sudo apt install atuin-ai. New releases arrive through the normal sudo apt upgrade.

Are the packages signed and how are they built?

Every package is signed with the repository's GPG key (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) and built from upstream releases in public GitHub packaging repositories that anyone can inspect.

Which Ubuntu releases are supported?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing, 26.04 Resolute and 26.10 Stonking.
