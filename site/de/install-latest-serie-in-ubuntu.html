Was ist Serie?

Serie ist eine Terminal-Oberfläche zum Durchstöbern der Historie eines Git-Repositories. Sie zeigt, was git log --graph --all zeigt — nur wird der Graph über das Inline-Bildprotokoll des Terminals gezeichnet statt mit ASCII-Kunst angenähert, sodass Branches und Merges auf einen Blick lesbar sind. Neben dem Graphen steht eine scroll- und durchsuchbare Commit-Liste mit Detailansicht. Serie ist bewusst ein Betrachter, kein Git-Client: es committet, branched und pusht nicht.

🚀 Warum neueste Versionen wichtig sind: Serie ist ein junges Projekt vor 1.0, und Funktionen landen in ganz normalen Releases: eigene Befehle, anpassbare Tastenbelegungen, Optionen für Graph-Stil und -Reihenfolge sowie Unterstützung für die Unicode-Platzhalter-Variante des Kitty-Grafikprotokolls. Auch die Bildunterstützung der Terminals bewegt sich ständig — der Build, der in deinem Terminal sauber zeichnet, ist meist der aktuelle.

⚡ Hauptfunktionen von Serie

🖼️ Ein echter Commit-Graph

Der Graph wird über das Kitty- oder iTerm2-Protokoll als Bild gerendert, sodass Branch-Linien auch bei Dutzenden paralleler Branches lesbar bleiben.

🔍 Durchsuchbare Historie

Eine Commit-Liste neben dem Graphen, die scrollt und sucht, statt sich durch die Ausgabe von git log zu blättern.

📄 Detailansicht pro Commit

Einen Commit auswählen und Nachricht, Refs und Diff sehen, ohne den Graphen zu verlassen.

🎛️ Graph-Optionen

Chronologische oder topologische Sortierung, einfach oder doppelt breite Zellen, runde oder eckige Kanten — einmal auf der Kommandozeile oder in der Konfiguration gesetzt.

⌨️ Eigene Tastenbelegungen

? zeigt die aktuellen Belegungen, und jede davon lässt sich in config.toml überschreiben.

🧰 Eigene Befehle

Eigene Kommandos auf dem ausgewählten Commit ausführen: Ausgabe in einer eigenen Ansicht, etwas im Hintergrund starten oder Serie für ein interaktives Programm pausieren.

🚀 Immer den offiziellen Archiven voraus: Debian und Ubuntu frieren Paketversionen zum Release-Zeitpunkt ein — dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb weniger Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

🎯 Grundlegende Verwendungsbeispiele

Historie durchstöbern:

# Die vollständige Historie des aktuellen Repositories
serie

# Nur die neuesten Commits, bei sehr großen Repositories
serie -n 5000

# Topologische statt chronologischer Reihenfolge
serie -o topo

# Mit HEAD statt dem neuesten Commit starten
serie -i head

Den Graphen ans Terminal anpassen:

# Ein Bildprotokoll erzwingen, wenn die Erkennung danebenliegt
serie -p kitty
serie -p iterm
serie -p kitty-unicode

# Schmalere Graph-Zellen für ein kleines Fenster
serie -g single

# Eckige statt runder Kanten
serie -s angular

# Oder der großzügige, runde Look auf einem breiten Terminal
serie -g double -s rounded

Konfiguration und Alltag:

# Die Konfigurationsdatei für Tasten und Standardwerte
mkdir -p ~/.config/serie
$EDITOR ~/.config/serie/config.toml

# Oder Serie auf eine Konfiguration anderswo zeigen lassen
SERIE_CONFIG_FILE=~/dotfiles/serie.toml serie

# Serie liest nur die Historie — git bleibt dein Client
git -C ~/src/project log --oneline -5

# Committen ist also weiterhin Sache von git
git commit -v

🔧 Tool-Integrationen

Serie braucht zwei Dinge und arbeitet mit einem dritten zusammen:

  • git: ein ganz normales Git-Repository und das git-Binary, das das Paket als Abhängigkeit mitbringt
  • Dein Terminal: ein Emulator, der das Inline-Bildprotokoll von Kitty oder iTerm2 spricht — Ghostty, Kitty, WezTerm und iTerm2 gehören dazu
  • Konfigurationsdatei: $XDG_CONFIG_HOME/serie/config.toml oder das, worauf SERIE_CONFIG_FILE zeigt
  • Eigene Befehle: git diff, einen Editor oder ein eigenes Skript auf eine Taste legen und auf dem ausgewählten Commit ausführen
  • Dein git-Client: Serie committet und pusht bewusst nicht und steht damit neben lazygit, GitUI oder purem git, statt sie zu ersetzen

🚀 Warum deb.griffo.io?

📊 Repository-Vergleich:
  • Offizielles Ubuntu: paketiert Serie überhaupt nicht — auf einem Standardsystem gibt es nichts zu installieren
  • cargo install --locked serie: aktuell, aber Rust-Toolchain und Kompilierlauf auf jeder Maschine, außerhalb von apt
  • Upstream-Tarball: das offizielle Binary, für jedes Release von Hand neu geholt
  • deb.griffo.io: neueste Version mit automatischen Updates
  • ✅ Jung und in Bewegung: eigene Befehle, anpassbare Tasten und die Graph-Optionen kamen alle in normalen Releases — der aktuelle Build ist ein anderes Werkzeug als einer von vor einem Jahr
  • ✅ Die einzige apt-Quelle: Serie ist weder in den Debian- noch in den Ubuntu-Archiven; dieses Repository paketiert den offiziellen Upstream-Build
  • ✅ Automatische Updates: Pakete werden innerhalb von Stunden nach Upstream-Releases aktualisiert
  • ✅ Ehrliche Paketierung: das Upstream-Binary unter /usr/bin/serie, mit git als Abhängigkeit; upstream liefert weder Handbuchseite noch Vervollständigungen, also erfindet das Paket keine
  • ✅ Zwei Architekturen: amd64 und arm64, beide statisch gelinkte musl-Builds ohne Bibliotheksabhängigkeiten
  • ✅ Multi-Distribution: läuft auf Ubuntu 22.04, 24.04, 25.10 und 26.04
  • ✅ Einfache Wartung: Updates mit den üblichen apt-Befehlen

❓ Häufig gestellte Fragen

Ist Serie in den offiziellen Ubuntu-Paketquellen?

Nein, Serie ist nicht in den offiziellen Ubuntu-Archiven paketiert. Dieses Repository ist derzeit die einzige apt-Quelle und liefert Serie 0.8.1.

Wie installiere ich das neueste Serie unter Ubuntu?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install serie. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Ubuntu-Versionen werden unterstützt?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing und 26.04 Resolute.
