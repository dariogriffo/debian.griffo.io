Was ist lnav?

lnav, der Logfile Navigator, ist ein Log-Viewer fürs Terminal, der Logdateien aus vielen Quellen zu einer einzigen, nach Zeitstempel geordneten Ansicht zusammenführt. Du gibst ihm ein paar Dateien, ein Verzeichnis oder ein komprimiertes Archiv, und er erkennt die Formate selbst (syslog, das systemd-Journal, Apache- und nginx-Access-Logs, JSON Lines und viele mehr), verzahnt die Meldungen nach Zeit, färbt Fehler und Warnungen ein, damit sie auffallen, und folgt den Dateien, während sie wachsen. Von dort aus filterst du, suchst, springst von Fehler zu Fehler, und wenn eine Frage mehr als eine Suche braucht, fragst du die Log-Meldungen mit SQL ab. Entfernte Logs öffnet es über ssh so einfach wie lokale. lnav ist in C++ von Tim Stack geschrieben und steht unter der BSD-2-Clause-Lizenz.

🚀 Warum die neueste Version zählt: lnav bekommt laufend neue Formate, SQL-Funktionen und Viewer-Funktionen, und jedes Release korrigiert, wie bestimmte Logs geparst werden. Debian trixie ist bei lnav 0.12.4 eingefroren und Bookworm bei 0.11.1, ein frisches System verpasst also das aktuelle Release samt den Formaten und Korrekturen, die damit kamen. Dieses Repository liefert lnav 0.14.1 unter demselben Paketnamen, es ersetzt das lnav der Distribution also beim nächsten apt upgrade an Ort und Stelle.

⚡ Hauptfunktionen von lnav

🔀 Eine gemeinsame Zeitachse

Öffne syslog, ein Anwendungs-Log und ein Webserver-Log zusammen, und lnav verzahnt ihre Zeilen nach Zeitstempel, du liest also, was im ganzen System passiert ist, in der Reihenfolge, in der es passiert ist.

🔍 Automatische Formaterkennung

syslog, journald-JSON, Apache- und nginx-Access-Logs, JSON Lines, logfmt und Dutzende mehr werden ohne Konfiguration erkannt; Level, Zeitstempel und Felder werden geparst, Fehler und Warnungen hervorgehoben.

🗄️ SQL über deine Logs

Jedes erkannte Format ist eine Tabelle. Drück ; und führe SELECT-Abfragen auf die Log-Meldungen aus: Fehler pro Host zählen, die langsamsten Requests finden, Statuscodes gruppieren, mit dem Ergebnis im selben Fenster.

🌐 Entfernte Logs über ssh

lnav user@host:/var/log/syslog öffnet ein Log auf einem anderen Rechner über deine normale ssh-Konfiguration und deine Schlüssel, ohne einen Agenten auf dem Server.

📦 Komprimierte Dateien und Archive

Rotierte .gz- und .bz2-Logs öffnen sich direkt, ebenso .zip- und .tar-Archive, ein Support-Bundle lässt sich also lesen, ohne es vorher zu entpacken.

👀 Folgen, filtern und suchen

Dateien werden verfolgt, während sie wachsen, Filter blenden Zeilen nach Muster aus oder ein, Suchen heben jeden Treffer hervor, und einzelne Tasten springen zum nächsten Fehler oder zur nächsten Warnung, damit nichts Wichtiges vorbeirollt.

🚀 Immer vor den offiziellen Archiven: Debian und Ubuntu frieren Paketversionen beim Release ein. Dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb von Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

🔧 Werkzeug-Integrationen

lnav liest alles, was Text erzeugt, aus Dateien, aus Pipes und von anderen Rechnern:

  • ssh: entfernte Pfade wie user@host:/var/log/syslog laufen über deine bestehende ssh-Konfiguration und deine Schlüssel; das Paket empfiehlt dafür openssh-client
  • systemd-Journal: leite journalctl -o json (mit -f zum Verfolgen) in lnav, und jedes Journal-Feld wird durchsuchbar und abfragbar
  • Container: docker logs -f app 2>&1 | lnav oder kubectl logs -f pod | lnav gibt Container-Ausgaben dieselbe Hervorhebung und dasselbe SQL
  • Zwischenablage: Zeilen markieren und c drücken, um sie zu kopieren; das Paket schlägt wl-clipboard oder xclip für Wayland und X11 vor
  • Eigene Formate: beschreibe ein hauseigenes Log-Format in einer JSON-Datei und installiere es mit lnav -i myformat.json; danach bekommt es Erkennung, Hervorhebung und eine eigene SQL-Tabelle
  • Skripte und CI: lnav -n -c führt Befehle und Abfragen ohne Oberfläche aus, dasselbe SQL, das interaktiv eine Frage beantwortet, läuft also auch in einem Cronjob oder einer Pipeline
  • Dokumentation: die Manpage kommt mit dem Paket (man lnav), das vollständige Handbuch steht unter docs.lnav.org

🚀 Warum deb.griffo.io?

📊 Repository-Vergleich:
  • Offizielles Debian: liefert lnav 0.12.4 in trixie und 0.11.1 in Bookworm, jeweils für die Lebensdauer des Release eingefroren

  • Selbst aus dem Quelltext bauen: eine C++-Toolchain plus die Entwicklungspakete von SQLite, PCRE2, ncurses, libarchive und libcurl, und ein langer Build
  • deb.griffo.io: neueste Version mit automatischen Updates
  • ✅ Derselbe Paketname wie bei Debian: das Paket heißt lnav, genau wie im Debian-Archiv, dieses Repository aktualisiert das mitgelieferte lnav also bei apt upgrade an Ort und Stelle, und ein späteres apt remove hinterlässt nichts
  • ✅ Der offizielle statische Build: upstreams eigene statische musl-Binärdatei, ganz ohne Laufzeitabhängigkeiten und auf jeder Version mit demselben Verhalten
  • ✅ Vollständiges Paket: die Binärdatei lnav und ihre Manpage, mit openssh-client als Empfehlung für entfernte Logs und wl-clipboard oder xclip als Vorschlag zum Kopieren von Zeilen
  • ✅ Automatische Updates: Pakete werden innerhalb von Stunden nach dem Upstream-Release aktualisiert
  • ✅ Zwei Architekturen: amd64 und arm64 auf jeder Version, dasselbe lnav läuft also auf Servern, Laptops und ARM-Boards wie dem Raspberry Pi
  • ✅ Multi-Distribution: läuft auf Bookworm, Trixie, Forky und Sid
  • ✅ Einfache Wartung: Updates mit den üblichen apt-Befehlen

❓ Häufig gestellte Fragen

Ist lnav in den offiziellen Debian-Paketquellen?

Ja, aber das offizielle Debian-Archiv liefert lnav 0.12.4, während dieses Repository lnav 0.14.1 bereitstellt, wenige Stunden nach jedem Upstream-Release neu gebaut.

Wie installiere ich das neueste lnav unter Debian?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install lnav. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Debian-Versionen werden unterstützt?

Debian 12 Bookworm, Debian 13 Trixie, Forky und Sid.
