Was ist rumdl?

rumdl ist ein Markdown-Linter und -Formatierer, geschrieben in Rust. Es setzt genau das Regelwerk um, das alle schon von markdownlint kennen, die Prüfungen MD001 bis MD059 für Überschriftenebenen, Listeneinrückung, Zeilenlänge, den Stil von Codeblöcken, Linksyntax und Leerzeichen am Zeilenende, und es lässt sie in Millisekunden statt in Sekunden über einen ganzen Dokumentationsbaum laufen. Zu den meisten dieser Regeln gehört eine Korrektur, rumdl check --fix repariert also, was es meldet, statt dir nur eine Liste zu hinterlassen, und rumdl fmt formatiert eine Datei komplett neu. Konfiguriert wird über eine rumdl.toml oder eine [tool.rumdl]-Tabelle in der pyproject.toml, eine vorhandene .markdownlint.json wandelt rumdl import um, und rumdl server spricht das Language Server Protocol, dieselbe Binärdatei unterstreicht Probleme also auch in deinem Editor. Denk an das, was Ruff für Python ist, angewandt auf Markdown.

🚀 Warum die neueste Version zählt: rumdl bekommt von Release zu Release weiterhin Regeln, Korrekturen und Konfigurationsschlüssel dazu, und jede neue Regel ist eine Prüfung, die deine Dokumentation bis zum Upgrade nicht bekommt. Das Verhalten der Korrekturen wird in denselben Releases nachgeschärft, eine alte Binärdatei kann eine Datei also auf eine Weise umschreiben, wie es die aktuelle nicht mehr täte, und eine rumdl.toml, die gegen die heutige Dokumentation geschrieben ist, nennt womöglich Optionen, die ein älterer Build stillschweigend ignoriert. Weder Debian noch Ubuntu paketieren rumdl überhaupt, ein aktueller Build ist hier also kein Luxus, sondern der einzige Weg, es über apt zu bekommen.

⚡ Hauptfunktionen von rumdl

🏎️ markdownlint-Regeln in Rust-Geschwindigkeit

Die vertrauten Prüfungen MD001 bis MD059, ausgeführt von einer kompilierten Binärdatei, hinter der kein Interpreter erst starten muss. Ein Dokumentationsbaum, der in der CI einen eigenen Lint-Schritt brauchte, ist schnell genug für jedes Speichern.

🔧 Korrekturen statt bloßer Beschwerden

rumdl check --fix repariert die Verstöße, für die es eine sichere Korrektur gibt: Satzzeichen in Überschriften, Listenzeichen und Einrückung, Leerzeilen um Blöcke, Leerzeichen am Zeilenende, den Stil von Codeblöcken, an Ort und Stelle im ganzen Baum.

🖊️ Auch ein Formatierer

rumdl fmt formatiert Markdown so um, wie es ein Code-Formatierer tut, die Form einer Datei ist damit kein Review-Kommentar mehr. Mit --check wird daraus ein CI-Gate, das selbst nichts verändert.

🔌 Editor-Anbindung eingebaut

rumdl server ist ein Language Server, VS Code, Neovim, Helix und Zed bekommen also dieselben Diagnosen und dieselben Korrekturen wie die Kommandozeile, aus der einen Binärdatei, die du installiert hast.

♻️ Deine markdownlint-Konfiguration bleibt

rumdl import liest eine vorhandene .markdownlint.json oder .markdownlintrc und schreibt die passende rumdl.toml, ein Repository umzustellen ist damit ein Befehl und keine Regelinventur.

📖 Regeln, die sich selbst erklären

rumdl rule listet jede Prüfung auf und rumdl explain MD013 beschreibt eine davon, mitsamt dem, was sie korrigiert, und dem, wie man sie einstellt, niemand muss also raten, was ein Code im CI-Log bedeutet hat.

🚀 Immer vor den offiziellen Archiven: Debian und Ubuntu frieren Paketversionen beim Release ein. Dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb von Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

🎯 Grundlegende Verwendungsbeispiele

# Maschinenlesbare Ausgabe für einen Schritt in der CI, der

rumdl check --output-format json .

🔧 Werkzeug-Integrationen

rumdl ist dafür gebaut, sich genau dort einzufügen, wo markdownlint schon sitzt:

  • Dein Editor: rumdl server ist ein Language Server, Neovim, Helix, VS Code und Zed zeigen die Diagnosen also direkt im Text und wenden die Korrekturen als Code-Aktionen an
  • markdownlint-Konfigurationen: rumdl import macht aus .markdownlint.json oder .markdownlintrc eine rumdl.toml, und die Regelcodes sind dieselben, über die dein Team ohnehin schon streitet
  • pyproject.toml: eine [tool.rumdl]-Tabelle hält die Einstellungen neben deiner Ruff- und pytest-Konfiguration, statt noch eine Punktdatei hinzuzufügen
  • CI und pre-commit: rumdl check . endet bei Verstößen mit einem Fehlercode und rumdl fmt --check sichert die Formatierung ab, ohne dass auf dem Agenten erst eine Node- oder Python-Laufzeit installiert werden müsste
  • Statische Website-Generatoren: die Doku-Quellen von MkDocs, Hugo, Docusaurus und mdBook sind gewöhnliches Markdown, dieselbe Prüfung läuft also darüber, bevor der Build es tut

🚀 Warum deb.griffo.io?

📊 Repository-Vergleich:
  • Offizielles Debian: paketiert rumdl nicht, apt install rumdl schlägt auf einem Standardsystem fehl
  • npm oder pip: funktioniert, bindet eine Markdown-Prüfung aber an eine Node- oder Python-Umgebung und installiert sie in jedem Projekt und jedem CI-Image neu
  • Selbst aus dem Quelltext bauen: aktuell, aber eine Rust-Toolchain auf jeder Maschine und eine Binärdatei, von der apt nichts weiß
  • deb.griffo.io: neueste Version mit automatischen Updates
  • ✅ Die einzige apt-Quelle: rumdl ist weder in den Debian- noch in den Ubuntu-Archiven; dieses Repository paketiert das offizielle Upstream-Release
  • ✅ Systemweit, ohne Laufzeitumgebung: ein /usr/bin/rumdl für jedes Repository auf der Maschine, ohne npm install und ohne virtualenv dahinter
  • ✅ Automatische Updates: Pakete werden innerhalb von Stunden nach dem Upstream-Release aktualisiert, neue Regeln und Korrekturen kommen also mit einem schlichten apt upgrade
  • ✅ Vollständiges Paket: der offizielle Upstream-Linux-Build als /usr/bin/rumdl, nichts hinzugefügt, nichts gepatcht
  • ✅ Ehrliche Abhängigkeiten: eine statisch gelinkte Rust-Binärdatei, die nichts weiter braucht, um zu prüfen, zu korrigieren, zu formatieren oder als Server zu laufen
  • ✅ Zwei Architekturen: amd64 und arm64, dasselbe Paket deckt damit deinen Laptop, deine Server und deine arm64-Build-Agenten ab
  • ✅ Multi-Distribution: läuft auf Bookworm, Trixie, Forky und Sid
  • ✅ Einfache Wartung: Updates mit den üblichen apt-Befehlen

❓ Häufig gestellte Fragen

Ist rumdl in den offiziellen Debian-Paketquellen?

Nein, rumdl ist nicht in den offiziellen Debian-Archiven paketiert. Dieses Repository ist derzeit die einzige apt-Quelle und liefert rumdl 0.2.66.

Wie installiere ich das neueste rumdl unter Debian?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install rumdl. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Debian-Versionen werden unterstützt?

Debian 12 Bookworm, Debian 13 Trixie, Forky und Sid.
