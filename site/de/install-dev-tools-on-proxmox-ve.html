Aktuelle Entwicklertools für Proxmox VE

63 Entwicklertools in der neuesten Upstream-Version, ein apt-Befehl, GPG-signiert

⚡ Die kurze Antwort. Ja, deb.griffo.io funktioniert unter Proxmox VE. 63 Entwicklertools lassen sich unter Proxmox VE 9 und Proxmox VE 8 mit ganz normalem apt installieren, mit demselben Einrichtungsbefehl wie unter Debian und Ubuntu: Er liest VERSION_CODENAME aus /etc/os-release und fragt nach der passenden Suite, unter Proxmox VE 9 also nach trixie.

Proxmox VE läuft auf Debian, und seine Hosts werden meist per SSH als root verwaltet, mit dem, was das Debian-Archiv ausgeliefert hat. deb.griffo.io ergänzt aktuelle Versionen von Kommandozeilen-Tools, die das erleichtern, etwa ripgrep, fzf, bottom, lazydocker und neovim, als ganz normale signierte apt-Pakete für das Debian-Release, auf dem Proxmox VE aufbaut.

Die Datei /etc/os-release des Hosts enthält den Debian-Codenamen, daher ergibt der Einrichtungsbefehl unter Proxmox VE 9 trixie und unter Proxmox VE 8 bookworm. Die Befehle unten haben einen Schalter als root, denn so läuft eine Proxmox-Shell in der Regel.

Das Hinzufügen dieses Repositorys verändert weder die Proxmox- noch die Debian-Repositories, und nichts hier ersetzt ein Paket, von dem Proxmox abhängt. Jedes Paket ist ein eigenständiges Tool.

❓ Häufige Fragen

Ist es sicher, einem Proxmox-Host ein Drittanbieter-Repository hinzuzufügen?

Dieses Repository liefert ausschließlich eigenständige Kommandozeilen-Tools, von denen Proxmox VE oder Debian keines unter demselben Namen in einer neueren Version anbietet. apt tauscht also nie ein Proxmox- oder Debian-Paket gegen eines von hier aus. Das Archiv ist GPG-signiert, und der Schlüssel ist per signed-by an genau dieses eine Repository gebunden.

Kann ich es in LXC-Containern und VMs auf Proxmox verwenden?

Ja. Ein Container oder eine VM betreibt ein eigenes Debian oder Ubuntu, richten Sie das Repository also darin auf dieselbe Weise ein; der Einrichtungsbefehl wählt die Suite für das Release, das im Gast läuft.

Ist deb.griffo.io ein offizielles Repository von Proxmox VE?

Nein. Es ist ein inoffizielles Repository, das von Dario Griffo betreut wird und in keiner Verbindung zu Proxmox VE steht. Jedes Paket wird automatisch aus dem offiziellen Upstream-Release gebaut, die Paketierung ist Open Source auf GitHub, und das Archiv ist GPG-signiert.

Kostet das etwas?

Das Repository ist ein Abo (€15 pro Jahr oder einmalig €150) mit kostenloser Testphase. Ein kostenloser Mirror, deb-free.griffo.io, liefert eine kleinere Auswahl an Tools mit Verzögerung, mit derselben Einrichtung auf dieser Distribution.

Wie entferne ich das Repository wieder?

Löschen Sie /etc/apt/sources.list.d/deb.griffo.io.list und /etc/apt/keyrings/deb.griffo.io.gpg und führen Sie dann sudo apt update aus. Bereits installierte Tools bleiben, bis Sie sie mit apt remove entfernen.
