Was ist Atuin AI?

Atuin AI ist der Shell-Agent für Atuin. Atuin brachte ihn bis 18.24 eingebaut mit und hat ihn in 18.25 entfernt; seitdem gibt es ihn als eigenständige Binärdatei, atuin-ai. Drücke ? an einer leeren Eingabezeile, und direkt im Terminal öffnet sich ein Chat: beschreibe, was du vorhast, und er schlägt den Befehl vor, oder stell eine Frage, und er beantwortet sie. Mit deiner Erlaubnis kann er außerdem deine Atuin-Historie durchsuchen, Dateien lesen und bearbeiten und Befehle ausführen. Er spricht mit einem Atuin-AI-Server, den du selbst betreibst (upstream veröffentlicht ihn als Docker-Image), und dieser Server kann vor jedem OpenAI-kompatiblen Endpunkt stehen: Ollama, vLLM oder eine gehostete API. Der Client ist vom Atuin-Team in Rust geschrieben und MIT-lizenziert.

🚀 Warum die neueste Version zählt: Atuin AI ist jung und entwickelt sich schnell, und upstream veröffentlicht gar keine Releases, nur Commits auf main. Dieses Repository baut jeden Freitag einen Snapshot, wenn sich main bewegt hat, versioniert als <Client-Version>.<JJJJMMTT> (zum Beispiel 0.1.0.20261127), damit apt upgrade dir die Änderungen der Woche ohne Rust-Toolchain bringt. Ubuntu paketiert atuin-ai überhaupt nicht.

⚡ Hauptfunktionen von Atuin AI

❓ Eine Taste entfernt

Drücke ? an einer leeren Eingabezeile, um den Agenten zu öffnen. Überall sonst tippt ? wie gewohnt ein Fragezeichen, er kommt also keinem Befehl in die Quere, den du gerade schreibst.

💡 Befehlsvorschläge

Beschreibe die Aufgabe in einfachen Worten ("finde Dateien über 1 GB, die diese Woche geändert wurden") und bekomm einen Befehl zurück, den du lesen, anpassen und ausführen kannst, statt dich durch Manpages zu wühlen.

📜 Kennt deine Historie

Mit Erlaubnis durchsucht der Agent deine Atuin-Historie, findet so den Befehl vom letzten Monat wieder oder baut darauf auf, wie du die Dinge auf dieser Maschine üblicherweise erledigst.

🛠️ Dateien und Befehle

Er kann Dateien lesen und bearbeiten und Befehle für dich ausführen, und er fragt vorher. Du entscheidest, was dein System anfasst.

🏠 Dein eigener Server

Der Client spricht mit einem Atuin-AI-Server, den du selbst betreibst, deine Prompts und deine Historie gehen also dorthin, wo du es willst. Upstream liefert den Server als ghcr.io/atuinsh/atuin-ai-server.

🔌 Jedes OpenAI-kompatible Modell

Der Server arbeitet mit jedem OpenAI-kompatiblen Endpunkt: einem lokalen Modell über Ollama oder vLLM oder einer gehosteten API. Modelle wechselst du auf dem Server, ohne den Client anzufassen.

🚀 Immer vor den offiziellen Archiven: Debian und Ubuntu frieren Paketversionen beim Release ein. Dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb von Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

Schritt 3: Der erste Start

# Den Client auf deinen Atuin-AI-Server zeigen lassen
# (ein kommentiertes Beispiel: /usr/share/doc/atuin-ai/examples/ai.example.toml)
mkdir -p ~/.atuin
cat > ~/.atuin/ai.toml <<'EOF'
endpoint = "http://localhost:8080"
# api_token = "..."   # nur, wenn der Server AUTH_TOKEN setzt
EOF

# ? in deiner Shell belegen, nach Atuins eigener init-Zeile
echo 'eval "$(atuin-ai init bash)"' >> ~/.bashrc

# Neue Shell öffnen, dann ? an einer leeren Eingabezeile drücken
exec bash

🎯 Grundlegende Verwendungsbeispiele

Shell einrichten:

# bash, in ~/.bashrc
eval "$(atuin init bash)"
eval "$(atuin-ai init bash)"

# zsh, in ~/.zshrc
eval "$(atuin init zsh)"
eval "$(atuin-ai init zsh)"

# fish, in ~/.config/fish/config.fish
atuin init fish | source
atuin-ai init fish | source

Den Server betreiben:

# Paketiert ist nur der Client; der Server ist upstreams Docker-Image
docker pull ghcr.io/atuinsh/atuin-ai-server

# Mit deinem OpenAI-kompatiblen Endpunkt konfigurieren (Ollama, vLLM, gehostete API),
# wie upstreams Self-Hosting-Anleitung es beschreibt, dann prüfen, ob er antwortet
curl http://localhost:8080/api/cli/models

Im Alltag:

# An einer leeren Eingabezeile ? drücken und fragen, zum Beispiel:
#   welcher Prozess lauscht auf Port 5432?
#   komprimiere alle .log-Dateien in diesem Verzeichnis, die älter als 7 Tage sind
#   wie lautete der rsync-Befehl, den ich für die Backups benutzt habe?

# Alles, was der Client kann
atuin-ai --help

# Der Shell-Code, den er einbindet
atuin-ai init bash

🔧 Werkzeug-Integrationen

Atuin AI sitzt zwischen deiner Shell, deiner Atuin-Historie und einem Modell deiner Wahl:

  • Atuin: eine harte Abhängigkeit, die mit aus deb.griffo.io installiert wird; der Agent durchsucht dieselbe Historien-Datenbank wie atuin search, und nur, wenn du es erlaubst
  • Atuin 18.25 und neuer: 18.25 hat den eingebauten Agenten entfernt, mit diesem Paket behältst du den ?-Chat auf einem aktuellen Atuin
  • bash, zsh und fish: atuin-ai init bash, zsh oder fish gibt die Tastenbelegung aus; lade sie nach Atuins eigener init-Zeile, damit beide Belegungen nebeneinander funktionieren
  • Atuin-AI-Server: ghcr.io/atuinsh/atuin-ai-server, mit Docker oder Podman auf derselben Maschine oder überall, wo der Client ihn erreicht; setze dort AUTH_TOKEN und api_token in ~/.atuin/ai.toml, um ihn abzusichern
  • Ollama und vLLM: jeder Prompt bleibt auf deiner eigenen Hardware, wenn der Server auf einen lokalen OpenAI-kompatiblen Endpunkt zeigt
  • Gehostete APIs: jeder Anbieter, der die OpenAI-API spricht, funktioniert genauso, konfiguriert auf dem Server, nie im Client

🚀 Warum deb.griffo.io?

📊 Repository-Vergleich:
  • Offizielles Ubuntu: paketiert Atuin AI nicht, apt install atuin-ai schlägt auf einem frischen System fehl
  • Upstream-Downloads: gibt es nicht: upstream veröffentlicht für den Client weder Releases noch Tags noch Binärdateien
  • cargo build aus dem Quellcode: ein Klon, eine Rust-Toolchain und ein paar Minuten Kompilieren, von Hand wiederholt, sobald sich main bewegt
  • deb.griffo.io: neueste Version mit automatischen Updates
  • ✅ Gebaut aus upstreams main: kompiliert aus upstreams Quellcode mit dessen eigener Cargo.lock; die Release-Notes und /usr/share/doc/atuin-ai/changelog.Debian nennen den genauen Upstream-Commit jedes Snapshots
  • ✅ Bringt Atuin mit: hängt von atuin ab, das deb.griffo.io ebenfalls anbietet, ein einziges apt install atuin-ai liefert also beides
  • ✅ Nur der Client: das Paket installiert /usr/bin/atuin-ai und eine Beispiel-ai.toml; der Server bleibt in Docker, wo upstream ihn ausliefert
  • ✅ Automatische Updates: jeder neue Snapshot kommt mit einem einfachen apt upgrade
  • ✅ Zwei Architekturen: amd64 und arm64 auf Ubuntu 22.04, 24.04, 25.10, 26.04 und 26.10, dieselben zwei wie beim Atuin-Paket, von dem es abhängt; einen Build für i386 oder armhf gibt es nicht
  • ✅ Multi-Distribution: läuft auf Ubuntu 22.04, 24.04, 25.10, 26.04 und 26.10
  • ✅ Einfache Wartung: Updates mit den üblichen apt-Befehlen

❓ Häufig gestellte Fragen

Ist Atuin AI in den offiziellen Ubuntu-Paketquellen?

Nein, Atuin AI ist nicht in den offiziellen Ubuntu-Archiven paketiert. Dieses Repository ist derzeit die einzige apt-Quelle und liefert Atuin AI 0.1.0.20261125.

Wie installiere ich das neueste Atuin AI unter Ubuntu?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install atuin-ai. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Ubuntu-Versionen werden unterstützt?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing, 26.04 Resolute und 26.10 Stonking.
