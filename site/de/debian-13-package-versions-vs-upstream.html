📊 Paketversionen in Debian 13 und Ubuntu

Was die offiziellen Archive ausliefern, daneben das, was dieses Repository bereitstellt — 2026-08-22

⚡ Die kurze Antwort. Von den 51 Tools in diesem Repository sind 36 weder in Debian 13 noch in Ubuntu 26.04, und der Rest ist auf der Version eingefroren, die beim Erscheinen dieser Releases aktuell war. Debian und Ubuntu frieren Paketversionen ein, sobald ein Release erscheint, und übernehmen danach überwiegend nur noch Sicherheitsfixes — ein bewusster und oft richtiger Kompromiss, der aber bedeutet: Die Version, die apt install auf einem unveränderten System liefert, ist die vom Release-Tag. Diese Tabelle ist das vollständige Bild für einen Katalog von Entwicklertools, bei jedem ausgelieferten Paket neu erzeugt statt von Hand getippt.

📋 Die Tabelle

Die offiziellen Versionen stammen aus den Debian- und Ubuntu-Archiven selbst (dem madison-Dienst), verglichen jeweils mit dem aktuellen stabilen Release: Debian 13 „Trixie“ und Ubuntu 26.04 „Resolute“. 🔍 So ist sie zu lesen

  • „nicht paketiert“ bedeutet, dass das Archiv im aktuellen stabilen Release dieser Distribution überhaupt kein Paket dieses Namens enthält. Auf einem unveränderten System scheitert apt install mit „Unable to locate package“.
  • Versionen werden so ausgegeben, wie die Archive sie melden, jedoch ohne Epoche und Debian-Revision, sodass 1:0.44.1-1ubuntu2 als 0.44.1 erscheint — die Nummer, die das Upstream-Projekt wiedererkennen würde.
  • Ein Tool kann in Ubuntu enthalten sein, in Debian aber nicht, oder umgekehrt: Die beiden Archive entscheiden unabhängig voneinander und frieren zu unterschiedlichen Zeitpunkten ein.
  • Nichts davon ist eine Kritik an Debian. Ein eingefrorenes Archiv ist genau das, was ein stabiles Release stabil macht, und für sehr viele Pakete ist das genau richtig. Für Tools, die alle paar Wochen erscheinen, passt es schlecht — und genau deshalb gibt es dieses Repository.

✅ Jede Zeile selbst prüfen

Jede Zahl oben ist öffentlich. Auf einem Debian- oder Ubuntu-Rechner:

apt-cache policy ripgrep        # was Ihr System installieren würde, und woher
apt-cache madison ripgrep       # jede Version, die Ihre konfigurierten Quellen anbieten
rmadison ripgrep                # was die offiziellen Archive ausliefern, ohne etwas zu installieren

rmadison stammt aus dem Paket devscripts und fragt denselben Dienst ab, aus dem diese Tabelle gebaut wird. Die Spalte deb.griffo.io folgt dem jeweils neuesten Release jedes Projekts und wird innerhalb von Stunden danach neu gebaut; das Paketierungs-Repository jedes Tools ist unter wie Pakete gebaut werden aufgeführt.

📦 Stattdessen die aktuelle Version bekommen

Eine Repository-Zeile deckt jedes Tool der Tabelle ab, neu gebaut innerhalb von Stunden nach jedem Upstream-Release:

Befehle ausführen
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://deb.griffo.io/EA0F721D231FDD3A0A17B9AC7808B4DD62C41256.asc | sudo gpg --dearmor --yes -o /etc/apt/keyrings/deb.griffo.io.gpg
echo "deb [signed-by=/etc/apt/keyrings/deb.griffo.io.gpg] https://deb.griffo.io/apt $(lsb_release -sc 2>/dev/null) main" | sudo tee /etc/apt/sources.list.d/deb.griffo.io.list > /dev/null
sudo apt update
install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://deb.griffo.io/EA0F721D231FDD3A0A17B9AC7808B4DD62C41256.asc | gpg --dearmor --yes -o /etc/apt/keyrings/deb.griffo.io.gpg
echo "deb [signed-by=/etc/apt/keyrings/deb.griffo.io.gpg] https://deb.griffo.io/apt $(lsb_release -sc 2>/dev/null) main" | tee /etc/apt/sources.list.d/deb.griffo.io.list > /dev/null
apt update
sudo apt install extrepo
sudo extrepo enable griffo
sudo apt update

🧩 Zur extrepo-Option. extrepo ist Debians eigenes Werkzeug für externe Repositories: Es legt die Sources-Datei an und installiert den Signaturschlüssel für dich, nachdem es ihn gegen signierte Metadaten geprüft hat. Dieses Repository ist dort als griffo registriert, der für immer kostenlose Spiegel als griffo-free. Unter Debian (bookworm, trixie, forky und sid) sind die Befehle oben damit die gesamte Einrichtung.

extrepo richtet nur die Sources-Datei und den Schlüssel ein; die Zugangsdaten eines Abos gehören weiterhin in /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu wird nicht abgedeckt, denn extrepo veröffentlicht Metadaten nur für Debian-Suites: dort nimmst du die Befehle mit sudo oder als root.
