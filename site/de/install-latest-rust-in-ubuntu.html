Was ist Rust?

Rust ist eine Systemprogrammiersprache mit Fokus auf Geschwindigkeit, Speichersicherheit und zuverlässige Nebenläufigkeit, und dieses Paket ist die offizielle stabile Rust-Toolchain: die Binärdateien von static.rust-lang.org, genau das, was rustup installiert, unverändert neu verpackt. Jeder Build wird vor dem Verpacken geprüft: die GPG-Signatur des Release-Manifests gegen den Rust-Release-Signaturschlüssel (Fingerabdruck 108F 6620 5EAE B0AA A8DD 5E1C 85AB 96E6 FA1B E5FE) und die SHA-256-Summe jedes Tarballs gegen dieses Manifest. Ein Paket, rust-stable, liefert rustc, cargo, rustdoc, rustfmt, clippy, rust-analyzer und die Standardbibliothek, und es wird mit jedem stabilen Release aktualisiert, alle sechs Wochen plus Point-Releases. Debian und Ubuntu paketieren denselben Compiler als rustc; der andere Name hier ist Absicht, wie weiter unten erklärt.

🚀 Warum die neueste Version zählt: Rust bringt alle sechs Wochen ein neues stabiles Release, und die Crates ziehen mit: neue Sprachfunktionen und Bibliotheks-APIs werden genutzt, sobald sie stabil sind, und ein Crate, das eine neuere rust-version angibt, baut mit einem älteren Compiler nicht. Ubuntu paketiert Rust als rustc und cargo, und 26.04 ist bei rustc 1.93.1ubuntu1 eingefroren, ein frisches System fällt also mit jedem Release weiter zurück. Dieses Repository liefert Rust 1.100.0 als rust-stable, eine vollständige Toolchain, die an die Stelle von rustc und cargo der Distribution tritt und mit jedem apt upgrade mitzieht.

⚡ Hauptfunktionen von Rust

🦀 Die ganze Toolchain

rustc, cargo, rustdoc, rustfmt, clippy (cargo clippy), rust-analyzer, die Wrapper rust-gdb und rust-lldb und die Standardbibliothek für deinen Rechner, alles aus demselben Release.

🔏 Geprüfte offizielle Binärdateien

Genau die Binärdateien, die rustup von static.rust-lang.org laden würde, unverändert neu verpackt. Der Build prüft die GPG-Signatur des Release-Manifests und die SHA-256-Summe jedes Tarballs, bevor irgendetwas verpackt wird.

👥 Eine Installation für alle Benutzer

Eine einzige systemweite Toolchain für alle Benutzer des Rechners statt eines eigenen ~/.rustup in jedem Home-Verzeichnis, aktualisiert von apt zusammen mit dem restlichen System.

🧩 Zusammen, nie gemischt

rustc, cargo, die Standardbibliothek, clippy und rustfmt sind eine versionsgebundene Familie. Nur rustc zu ersetzen, würde einen neuen Compiler mit einer alten std kombinieren, deshalb bewegt rust-stable immer die ganze Toolchain auf einmal.

🎯 Zusätzliche Targets als Pakete

Statische Linux-Binärdateien mit rust-stable-std-musl, das sein eigenes musl mitbringt, und WebAssembly mit wasm32-unknown-unknown, wasm32-wasip1 und wasm32-wasip2, jeweils ein apt install entfernt.

📚 Quelltext und Offline-Doku

rust-stable-src ergänzt den Quelltext der Standardbibliothek, den rust-analyzer liest, und rust-stable-doc legt The Book, die std-API-Doku und das Cargo-Buch zum Offline-Lesen auf die Platte.

🚀 Immer vor den offiziellen Archiven: Debian und Ubuntu frieren Paketversionen beim Release ein. Dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb von Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

🔧 Werkzeug-Integrationen

Die Toolchain ist wie jedes andere Systempaket angelegt, der Rest deiner Umgebung findet sie also ohne Konfiguration:

  • Aufbau: alles liegt unter /usr/lib/rust-stable mit einem eigenen mitgelieferten LLVM, und die Befehle sind nach /usr/bin verlinkt, sie stehen also jedem Benutzer im PATH, ohne Änderungen am Shell-Profil
  • Linken: das Paket hängt von einem C-Compiler (gcc oder clang) und libc6-dev ab, mit denen rustc linkt, cargo build funktioniert also direkt nach der Installation
  • Editoren: rust-analyzer gehört zum Paket, jeder Editor mit Language-Server-Client kann ihn also nutzen; mit rust-stable-src navigiert er auch in die Standardbibliothek
  • Debugger: rust-gdb und rust-lldb starten gdb oder lldb mit geladenen Rust-Pretty-Printern, damit Rust-Typen lesbar angezeigt werden
  • Shell: die Manpages von cargo und seine Vervollständigungen für bash und zsh werden mit dem Paket installiert
  • Cross-Targets: die Standardbibliotheken für musl und WebAssembly sind eigene Pakete, hinzugefügt mit apt install statt rustup target add
  • Dokumentation: rust-stable-doc installiert die HTML-Doku unter /usr/share/doc/rust-stable-doc/html, und alles steht auch online unter doc.rust-lang.org

📊 Repository-Vergleich:

  • ✅ Die offiziellen Binärdateien: genau das, was rustup von static.rust-lang.org installiert, unverändert, beim Build gegen den Rust-Release-Signaturschlüssel und die SHA-256-Summen des Manifests geprüft
  • ✅ Vollständiges Paket: die Toolchain unter /usr/lib/rust-stable mit eigenem LLVM, Befehle in /usr/bin, Manpages und cargo-Vervollständigungen, mit rust-stable-src als Empfehlung und Doku, musl und WebAssembly-Targets als optionalen Paketen
  • ✅ Automatische Updates: Pakete werden innerhalb von Stunden nach dem Upstream-Release aktualisiert
  • ✅ Zwei Architekturen: amd64 und arm64 auf jeder Version, auch auf dem Raspberry Pi 4 und 5 mit einem 64-Bit-System
  • ✅ Multi-Distribution: läuft auf Ubuntu 22.04, 24.04, 25.10 und 26.04

❓ Häufig gestellte Fragen

Ist Rust in den offiziellen Ubuntu-Paketquellen?

Ja, aber das offizielle Ubuntu-Archiv liefert Rust 1.93.1ubuntu1, während dieses Repository Rust 1.100.0 bereitstellt, wenige Stunden nach jedem Upstream-Release neu gebaut.

Wie installiere ich das neueste Rust unter Ubuntu?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install rust-stable. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Ubuntu-Versionen werden unterstützt?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing, 26.04 Resolute und 26.10 Stonking.
