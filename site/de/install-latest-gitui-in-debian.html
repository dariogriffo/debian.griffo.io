Was ist GitUI?

GitUI ist eine Terminal-Oberfläche für git, geschrieben in Rust. Sie bietet genau die Teile einer git-GUI, die sich wirklich lohnen — einzelne Hunks und Zeilen stagen, Diffs lesen, das Log durchsuchen, stashen, blamen, branchen und pushen — ohne das Terminal zu verlassen und ohne die Hänger, die bekannte GUIs bei großen Repositories haben.

🚀 Warum neueste Versionen wichtig sind: GitUI ist noch vor 1.0 und entwickelt sich schnell: Submodul-Unterstützung, Log-Suche, Blame, besseres Rebasing und viele Korrekturen kamen in ganz normalen Releases. Weder Debian noch Ubuntu paketieren es überhaupt — die Alternative zu einem aktuellen Build ist also kein älteres Paket, sondern gar keins.

⚡ Hauptfunktionen von GitUI

⚡ Schnell bei riesigen Repositories

Der Benchmark von upstream liest die komplette Linux-Kernel-Historie in rund 24 Sekunden mit etwa 170 MB Speicher — dort, wo schwerere GUIs einfrieren oder abstürzen.

✂️ Hunks und Zeilen stagen

Ganze Dateien, einzelne Hunks oder einzelne Zeilen stagen, unstagen, zurücknehmen und zurücksetzen — der Grund, warum die meisten überhaupt eine git-GUI öffnen.

📜 Log und Diffs

Das Commit-Log durchblättern und durchsuchen, den Diff jedes Commits ansehen und eine Datei zeilenweise blamen — alles in derselben Tastatur-Oberfläche.

📦 Stashing

Stashes speichern, poppen, anwenden, verwerfen und ansehen — in einem eigenen Tab, statt sich die git stash-Unterbefehle zu merken.

🌿 Branches und Remotes

Branches anlegen, umbenennen, löschen und auschecken, mit Remotes arbeiten sowie pushen und fetchen, ohne zurück in die Shell zu wechseln.

⌨️ Kontextbezogene Hilfe

? zeigt genau die Tasten, die in der aktuellen Ansicht funktionieren, und mit key_bindings.ron lässt sich alles neu belegen — auf Wunsch vim-artig.

🚀 Immer den offiziellen Archiven voraus: Debian und Ubuntu frieren Paketversionen zum Release-Zeitpunkt ein — dieses Repository veröffentlicht neue Upstream-Releases in der Regel innerhalb weniger Stunden. Ein einfaches apt upgrade hält dich auf der neuesten Version.

🧩 Zur extrepo-Option. extrepo ist Debians eigenes Werkzeug für externe Repositories: Es legt die Sources-Datei an und installiert den Signaturschlüssel für dich, nachdem es ihn gegen signierte Metadaten geprüft hat. Dieses Repository ist dort als griffo registriert, der für immer kostenlose Spiegel als griffo-free. Unter Debian (bookworm, trixie, forky und sid) sind die Befehle oben damit die gesamte Einrichtung.

extrepo richtet nur die Sources-Datei und den Schlüssel ein; die Zugangsdaten eines Abos gehören weiterhin in /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu wird nicht abgedeckt, denn extrepo veröffentlicht Metadaten nur für Debian-Suites: dort nimmst du die Befehle mit sudo oder als root.

🎯 Grundlegende Verwendungsbeispiele

Repositories öffnen:

# Das Repository im aktuellen Verzeichnis
gitui

# Ein bestimmtes Repository, ohne hineinzuwechseln
gitui -d ~/src/linux

# Getrenntes Arbeitsverzeichnis und git-Verzeichnis
gitui -d ~/src/project/.git -w ~/src/project

# Mit bereits ausgewählter Datei im Dateien-Tab starten
gitui -f src/main.rs

Aussehen und Bedienung:

# Eine Theme-Datei aus ~/.config/gitui/
gitui -t mytheme.ron

# Eine eigene Datei mit Tastenbelegungen
gitui -k ~/.config/gitui/key_bindings.ron

# Eigene Tastensymbole für Tastaturen, die sie anders darstellen
gitui -s ~/.config/gitui/key_symbols.ron

# Den Dateisystem-Watcher statt zyklischer Aktualisierung nutzen
gitui --watcher

Wenn etwas geklärt werden muss:

# Umgebungsdaten für einen Fehlerbericht sammeln
gitui --bugreport

# Beim Nachstellen eines Problems ein Log schreiben
gitui --logging --logfile /tmp/gitui.log

# Die git-CLI ist weiterhin für alles da, was GitUI nicht abdeckt
git rebase -i origin/main

# HTTPS-Pushes brauchen einen explizit konfigurierten Credential-Helper
git config --global credential.helper store

🔧 Tool-Integrationen

GitUI setzt auf deinem vorhandenen git-Setup auf:

  • Deine Repositories: ein ganz normales git-Repository, gelesen und geschrieben über ein Rust-git-Backend — nichts daran ist GitUI-spezifisch
  • Hooks: pre-commit, commit-msg, post-commit und prepare-commit-msg laufen wie auf der Kommandozeile
  • GPG-Signaturen: signierte Commits funktionieren, mit den Einschränkungen, die upstream in seinem Issue-Tracker dokumentiert
  • Themes und Tastenbelegungen: theme.ron, key_bindings.ron und key_symbols.ron in ~/.config/gitui/
  • Über SSH: auf entfernten Maschinen schnell genug, dass das Aufräumen eines Commits auf dem Server keine Qual mehr ist; der amd64-Build braucht keine Bibliotheken

🚀 Warum deb.griffo.io?

📊 Repository-Vergleich:
  • Offizielles Debian: paketiert GitUI überhaupt nicht — apt install gitui schlägt auf einem Standardsystem fehl
  • cargo install gitui: aktuell, aber ein langer Rust-Build pro Maschine, außerhalb von apt und außerhalb deiner Update-Routine
  • Upstream-Tarball: das offizielle Binary, das du für jedes Release von Hand neu holst
  • deb.griffo.io: neueste Version mit automatischen Updates
  • ✅ Noch vor 1.0: GitUI bekommt in normalen Releases echte Funktionen — die aktuelle Version zu fahren entscheidet, ob du Submodule, Log-Suche und Blame hast oder nicht
  • ✅ Die einzige apt-Quelle: GitUI ist weder in den Debian- noch in den Ubuntu-Archiven; dieses Repository paketiert den offiziellen Upstream-Build
  • ✅ Automatische Updates: Pakete werden innerhalb von Stunden nach Upstream-Releases aktualisiert
  • ✅ Ehrliche Paketierung: das Upstream-Binary unter /usr/bin/gitui — upstream liefert weder Handbuchseite noch Vervollständigungen, also erfindet das Paket auch keine
  • ✅ Drei Architekturen: amd64 (statischer musl-Build), arm64 und armhf, mit deklarierten Bibliotheksabhängigkeiten dort, wo upstream gegen glibc linkt
  • ✅ Multi-Distribution: läuft auf Bookworm, Trixie, Forky und Sid
  • ✅ Einfache Wartung: Updates mit den üblichen apt-Befehlen

❓ Häufig gestellte Fragen

Ist GitUI in den offiziellen Debian-Paketquellen?

Nein, GitUI ist nicht in den offiziellen Debian-Archiven paketiert. Dieses Repository ist derzeit die einzige apt-Quelle und liefert GitUI 0.28.1.

Wie installiere ich das neueste GitUI unter Debian?

Fügen Sie das deb.griffo.io-Repository einmalig hinzu (Anleitung oben) und führen Sie dann aus: sudo apt install gitui. Neue Releases kommen über das normale sudo apt upgrade.

Sind die Pakete signiert und wie werden sie gebaut?

Jedes Paket ist mit dem GPG-Schlüssel des Repositories (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) signiert und wird aus Upstream-Releases in öffentlichen GitHub-Repositories gebaut, die jeder einsehen kann.

Welche Debian-Versionen werden unterstützt?

Debian 12 Bookworm, Debian 13 Trixie, Forky und Sid.
