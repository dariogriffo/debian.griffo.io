Что такое kitty?

kitty — это эмулятор терминала на GPU для тех, кто проводит в терминале весь день. Он рисует через OpenGL, так что лог сборки или стена цветного вывода прокручивается плавно, и относится к терминалу как к платформе, а не к текстовому полю: окна и вкладки, расставленные мозаичными раскладками, графический протокол, который рисует настоящие картинки прямо в выводе, клавиатурный протокол, позволяющий программам отличать shift+enter от enter, кликабельные гиперссылки, лигатуры и интеграция с оболочкой, которая знает, где начинается и заканчивается каждое приглашение и вывод каждой команды. Рядом с терминалом идёт kitten — один исполняемый файл-компаньон с маленькими инструментами, вокруг которых терминал построен: kitten icat показывает картинку, kitten ssh переносит ваш terminfo и интеграцию с оболочкой на удалённый хост, kitten diff — diff бок о бок, понимающий и картинки, kitten clipboard, kitten themes, а kitten @ управляет самим терминалом из скрипта. Написал его Ковид Гоял, автор calibre, и всё настраивается в одном kitty.conf.

🚀 Почему важна последняя версия: kitty выходит примерно раз в месяц, и каждый выпуск двигает протоколы, на которых строятся другие инструменты: графический протокол, которым рисуют yazi, viu и плагины изображений для Neovim, клавиатурный протокол, который согласуют редакторы, размер текста, хуки интеграции с оболочкой, команды удалённого управления. Debian trixie заморожен на 0.41.1, а 0.26.5 из Bookworm старше самостоятельного исполняемого файла kitten, так что команд kitten ssh и kitten icat из нынешней документации там попросту нет. Старый kitty к тому же молча игнорирует настройки kitty.conf, которые нынешняя документация советует выставить, а каждого нового kitten (choose-fonts, notify, quick-access-terminal, panel) просто нет. Терминал — единственная программа, которой вы пользуетесь весь день; она должна быть свежей.

⚡ Ключевые возможности kitty

🎮 Отрисовка на GPU

kitty рисует через OpenGL, отдаёт работу с глифами видеокарте и оставляет процессор программе, которую вы на самом деле запустили. Большой вывод прокручивается с частотой обновления экрана, а терминал остаётся отзывчивым под потоком текста.

🪟 Окна, вкладки и раскладки

Разделите вкладку на окна и доверьте раскладке (tall, fat, grid, splits, stack) их расставить: ctrl+shift+enter открывает окно, ctrl+shift+t — вкладку. Файл сессии воссоздаёт целое рабочее пространство, каждое окно со своим каталогом и своей командой.

🖼️ Графический протокол

Настоящие изображения, а не блочные символы. kitten icat показывает картинку прямо в выводе, и тем же протоколом пользуются yazi, viu, плагины изображений для Neovim и бэкенды matplotlib, когда рисуют в вашем терминале.

🐈 Kittens

kitten — один статический исполняемый файл, полный маленьких инструментов: icat, ssh, diff, clipboard, themes, hints, чтобы с клавиатуры выбирать с экрана URL, пути или хеши, unicode_input, transfer для копирования файлов через ssh-сессию и другие.

🎛️ Удалённое управление

С включённым allow_remote_control команда kitten @ управляет терминалом из любого скрипта: открывать окна, посылать в них текст, менять цвета, менять размер, перечислять запущенное. Раскладки по скрипту без мультиплексора посередине.

🐚 Интеграция с оболочкой

kitty знает, где начинается каждое приглашение: прыгайте между приглашениями по ctrl+shift+z, открывайте вывод последней команды в пейджере, щёлкайте, чтобы переставить курсор внутри текущей строки, и пусть новые окна открываются в текущем каталоге. bash, zsh и fish, поставляются пакетом kitty-shell-integration.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

Как работает бесплатное зеркало →

🧩 О варианте extrepo. extrepo — штатный инструмент Debian для внешних репозиториев: он создаёт файл sources и устанавливает ключ подписи, предварительно сверив его с подписанными метаданными. Этот репозиторий зарегистрирован в нём как griffo, а бесплатное навсегда зеркало — как griffo-free, поэтому в Debian (bookworm, trixie, forky и sid) команды выше и есть вся настройка.

extrepo настраивает только файл sources и ключ — учётные данные подписки по-прежнему прописываются в /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu не поддерживается, так как extrepo публикует метаданные только для выпусков Debian: там используйте команды с sudo или от root.

# Терминал

Kittens:

kitten icat photo.png

# ssh, который берёт с собой terminfo и интеграцию с оболочкой
kitten ssh user@server

# Diff бок о бок, включая картинки
kitten diff old.txt new.txt

# Скопировать в системный буфер обмена и прочитать из него
echo hello | kitten clipboard
kitten clipboard --get-clipboard

# Применить тему ко всем открытым окнам kitty
kitten themes --reload-in=all Catppuccin-Mocha

# Выбрать шрифт интерактивно
kitten choose-fonts

Удалённое управление:

# Пропишите allow_remote_control yes в kitty.conf, затем из любой оболочки,
# запущенной внутри kitty: открыть новое окно справа от этого

# Набрать команду в другом окне, выбранном по заголовку

kitten @ set-colors background=#1e1e2e

# Что сейчас открыто
kitten @ ls

🔧 Интеграции

kitty — терминал под всем остальным, поэтому интеграция в основном про то, что запускается внутри него:

  • Удалённые серверы: kitty выставляет TERM=xterm-kitty, и хост без этого terminfo встречает вас сломанным backspace и жалобами less и clear. kitten ssh копирует его за вас; для хостов, куда вы ходите обычным ssh, установите там kitty-terminfo — независимый от архитектуры пакет, в котором нет ничего, кроме записи terminfo, и который ничего за собой не тянет
  • Ваша оболочка: kitty-shell-integration поставляет хуки для bash, zsh и fish в /usr/share/kitty/shell-integration, а shell_integration enabled в kitty.conf — значение по умолчанию — включает их, не трогая ваши rc-файлы
  • yazi, viu и Neovim: все трое рисуют картинки через графический протокол kitty, а Neovim говорит на клавиатурном протоколе kitty из коробки, так что это тот терминал, в котором их тестировали
  • Zellij и tmux: собственные окна, вкладки и раскладки kitty покрывают большую часть того, что делает локальный мультиплексор; берите Zellij, когда сессия должна пережить окно, и дайте tmux extended-keys и passthrough, чтобы протоколы kitty пережили дорогу
  • Ваш рабочий стол: пакет ставит desktop-файл, иконки и man-страницы и регистрирует альтернативу x-terminal-emulator, так что kitty появляется в вашем лаунчере, а один вызов update-alternatives делает его системным по умолчанию

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальный Debian: поставляет kitty 0.41.1 в trixie и 0.26.5 в Bookworm, каждый заморожен на весь срок жизни своего выпуска
  • Установщик от разработчика: один curl | sh в ~/.local/kitty.app, свежо, но для одного пользователя, без desktop-файла, man-страниц и x-terminal-emulator, если не подключить их самому, а обновляется повторным запуском установщика
  • Сборка из исходников: Python, Go, длинный список -dev-пакетов и изрядно времени ради бинарника, о котором apt ничего не знает
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ Те же имена пакетов, что в Debian: kitty, kitty-terminfo, kitty-shell-integration и kitty-doc, ровно так, как их называет архив Debian, поэтому этот репозиторий обновляет штатный kitty на месте, а последующий apt remove ничего после себя не оставляет
  • ✅ Официальная сборка: готовый бандл от разработчика, те же байты, что и в собственном установщике kitty, размещённый в /opt/kitty с симлинками /usr/bin/kitty и /usr/bin/kitten; без сборки из исходников, без патчей
  • ✅ Аккуратно встроен: desktop-файл, иконки, man-страницы, terminfo и интеграция с оболочкой на стандартных путях Debian, и зарегистрированная альтернатива x-terminal-emulator
  • ✅ kitty-terminfo ездит один: независимый от архитектуры пакет, в котором нет ничего, кроме terminfo xterm-kitty, для серверов, куда вы заходите по ssh
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream
  • ✅ Две архитектуры: amd64 и arm64 — две, для которых разработчик публикует бандлы; сборок под i386, armhf и riscv64 нет
  • ✅ Много дистрибутивов: работает на Bookworm, Trixie, Forky и Sid
  • ✅ Простое обслуживание: обновления обычными командами apt

❓ Часто задаваемые вопросы

Есть ли kitty в официальных репозиториях Debian?

Да, но официальный архив Debian поставляет kitty 0.41.1, тогда как этот репозиторий предлагает kitty 0.49.2, пересобирается через несколько часов после каждого релиза.

Как установить последнюю версию kitty в Debian?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install kitty. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Debian поддерживаются?

Debian 12 Bookworm, Debian 13 Trixie, Forky и Sid.
