Что такое tmux?

tmux — это терминальный мультиплексор: он запускает много оболочек внутри одного терминала, разбивая их на окна и панели, и оставляет их работать после того, как вы отключились. Сеанс tmux живёт в серверном процессе, а не в окне терминала, поэтому вы можете отключиться от него, закрыть окно или потерять соединение ssh, а позже подключиться снова, и все программы будут работать ровно там, где вы их оставили. Внутри сеанса вы открываете окна как вкладки, делите каждое на панели рядом или одну над другой, прокручиваете историю назад и копируете текст с клавиатуры, а управляете всем этим из файла конфигурации или из скриптов. tmux написан на C, его начал Nicholas Marriott, и он распространяется под лицензией ISC.

🚀 Почему важна последняя версия: tmux постоянно расширяет возможности терминала: tmux 3.8 принёс плавающие и модальные панели, а каждый релиз добавляет параметры и исправляет работу с терминалами. Ubuntu 26.04 поставляет tmux 3.6a, а Noble 3.4, каждый заморожен на весь срок жизни своего выпуска, так что на стандартной системе нет всего, что вышло с тех пор. Этот репозиторий поставляет tmux 3.8 под тем же именем пакета, поэтому он заменяет tmux из дистрибутива на месте при следующем apt upgrade.

⚡ Ключевые возможности tmux

🔌 Отключение и повторное подключение

Запустите долгую сборку или серверный процесс внутри tmux, отключитесь, выйдите из системы или потеряйте сеть, а затем подключитесь снова откуда угодно: сеанс и всё в нём продолжали работать, пока вас не было.

🪟 Окна и панели

Каждый сеанс содержит окна, как вкладки, а каждое окно делится на панели, так что редактор, оболочка и хвост лога делят один экран. Панели меняют размер, разворачиваются на весь экран и переставляются парой клавиш.

🎈 Плавающие и модальные панели

tmux 3.8 добавляет плавающие панели, которые располагаются поверх раскладки, и модальные панели, которые занимают окно, пока вы их не закроете, для быстрой команды или выбора из списка, не нарушая ваших разбиений.

📋 Режим копирования и буфер обмена

Прокручивайте историю панели назад, ищите в ней и выделяйте текст клавишами vi или emacs. Скопированный текст попадает в буфер обмена вашего рабочего стола через OSC 52, даже из tmux, запущенного на удалённом сервере.

🖼️ Изображения в терминале

В этой сборке включена поддержка sixel, так что программы, рисующие изображения sixel, показывают их внутри панели tmux, если ваш терминал тоже поддерживает sixel.

🧰 Скрипты и настройка

Каждое действие — это команда: привяжите её к клавише в ~/.tmux.conf или запустите из shell-скрипта, чтобы построить всю раскладку сеанса за один раз. Менеджеры плагинов и инструменты для сеансов построены именно на этом.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

# со старым сервером, пока вы из них не выйдете; эта команда останавливает их все разом
tmux kill-server

# Запустить именованный сеанс
tmux new -s work

# Отключитесь через Ctrl-b d, а позже подключитесь снова, отсюда или по ssh
tmux attach -t work

🎯 Базовые примеры использования

Сеансы, окна и панели:

# Список запущенных сеансов
tmux ls

# Внутри tmux префикс — Ctrl-b, после него:
# c  новое окно              n / p   следующее / предыдущее окно
# %  разбить слева/справа    "       разбить сверху/снизу
# стрелки  переход между панелями   z  развернуть текущую панель
# [  режим копирования, чтобы прокрутить назад и выделить текст
# d  отключиться

Раскладка из скрипта:

# Отключённый сеанс с редактором слева и оболочкой справа
tmux new-session -d -s dev -n code
tmux split-window -h -t dev:code
tmux send-keys -t dev:code.0 'nvim' Enter
tmux attach -t dev

# Перечитать конфигурацию, ничего не перезапуская
tmux source-file ~/.tmux.conf

Обновления:

# tmux обновляется вместе с остальной системой
sudo apt update && sudo apt upgrade

🔧 Интеграции

Поскольку пакет называется tmux, всё, что построено на tmux, продолжает работать после обновления:

  • ssh: запускайте tmux на сервере, а не на ноутбуке, и оборванное соединение лишь отключит вас от сеанса; ssh -t host tmux attach снова подхватит его
  • Плагины: tmux-plugin-manager (tpm) и устанавливаемые им плагины загружаются из ~/.tmux.conf точно так же, как раньше
  • Инструменты для сеансов: tmuxinator и byobu управляют командой tmux, поэтому получают новую версию без какой-либо перенастройки
  • Буфер обмена: благодаря OSC 52 текст, скопированный в режиме копирования, попадает в буфер обмена терминала, за которым вы сидите, даже через ssh
  • Возможности терминала: ncurses 6.6 слинкован статически, поэтому буфер обмена, цвет и форма курсора и стилизованные подчёркивания ведут себя одинаково на всех поддерживаемых выпусках
  • systemd: собран с поддержкой systemd, как и собственный пакет дистрибутива, а его сокеты в /tmp точно так же защищены от очистки systemd-tmpfiles
  • Документация: вики tmux на github.com/tmux/tmux/wiki охватывает начало работы, FAQ и каждый параметр

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальная Ubuntu: поставляет tmux 3.6a в 26.04 и 3.4 в Noble, каждый заморожен на весь срок жизни своего выпуска
  • Загрузки из upstream: tmux публикует только исходный код, так что готового бинарника для загрузки нет ни для одного релиза
  • Сборка из исходников: тулчейн C плюс пакеты разработки libevent и ncurses, configure и make для каждого релиза, и ничего, что обновляло бы его за вас
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ То же имя пакета, что в Ubuntu: пакет называется tmux, ровно как в архиве Ubuntu, поэтому этот репозиторий обновляет стандартный tmux на месте при apt upgrade
  • ✅ Сборка из каждого релиза с тегом: скомпилирован из архива релиза с включённой поддержкой systemd, jemalloc и изображений sixel, как и собственная сборка дистрибутива, и зарегистрирован в /etc/shells
  • ✅ Один tmux от Jammy до Resolute: один и тот же релиз на каждой поддерживаемой Ubuntu, так что один ~/.tmux.conf ведёт себя одинаково на всех ваших машинах
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream
  • ✅ Две архитектуры: amd64 и arm64 на всех версиях, так что один и тот же tmux работает на серверах, ноутбуках и ARM-платах вроде Raspberry Pi
  • ✅ Много дистрибутивов: работает на Ubuntu 22.04, 24.04, 25.10 и 26.04
  • ✅ Простое обслуживание: обновления обычными командами apt

❓ Часто задаваемые вопросы

Есть ли tmux в официальных репозиториях Ubuntu?

Да, но официальный архив Ubuntu поставляет tmux 3.6a, тогда как этот репозиторий предлагает tmux 3.8, пересобирается через несколько часов после каждого релиза.

Как установить последнюю версию tmux в Ubuntu?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install tmux. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Ubuntu поддерживаются?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing, 26.04 Resolute и 26.10 Stonking.
