Что такое GitUI?

GitUI — это терминальный интерфейс для git, написанный на Rust. Он даёт именно те части графического клиента, которые действительно нужны: индексирование отдельных ханков и строк, чтение диффов, просмотр и поиск по логу, stash, blame, ветки и push — не выходя из терминала и без зависаний, которыми популярные GUI славятся на больших репозиториях.

🚀 Почему важна последняя версия: GitUI ещё не достиг 1.0 и быстро развивается: поддержка подмодулей, поиск по логу, blame, улучшенный rebase и длинный хвост исправлений приходили в обычных выпусках. Ни Debian, ни Ubuntu его вообще не пакуют, так что альтернатива свежей сборке — не более старый пакет, а полное его отсутствие.

⚡ Ключевые возможности GitUI

⚡ Быстрый на огромных репозиториях

Собственный бенчмарк upstream разбирает всю историю ядра Linux примерно за 24 секунды и около 170 МБ памяти — там, где тяжёлые GUI зависают или падают.

✂️ Индексирование ханков и строк

Индексировать, снимать, откатывать и сбрасывать целые файлы, отдельные ханки или конкретные строки — ради этого графический клиент обычно и открывают.

📜 Лог и диффы

Просматривать и искать по логу коммитов, смотреть дифф любого из них и делать blame построчно — в одном и том же клавиатурном интерфейсе.

📦 Stash

Сохранять, применять, доставать, удалять и просматривать stash-и в отдельной вкладке, вместо того чтобы помнить, какая подкоманда git stash что делает.

🌿 Ветки и удалённые репозитории

Создавать, переименовывать, удалять и переключать ветки, работать с remote и делать push или fetch, не возвращаясь в оболочку.

⌨️ Контекстная справка

? показывает ровно те клавиши, которые работают в текущем виде, а key_bindings.ron позволяет переназначить всё — хоть по-вимовски.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

🎯 Базовые примеры использования

Открытие репозиториев:

# Репозиторий в текущем каталоге
gitui

# Конкретный репозиторий, без перехода в него
gitui -d ~/src/linux

# Отдельные рабочий каталог и каталог git
gitui -d ~/src/project/.git -w ~/src/project

# Запуск с уже выбранным файлом во вкладке файлов
gitui -f src/main.rs

Внешний вид и управление:

# Файл темы из ~/.config/gitui/
gitui -t mytheme.ron

# Свой файл с сочетаниями клавиш
gitui -k ~/.config/gitui/key_bindings.ron

# Свои символы клавиш — для клавиатур, где они рисуются иначе
gitui -s ~/.config/gitui/key_symbols.ron

# Использовать наблюдатель файловой системы вместо периодического обновления
gitui --watcher

Когда нужно разобраться:

# Собрать данные окружения для отчёта об ошибке
gitui --bugreport

# Писать лог, пока вы воспроизводите проблему
gitui --logging --logfile /tmp/gitui.log

# Командная строка git остаётся для всего, что GitUI не покрывает
git rebase -i origin/main

# Для push по HTTPS нужен явно настроенный credential helper
git config --global credential.helper store

🔧 Интеграция с другими инструментами

GitUI работает поверх вашей существующей настройки git:

  • Ваши репозитории: обычный git-репозиторий, читаемый и записываемый через git-бэкенд на Rust — ничего специфичного для GitUI в нём нет
  • Хуки: pre-commit, commit-msg, post-commit и prepare-commit-msg выполняются так же, как из командной строки
  • Подпись GPG: подписанные коммиты работают — с оговорками, которые upstream описывает в своём трекере
  • Темы и раскладки: theme.ron, key_bindings.ron и key_symbols.ron в ~/.config/gitui/
  • По SSH: на удалённой машине достаточно быстр, чтобы привести коммит в порядок прямо на сервере; сборке amd64 не нужны библиотеки

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальный Debian: вообще не пакует GitUI — apt install gitui на стандартной системе завершится ошибкой
  • cargo install gitui: свежая версия, но долгая сборка Rust на каждой машине, вне apt и вне вашего обновления системы
  • Архив upstream: официальный бинарник, который вы вручную скачиваете к каждому выпуску
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ Всё ещё до 1.0: GitUI получает настоящие возможности в обычных выпусках, поэтому свежая версия — это разница между наличием подмодулей, поиска по логу и blame и их отсутствием
  • ✅ Единственный источник apt: GitUI нет ни в архивах Debian, ни в архивах Ubuntu; этот репозиторий пакует официальную сборку upstream
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream
  • ✅ Честная упаковка: бинарник upstream в /usr/bin/gitui — upstream не выпускает ни man-страницы, ни дополнений, поэтому пакет их не выдумывает
  • ✅ Три архитектуры: amd64 (статическая сборка musl), arm64 и armhf, с объявленными зависимостями там, где upstream линкуется с glibc
  • ✅ Много дистрибутивов: работает на Bookworm, Trixie, Forky и Sid
  • ✅ Простое обслуживание: обновления обычными командами apt

❓ Часто задаваемые вопросы

Есть ли GitUI в официальных репозиториях Debian?

Нет — GitUI не упакован в официальных архивах Debian. Этот репозиторий сейчас единственный источник apt и предлагает GitUI 0.28.1.

Как установить последнюю версию GitUI в Debian?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install gitui. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Debian поддерживаются?

Debian 12 Bookworm, Debian 13 Trixie, Forky и Sid.
