Что такое rclone?

rclone — это консольный менеджер файлов в облачных хранилищах. Он работает более чем с семьюдесятью провайдерами: S3 и всё S3-совместимое, Google Drive, Dropbox, OneDrive и SharePoint, Backblaze B2, Google Cloud Storage, Swift, SFTP, FTP, WebDAV и обычный HTTP — с одним и тем же набором команд. Он копирует, синхронизирует и переносит с контрольными суммами, монтирует любой удалённый ресурс как файловую систему, раздаёт его по полудюжине протоколов и передаёт данные напрямую между двумя облаками, не пропуская их через ваш диск.

🚀 Почему важна последняя версия: rclone общается с API, которые меняются, не спрашивая вас. Провайдеры меняют схемы аутентификации, отключают endpoint-ы и добавляют регионы, а исправление выходит в следующем релизе rclone — там же появляются новые бэкенды и целые подкоманды. Версия из официальных архивов старше нескольких лет этой работы, и «в прошлом году работало» — ровно тот сбой, которого избегает свежий rclone.

⚡ Ключевые возможности rclone

☁️ Более семидесяти бэкендов

S3-совместимые объектные хранилища, потребительские облака, корпоративные пакеты и простые протоколы (SFTP, FTP, WebDAV, HTTP) — за одним набором команд.

🔁 Синхронизация с контрольными суммами

copy, sync и move сравнивают размер, время и хеши, а --dry-run заранее показывает, что именно изменится.

🗂️ Монтирование как файловой системы

rclone mount подключает удалённый ресурс в каталог с VFS-кешем, чтобы обычные программы могли читать и писать.

🌐 Раздача обратно

rclone serve публикует любой ресурс по HTTP, WebDAV, SFTP, FTP, DLNA, NFS или как S3-endpoint — удобно для устройств, знающих лишь один протокол.

🔐 Шифрование на стороне клиента

Обёртка crypt шифрует содержимое и имена файлов до отправки, а сам файл конфигурации с токенами тоже можно зашифровать.

⚡ Рассчитан на объёмы

Параллельные передачи и проверки, расписание ограничения полосы, фильтры и серверные копии, которые не тянут байты через вашу машину.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

🎯 Базовые примеры использования

Копирование и синхронизация:

# Загрузить папку с отображением прогресса
rclone copy -P ~/Documents mydrive:Documents

# Привести приёмник к состоянию источника — всегда сначала пробный прогон
rclone sync --dry-run ~/site remote:bucket/site
rclone sync -P ~/site remote:bucket/site

# Напрямую из одного облака в другое, без локальной копии
rclone copy s3:bucket/data b2:backup/data

# Проверить, что пришло именно то, что отправляли
rclone check ~/site remote:bucket/site

Монтирование и раздача:

# Смонтировать ресурс как файловую систему (нужен FUSE)
sudo apt install fuse3
rclone mount mydrive: ~/mnt/drive --vfs-cache-mode writes

# Раздать ресурс в локальную сеть по HTTP или WebDAV
rclone serve http remote:public --addr :8080
rclone serve webdav remote:docs --addr :8081

# Посмотреть, что занимает место, в стиле ncdu
rclone ncdu remote:

# Просто общий размер бакета
rclone size remote:bucket

Настройка, фильтры и шифрование:

# Больше параллелизма для множества мелких файлов
rclone sync -P --transfers 8 --checkers 16 src: dst:

# Расписание полосы, чтобы бэкапы не съедали рабочий день
rclone sync -P --bwlimit "08:00,512k 23:00,off" ~/photos remote:photos

# Фильтры вместо копирования всего подряд
rclone copy src: dst: --exclude "*.tmp" --filter-from filters.txt

# Обернуть существующий ресурс клиентским шифрованием
rclone config create secret crypt remote=mydrive:vault

🔧 Интеграция с другими инструментами

rclone — та деталь, на которую опираются другие инструменты:

  • FUSE: fuse3 (или fuse) превращает rclone mount в настоящий каталог для программ, которые понимают только файлы
  • systemd: юнит на каждый mount или serve и таймер для ночного sync — обычный способ запускать это без присмотра
  • Инструменты бэкапа: restic и подобные умеют работать с rclone как с удалённым хранилищем и сразу получают все поддерживаемые им бэкенды
  • Удалённое управление: rclone rcd --rc-web-gui даёт HTTP-API и веб-интерфейс для долгих передач
  • Файл конфигурации: ~/.config/rclone/rclone.conf хранит описания ресурсов и может быть зашифрован, чтобы учётные данные не лежали открытым текстом

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальный Ubuntu: содержит rclone в universe, замороженный на момент выпуска, так что новых провайдеров и подкоманд там просто нет
  • Установочный скрипт upstream: свежая версия, но кладёт бинарник в /usr/bin в обход apt и дальше рассчитывает на rclone selfupdate
  • Snap: изолированный пакет: FUSE-монтирование и пути вне домашнего каталога требуют лишних усилий
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ Рабочие бэкенды: самый свежий выпуск с исправлениями для провайдеров и новыми бэкендами, которых замороженная версия из архива так и не получила
  • ✅ apt держит версию свежей: никакого selfupdate и скриптов, пишущих в /usr/bin в обход пакетного менеджера
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream
  • ✅ Полный пакет: официальный бинарник upstream плюс man-страница rclone.1 и дополнения для bash, zsh и fish
  • ✅ Четыре архитектуры: amd64, arm64, armhf и i386 — на NAS и Raspberry Pi тот же rclone, что и на рабочей станции
  • ✅ Много дистрибутивов: работает на Ubuntu 22.04, 24.04, 25.10 и 26.04
  • ✅ Простое обслуживание: обновления обычными командами apt

❓ Часто задаваемые вопросы

Есть ли rclone в официальных репозиториях Ubuntu?

Да, но официальный архив Ubuntu поставляет rclone 1.60.1, тогда как этот репозиторий предлагает rclone 1.75.0, пересобирается через несколько часов после каждого релиза.

Как установить последнюю версию rclone в Ubuntu?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install rclone. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Ubuntu поддерживаются?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing и 26.04 Resolute.
