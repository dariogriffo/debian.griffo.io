Что такое GPU Screen Recorder?

GPU Screen Recorder — это экранный рекордер, который держит весь конвейер захвата на GPU: он захватывает монитор, окно, область экрана или веб-камеру и передаёт кадры прямо в видеокодировщик GPU (VA-API на AMD и Intel, NVENC на NVIDIA или Vulkan video), поэтому запись игры на 60 или 144 FPS почти не сказывается на частоте кадров. Он пишет видео в файл, транслирует по RTMP, SRT или WHIP, делает скриншоты и хранит буфер мгновенного повтора в духе ShadowPlay, который по команде сохраняет последние несколько минут. Работает на X11 и Wayland, а команда, которую вы вводите, — gpu-screen-recorder.

🚀 Почему важна последняя версия: Ubuntu 24.04, 25.10 и 26.04 вообще не включают GPU Screen Recorder в пакеты, а версия 5.13.8, запланированная для следующего выпуска Ubuntu, относится к линейке до 6.x. В ней нет ни gsr-cli, ни опции -ipc, поэтому управлять запущенным рекордером можно только сигналами; нет вывода WHIP с -auth для потоковой передачи с низкой задержкой; и нет -exclude-metadata. Скрипты для горячих клавиш и настройки повтора, написанные по сегодняшней документации upstream, рассчитывают на всё это.

⚡ Ключевые возможности GPU Screen Recorder

⏪ Мгновенный повтор

-r 60 хранит последние 60 секунд в памяти (или на диске с -replay-storage disk), а сохранить их можно одной командой: нужный клип, записанный ещё до того, как вы поняли, что он понадобится.

🎮 Почти нулевые накладные расходы

Захват и кодирование никогда не покидают GPU, поэтому CPU остаётся свободен для игры. Поддерживаются H.264, HEVC, AV1, VP8 и VP9, а также варианты HDR и 10-бит для HEVC и AV1.

🖥️ X11 и Wayland

Записывайте монитор напрямую, окно в X11, окно в фокусе, область, выбранную через slop или slurp, или всё, что предлагает десктопный портал через -w portal в Wayland.

📡 Трансляция

Отправляйте тот же захват на Twitch или YouTube по RTMP, слушателю SRT или по WHIP для задержки менее секунды, используя -bm cbr для постоянного битрейта, которого ожидают стриминговые сервисы.

🎛️ Удалённое управление через gsr-cli

Запустите рекордер с -ipc, и gsr-cli сможет поставить его на паузу, остановить или сохранить последние 30 секунд буфера повтора, а также напечатать путь к сохранённому файлу — это делает горячие клавиши тривиальными.

🔊 Микширование звука

Смешивайте звук рабочего стола с микрофоном через -a "default_output|default_input", либо записывайте звук отдельного приложения командой app:firefox через PipeWire.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

🎯 Базовые примеры использования

Запись:

# Звук рабочего стола и микрофон, смикшированные в одну дорожку
gpu-screen-recorder -w screen -f 60 -a "default_output|default_input" -o video.mp4

# Один монитор по имени, см. --list-monitors
gpu-screen-recorder -w DP-1 -f 144 -k hevc -o video.mp4

# Область, выбранная через slurp в Wayland, или slop в X11
gpu-screen-recorder -w region -region $(slurp -f "%wx%h+%x+%y") -o video.mp4

# Экран с веб-камерой в правом нижнем углу
gpu-screen-recorder -w "screen|/dev/video0;halign=end;valign=end;width=30%;height=30%" -o video.mp4

Мгновенный повтор:

# Хранить последние 60 секунд, постоянный битрейт для предсказуемого расхода памяти
gpu-screen-recorder -w screen -c mp4 -r 60 -bm cbr -q 40000 -a default_output \
    -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o ~/Videos

# По горячей клавише: сохранить весь буфер или только последние 30 секунд
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" save-replay 30

# Сигналы по-прежнему работают без -ipc
pkill -SIGUSR1 -f "^gpu-screen-recorder"

Трансляция и скриншоты:

# Трансляция на Twitch с постоянным битрейтом 8000 кбит/с
gpu-screen-recorder -w screen -c flv -a default_output -bm cbr -q 8000 \
    -o "rtmp://live.twitch.tv/app/$STREAM_KEY"

# WHIP-трансляция с низкой задержкой с bearer-токеном
gpu-screen-recorder -w screen -bm cbr -q 3500 -c whip -auth "$TOKEN" -o https://whip.example.com/api/whip

# Сделать скриншот
gpu-screen-recorder -w screen -o screenshot.png

Управление записью:

# Запустить запись, которой можно управлять через сокет
gpu-screen-recorder -w screen -f 60 -ipc "$XDG_RUNTIME_DIR/gsr.sock" -o video.mp4 &

# Проверить её состояние, поставить на паузу, затем остановить и напечатать, куда сохранён файл
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" status
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" set-paused true
gsr-cli -ipc "$XDG_RUNTIME_DIR/gsr.sock" stop

🔧 Интеграция с другими инструментами

GPU Screen Recorder — программа командной строки, поэтому она впишется везде, где ярлык может запустить команду:

  • Горячие клавиши рабочего стола: привяжите gsr-cli save-replay 30 в GNOME, KDE, Sway или Hyprland, чтобы получить клавишу «сохранить последние 30 секунд» в духе ShadowPlay
  • Вспомогательные скрипты: скрипты upstream для переключения, повтора и трансляции поставляются в /usr/share/gpu-screen-recorder/scripts
  • systemd: пользовательский сервис для постоянно включённого буфера повтора устанавливается, но не активируется по умолчанию; настройте ~/.config/gpu-screen-recorder.env, затем выполните systemctl --user enable --now gpu-screen-recorder
  • Трансляция без OBS: вывод по RTMP, SRT и WHIP покрывает Twitch, YouTube и серверы собственного хостинга без второй программы
  • FFmpeg: -ffmpeg-opts, -ffmpeg-video-opts и -ffmpeg-audio-opts передают опции напрямую кодировщику и мультиплексору

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальный Ubuntu: не упакован ни в 24.04, ни в 25.10, ни в 26.04; в следующем выпуске появится 5.13.8, разбитая на несколько пакетов gpu-screen-recorder-* и без gsr-cli, -ipc или WHIP
  • Flatpak: актуальная версия со своими кодировщиками в комплекте, но это интерфейс на GTK, командная строка спрятана за flatpak run --command=gpu-screen-recorder, а захват монитора на AMD/Intel требует установки на уровне всей системы
  • Сборка из исходников: install.sh от upstream требует meson и около двадцати пакетов -dev, устанавливает мимо apt и должен запускаться вручную при каждом релизе
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ Собран для каждого выпуска: компилируется из тега upstream для каждого набора пакетов со своим собственным FFmpeg, поэтому линкуется с библиотеками, уже установленными в системе
  • ✅ Без запроса пароля: gsr-kms-server получает ту же capability, что задаёт установщик upstream, поэтому запись монитора на AMD, Intel или NVIDIA Wayland не спрашивает пароль каждый раз
  • ✅ Заменяет разделённые пакеты: занимает место пакетов gpu-screen-recorder-cli, которые поставляет Debian и которые добавляет Ubuntu, поэтому apt обновляет, а не устанавливает вторую копию
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream
  • ✅ Полный пакет: gpu-screen-recorder, gsr-cli, gsr-kms-server, man-страницы, заголовочный файл плагина, вспомогательные скрипты upstream и пользовательский сервис, который остаётся выключенным, пока вы его не включите
  • ✅ Много дистрибутивов: работает на Ubuntu 24.04, 25.10 и 26.04, на amd64 (FFmpeg в 22.04 слишком старый, чтобы его собрать)
  • ✅ Простое обслуживание: обновления обычными командами apt

Один нюанс переходит от upstream и сюда: с FFmpeg из дистрибутива видеокарты NVIDIA поколения GTX 1080 и старше могут не суметь кодировать. Flatpak и AppImage от upstream поставляют для них пропатченный FFmpeg.

❓ Часто задаваемые вопросы

Есть ли GPU Screen Recorder в официальных репозиториях Ubuntu?

Нет, GPU Screen Recorder не упакован в официальных архивах Ubuntu. Этот репозиторий сейчас единственный источник apt и предлагает GPU Screen Recorder 6.1.3.

Как установить последнюю версию GPU Screen Recorder в Ubuntu?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install gpu-screen-recorder-cli. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Ubuntu поддерживаются?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing и 26.04 Resolute.
