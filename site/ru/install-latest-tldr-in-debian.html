Что такое tldr?

tldr — это официальный Rust-клиент для tldr-pages, поддерживаемой сообществом коллекции упрощённых man-страниц: каждая страница — это описание команды в одну строку и горстка примеров, которые люди действительно набирают. Проект upstream называется tlrc, а пакет и команда называются tldr. Это один статический бинарник без зависимостей, он держит всю коллекцию в локальном кэше, поэтому поиск мгновенный и работает без сети, и сам обновляет этот кэш, когда тот устаревает. Страницы есть для разных платформ (Linux, macOS, Windows, Android, BSD) и на десятках языков, цвета и оформление вывода задаются в TOML-файле, а в пакете лежат man-страница и автодополнение для bash, zsh и fish.

🚀 Почему важна последняя версия: tlrc идёт в ногу со спецификацией клиентов tldr-pages: новые каталоги платформ, правила отката между языками, поиск по страницам, каталог собственных страниц и ключи конфигурации, управляющие возрастом кэша и цветами, появлялись от выпуска к выпуску, и старый бинарник либо игнорирует их, либо неверно отрисовывает новые страницы. Собственный пакет tldr в Debian — это другая программа, клиент на Haskell tldr-hs, а пакет tealdeer в Debian тоже ставит /usr/bin/tldr; ни один из них не tlrc, так что официальный клиент через apt берётся из этого репозитория.

⚡ Ключевые возможности tldr

📄 Сначала примеры

tldr tar печатает восемь способов, которыми вы действительно пользуетесь tar, а не две сотни флагов, которые он принимает. Команды из нескольких слов работают так, как вы их набираете: tldr git rebase, tldr docker compose.

⚡ Локальный кэш, а не запрос

Первый запуск скачивает всю коллекцию; каждый следующий поиск — это чтение файла, так что страница появляется раньше, чем палец отпустит Enter, в поезде или за прокси. Кэш обновляется сам, когда становится старше заданного возраста, или по --update.

🖥️ Любая платформа, одна команда

Страницы разложены по платформам. По умолчанию вы получаете вариант для Linux, а -p macos или -p windows — когда пишете инструкцию для машины, которой нет перед вами.

🌍 Ваш язык

tldr-pages переведён на десятки языков. tlrc следует LANG и LANGUAGE и постранично откатывается на английский, а -L выбирает язык для одного запроса.

🔍 Найти страницу, о которой вы не знаете

--list печатает имена всех страниц для текущей платформы, --search ищет по именам и описаниям, а --info сообщает, насколько стар кэш и какие языки в нём есть.

🎨 Настраивается под вас

Один config.toml: каждый цвет и стиль отрисованной страницы, возраст кэша до автоматического обновления, языки для загрузки, предпочитаемая платформа и каталог собственных страниц, в котором ищут раньше, чем в кэше.

🚀 Всегда впереди официальных архивов: Debian и Ubuntu замораживают версии пакетов при выпуске релиза — этот репозиторий публикует новые версии обычно в течение нескольких часов. Простое apt upgrade держит вас на последней версии.

Как работает бесплатное зеркало →

🧩 О варианте extrepo. extrepo — штатный инструмент Debian для внешних репозиториев: он создаёт файл sources и устанавливает ключ подписи, предварительно сверив его с подписанными метаданными. Этот репозиторий зарегистрирован в нём как griffo, а бесплатное навсегда зеркало — как griffo-free, поэтому в Debian (bookworm, trixie, forky и sid) команды выше и есть вся настройка.

extrepo настраивает только файл sources и ключ — учётные данные подписки по-прежнему прописываются в /etc/apt/auth.conf.d/deb.griffo.io.conf. Ubuntu не поддерживается, так как extrepo публикует метаданные только для выпусков Debian: там используйте команды с sudo или от root.

🎯 Базовые примеры использования

Поиск:

# Страница для команды
tldr tar

# Подкоманды, записанные так, как вы бы их набрали
tldr git rebase

# Страница для другой платформы
tldr -p macos brew
tldr -p windows choco

# Страница на другом языке для одного запроса
tldr -L ru tar

# Имена всех страниц для этой платформы и поиск по именам
# и описаниям, когда вы не знаете команду
tldr --list
tldr --search "compress"

Форма вывода:

# Сырой markdown, чтобы передать дальше
tldr -R tar

# Без пустых строк на маленьком терминале
tldr --compact tar

# Без цветов, для логов и скриптов
tldr --color never tar

# Никогда не трогать сеть, даже если кэш устарел
tldr --offline tar

# Отрисовать страницу, которую вы пишете, прежде чем отправить её upstream
tldr -r my-command.md

Под себя:

# Откуда читается конфигурация и заготовка для начала
tldr --config-path
mkdir -p "$(dirname "$(tldr --config-path)")"
tldr --gen-config > "$(tldr --config-path)"

# Дальше в config.toml: возраст кэша до автоматического обновления,
# какие языки хранить, какую платформу предпочитать
# и цвета каждой части страницы

# Стереть кэш, если загрузка пошла не так
tldr --clean-cache

🔧 Интеграции

tldr — это справка, поэтому он встаёт рядом с инструментами, которыми вы уже пользуетесь:

  • Ваша оболочка: пакет ставит автодополнение для bash, zsh и fish, так что tldr gi<tab> дополняет имена страниц из кэша, а man tldr описывает сам клиент
  • fzf: tldr --list | fzf | xargs tldr — нечёткий выбор страницы в одну строку, а вывод --raw идёт в панель предпросмотра
  • Исправить страницу: tldr --edit tar печатает ссылку, открывающую эту страницу в веб-редакторе GitHub, так что исправление страницы tldr — это один pull request
  • man: tldr не заменяет руководство, это то, что читают первым; полная страница в одном man от вас, как только вы знаете, какой флаг нужен
  • Скрипты и документация: --color never и --raw делают вывод безопасным для вставки в README, тикет или лог

🚀 Почему стоит выбрать deb.griffo.io?

📊 Сравнение репозиториев:
  • Официальный Debian: apt install tldr ставит tldr-hs, клиент на Haskell, а tealdeer — другой клиент на Rust с тем же именем команды; ни один из них не официальный tlrc
  • Сборка из исходников: свежо, но требует тулчейн Rust на каждой машине и оставляет бинарник, о котором apt ничего не знает
  • Архив релиза upstream: тот же статический бинарник, но распакованный вручную в PATH, без автодополнения, без man-страницы и без обновлений
  • deb.griffo.io: последняя версия с автоматическими обновлениями
  • ✅ Официальный клиент: tlrc, клиент, который поддерживает сам проект tldr-pages, а не одна из многих реализаций
  • ✅ Команда называется tldr: пакет назван tldr, потому что так называется команда, и он конфликтует с tealdeer и заменяет его, так что спора за /usr/bin/tldr не бывает
  • ✅ Автоматические обновления: пакеты обновляются в течение нескольких часов после релиза upstream, а кэш страниц сверх того обновляется сам
  • ✅ Полный пакет: бинарник, man-страница и автодополнение для bash, zsh и fish
  • ✅ Ноль зависимостей: статически слинкованный бинарник на musl, больше ничего не подтягивается
  • ✅ Две архитектуры: amd64 и arm64, один и тот же статический бинарник на любом выпуске
  • ✅ Много дистрибутивов: работает на Debian 13 (trixie) и новее: Trixie, Forky и Sid
  • ✅ Простое обслуживание: обновления обычными командами apt

❓ Часто задаваемые вопросы

Есть ли tldr в официальных репозиториях Debian?

Нет, tldr не упакован в официальных архивах Debian. Этот репозиторий сейчас единственный источник apt и предлагает tldr 1.13.1.

Как установить последнюю версию tldr в Debian?

Добавьте репозиторий deb.griffo.io один раз по инструкции выше, затем выполните: sudo apt install tldr. Новые версии приходят через обычный sudo apt upgrade.

Подписаны ли пакеты и как они собираются?

Каждый пакет подписан GPG-ключом репозитория (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) и собирается из релизов upstream в публичных репозиториях GitHub, которые может проверить любой.

Какие версии Debian поддерживаются?

Debian 12 Bookworm, Debian 13 Trixie, Forky и Sid.
