What is jjui?

jjui is a terminal user interface for Jujutsu, the Git-compatible version control system you drive with the jj command. Run it inside a jj repository and it shows the revision graph, then lets you work on it directly: change the revset with auto-complete to choose what is shown, rebase a revision or a whole branch, squash, split and abandon revisions, move bookmarks, open a revision to see its files and diffs and restore files one by one, preview jj show and jj diff output beside the graph, push and fetch through a Git menu, and browse or restore the operation log. Everything works from the keyboard or with the mouse. jjui is written in Go by Ibrahim Dursun and is MIT licensed.

🚀 Why Latest Versions Matter: jjui moves together with Jujutsu: jj releases change commands and output, and jjui follows them while adding operations, completion improvements and fixes in most releases. Ubuntu does not package jjui at all, so without this repository the only way to stay current is to download every new release by hand. Here a normal apt upgrade updates jjui and the jj it depends on together.

⚡ Key Features of jjui

🌳 The Revision Graph, Live

jjui opens on the same graph jj log prints, but you can move through it, select revisions and act on them, and the graph redraws after every change.

🔎 Revsets with Auto-Complete

Edit the revset at the top of the screen to choose which revisions are shown; functions and aliases are completed as you type, so you do not have to remember the revset language.

✂️ Rebase, Squash, Split, Abandon

Rebase a single revision or a whole branch onto another, squash a revision into its parent, split it in two, abandon it, or move a bookmark, all from the graph, and see the result straight away.

📄 Files, Diffs and Previews

Open a revision to list the files it changes, read their diffs and restore files interactively, or keep a preview pane with the jj show or jj diff output of whatever is selected.

🔄 Git Menu and Operation Log

Push and fetch through a Git menu without leaving the graph, and browse the operation log to see what changed and restore the repository to an earlier state.

🖱️ Keyboard, Mouse, Lua and Themes

Every action has a key binding (press ? to list them) and the mouse works too. Lua scripting adds your own actions, and themes change the colours.

🚀 Always ahead of the official archives: Debian and Ubuntu freeze package versions when a release ships. This repository publishes new upstream releases typically within hours. A simple apt upgrade keeps you on the latest version.

🔧 Tool Integrations

jjui is a front end for jj, so it fits wherever jj already does:

  • Jujutsu: every action runs the jj command, so jjui sees the same repository, config and revset aliases as jj itself; the package depends on jujutsu (>= 0.37), and deb.griffo.io packages Jujutsu for every suite, so apt installs it along with jjui
  • Git remotes: in a colocated repository, push and fetch from the Git menu go to your normal Git remotes with the credentials you already use
  • Your editor: jjui -config opens the configuration file in $EDITOR, where key bindings, the theme and custom actions live
  • Lua scripting: write your own actions in Lua and bind them to keys, for the jj commands you run often
  • Themes: the colours of the graph, the selection and the panes come from a theme you can change or write yourself
  • Mouse: click to select revisions and scroll the graph and the preview, in any terminal with mouse support
  • Documentation: upstream ships no man page, so the full guide is at idursun.github.io/jjui, and ? inside jjui lists the key bindings

❓ Frequently asked questions

Is jjui in the official Ubuntu repositories?

No, jjui is not packaged in the official Ubuntu archives. This repository is currently the only apt source, serving jjui 0.10.12.

How do I install the latest jjui on Ubuntu?

Add the deb.griffo.io repository once using the instructions above, then run: sudo apt install jjui. New releases arrive through the normal sudo apt upgrade.

Are the packages signed and how are they built?

Every package is signed with the repository's GPG key (EA0F721D231FDD3A0A17B9AC7808B4DD62C41256) and built from upstream releases in public GitHub packaging repositories that anyone can inspect.

Which Ubuntu releases are supported?

Ubuntu 22.04 Jammy, 24.04 Noble, 25.10 Questing and 26.04 Resolute.
